The text in a document -- a story, a text block, a selection of words -- can leave {product}
three ways: through the Export sheet as an RTF or plain text file, through Copy and Paste,
and by dragging.  RTF keeps the formatting a word processor understands; plain text keeps the
words.

== Exporting a text file

To export text through the Export sheet:

. Choose menu:File[Export…].
. Choose *Rich Text* or *Plain Text* from the *Format* menu.
. Choose what to export:
+
[cols="1,3"]
|===
|Choice |Exports

|*Pages* (current, all or a range)
|Every text block on those pages.  Linked blocks export as one story in link order, once,
where the first block of the chain appears.  Unlinked blocks export in stacking order,
bottom to top, page by page, each separated by a blank line.

|*Selected objects*
|The selected text blocks in the same order; or, while editing text, just the selected
characters.
|===
. For plain text, click btn:[Options…] to choose the *Encoding* (UTF-8 with or without a
  byte-order mark, UTF-16) and *Line endings* (macOS/Unix or Windows).  Rich Text has an
  *Embed inline graphics* option (below).
. Click btn:[Export].

Only text goes into the file.  Artwork is left out; text on a path exports as its
characters; text inside groups, symbols and clipping paths is included; text on hidden layers
is not.

== Copying and dragging text

* Select characters in a text block and choose menu:Edit[Copy] (kbd:[Cmd+C]).  The clipboard
  holds both rich and plain text, and the receiving application takes the one it prefers:
  Pages, Word and Mail paste formatting, a code editor pastes plain words.
* Select a text block as an object and copy it: the clipboard holds the block's text as rich
  and plain text, as well as the artwork for pasting into other {product} windows
  (xref:copying-type.adoc[Copying type]).
* Drag selected characters, or a text block, out of the window into another application to
  hand over the same thing.  Dragging into the Finder writes an `.rtf` file.

== What formatting is preserved

Rich Text carries the formatting that word processors share.  From the type settings on
xref:type-specifications.adoc[Type specifications], xref:paragraphs.adoc[Paragraphs] and
xref:tabs-indents.adoc[Tabs and indents]:

[cols="1,3"]
|===
|Kept |

|Characters
|Font family, style and size; bold and italic (as font styles); color (converted to RGB);
underline and strikethrough; superscript and subscript; baseline shift; horizontal scale;
kerning and range kerning (tracking); small caps and all caps as font features where the
receiving program supports them; the language.

|Paragraphs
|Alignment, left and right indents, first-line indent, space before and after, line spacing
(fixed, or a multiple), tab stops with their alignment and leaders, paragraph rules, keep
with next, hyphenation on or off.

|Styles
|Text styles become RTF paragraph and character styles with their names, so a document's
styles reappear in Word's style list (xref:text-styles.adoc[Text styles]).

|Structure
|Columns export as consecutive text (column breaks become paragraph breaks); tables export as
RTF tables with column widths (xref:columns-tables.adoc[Columns and tables]); page breaks
between pages.

|Inline graphics
|With *Embed inline graphics* on (default), each graphic is rendered to a PNG at the
document's raster resolution and embedded in the RTF.  Off, or in plain text, a bullet stands
in for each graphic.
|===

[cols="1,3"]
|===
|Not kept |

|Text effects
|Highlight, inline, shadow, zoom and other text effects (xref:text-effects.adoc[Text
effects]) do not exist in RTF; the text exports plain.  Underline and strikethrough are the
exceptions.

|Shape
|Text on a path, text wrapped inside a shape, rows, inset and vertical text export as
ordinary paragraphs.

|Attributes RTF lacks
|Gradient or pattern text fills (converted to the first color), spot colors (converted to
RGB), OpenType feature choices beyond small caps, and text linked to an external file.
|===

Plain text keeps characters, paragraph breaks and tabs only.  Smart quotes, dashes and other
typographic characters are kept as the Unicode characters they are.

NOTE: RTF export keeps subscript and superscript.  Inline graphics do not have to be converted
to paths for any export.

== Working with others

Text export reads the document; it never changes it.  A story someone else is typing in
exports as far as their typing has reached this Mac.  If a colleague has a text block open
while you export, you get their text as it currently reads, not a locked or partial version:
there are no locks on text.

=== Merge semantics

None; exports write nothing.  The text read is the plain-string read-out of each `RichText`
register with its resolved marks, taken from the `SceneSnapshot` so a concurrent
`TextInsert` arriving mid-export does not split the story.

=== Offline behavior

Works offline.

=== Server

Nothing.

=== Client

* `WTInterchange.RTFWriter` builds an `NSAttributedString` from the text layout's attributed
  runs (TXT-001) with paragraph styles, tab stops, `NSTextTable` for tables, `NSTextAttachment`
  with PNG data for inline graphics, and document attributes for the style sheet; then
  `rtf(from:documentAttributes:)` for characters-only output and `rtfd` is not used (RTFD
  bundles are a macOS-only convention).  Style names are written by post-processing the RTF
  `\stylesheet` group, which `NSAttributedString` does not emit.
* Story ordering: linked chains are walked from their head block; a chain forming a loop is
  cut per the read-time normalization in xref:crdt-model.adoc[CRDT model].  Unlinked blocks
  are sorted by page (geometric page containment of the block's origin), then stacking order.
* Plain text: the same walk, `String` joined with paragraph separators, tabs kept, attachments
  replaced by U+2022.
* Pasteboard: `public.rtf`, `public.utf8-plain-text` (and `com.apple.flat-rtfd` when the
  selection contains inline graphics), written lazily.
* Undo: none.

NOTE: As built by IO-030 (`WTInterchange/Text`).  *Input*: the display list holds text only as
glyph runs, so `ExportScene.text` carries what text export reads, and `WTModel` (IO-014's
`SceneSnapshot`) must fill it: one `ExportTextBlock` per text block on the exported pages -- on a
visible layer, inside groups, symbols and clipping paths included -- with its node id, the index of
the page holding its origin, its stacking order on that page (bottom to top), the next block of
its chain, and its `ExportStory` (on the chain's head; stories on other blocks of a chain are
joined in link order).  A story is `ExportStoryElement`s: paragraphs (`ExportParagraph`: runs and
an `ExportParagraphStyle` with alignment, indents, spacing, line spacing, tab stops with alignment
and leader, keep with next, hyphenation, style name) and tables (`ExportTable`: column widths, rows
of cells of paragraphs).  A run (`ExportTextRun`) is text with `ExportTextAttributes` -- family,
size, bold, italic, colour, underline, strikethrough, super/subscript, baseline shift, horizontal
scale, tracking in thousandths of an em, small caps, all caps, BCP 47 language, character style
name -- or an inline graphic already rendered at the raster resolution with its size in points
(text U+FFFC).  Selected characters are a one-block scene holding just them; line breaks inside
a paragraph are U+2028; column breaks arrive as paragraph breaks.  *Order*: chains once at their
head, blocks by page then stacking order; a chain that loops is cut before the block that would
repeat, and a loop with no head starts at its first block in that order (the exporter sees blocks,
not the CRDT, so this stands in for the read-time normalization).  *RTF* is an own writer, not
`NSAttributedString`'s: that writer emits no style sheet, drops attachments outside RTFD and writes
no tables, the three things the specification patches around.  It writes the font table (family
names; bold and italic as `\b`, `\i`), the colour table with an `\expandedcolortbl` in sRGB (which
Apple's readers otherwise take as generic RGB; colours are sRGB fallbacks), a style sheet of
paragraph (`\s`) and character (`\*\cs`) styles by name, paragraph and run controls for every
attribute above (language through `NSLocale.windowsLocaleCode`), tables as `\trowd … \cell …
\row`, `\page` between pages and a blank paragraph between stories on one page, inline graphics
as `\pict\pngblip` (a bullet when *Embed inline graphics* is off), and non-ASCII as `\uN?`.  *Plain
text* joins paragraphs with line breaks, table cells with tabs and rows with line breaks, stories
with a blank line; UTF-16 is little-endian with a byte-order mark.  *Pasteboard*:
`TextPasteboard.flavors` returns `public.rtf` and `public.utf8-plain-text` for the app to provide
lazily; `com.apple.flat-rtfd`, the `NSPasteboard` writing and drag to Finder are the app's.  Tests
read the RTF back with AppKit's RTF reader (fonts, bold, underline, tracking as kern, colour,
alignment, spacing, super/subscript, baseline shift, indents, fixed line height, tab stops, table
cells); the inline graphic is checked in the RTF text (a PNG `\pict`).
The Word and Pages acceptance test needs a person at the Mac and was not run.
