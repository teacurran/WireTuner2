PDF is the format to reach for when the artwork has to arrive intact: at a print shop, in a
page-layout program, in someone's mail.  {product} writes PDFs that keep text as text, vector
as vector, transparency live, spot colors named, fonts embedded and every page in one file,
and it can produce the PDF/X files printers ask for, with bleed and printer's marks.

To export a PDF:

. Choose menu:File[Export…] and choose *PDF* from the *Format* menu.
. Choose what to export.  *All pages* and page ranges go into one PDF; *Output area* and
  *Selected objects* make a one-page PDF cropped to them (xref:exporting.adoc[Exporting
  files]).
. Click btn:[Options…] and choose a *Preset* at the top of the sheet, or set the options
  below.
. Click btn:[OK], then btn:[Export].

The options sheet has five sections.  The *Preset* menu at its top fills all of them at once:

any presets you have saved (xref:exporting.adoc[Exporting files]).

== General

[cols="1,3"]
|===
|Option |Effect

|*Compatibility*
|*PDF 1.4* (Acrobat 5) through *PDF 1.7* (Acrobat 8 and later, default) and *PDF 2.0*.  Every
level from 1.4 up keeps transparency live; 1.5 adds layers and object streams (smaller files);
1.7 is what nearly everything reads today and the first level that carries Display P3 colors
with their profile -- below it they are converted to the destination RGB profile and listed.

|*Standard*
|*None*, *PDF/X-1a:2001*, *PDF/X-4:2010*.  Choosing a standard fixes the options it requires
(below) and validates the result.

|*Layers*
|Writes each {product} layer as a PDF layer that Acrobat and Illustrator can show and hide.
Needs PDF 1.5 or later.

|*Embed {product} document*
|Attaches a complete package of the document to the PDF, so opening the PDF in {product} gives
you the editable original (xref:saving.adoc[Saving]).  The attachment is visible in Acrobat's
attachments pane.

|*Optimize for fast web view*
|Arranges the file so the first page displays before the rest downloads.

|*Include document info*
|Writes the Document Info fields (xref:file-info.adoc[Adding file information]).  Always on
for PDF/X.

|*Tagged PDF (PDF/UA-1)*
|On by default.  Writes the structure a screen reader needs: every object with alt text
becomes a figure carrying that text, decorative objects are marked as artifacts, text stays
text in reading order, and the document's language comes from Document Info
(xref:names-notes.adoc[Names, notes and alt text]).  The file claims PDF/UA-1 conformance
only when it can: with *Convert text to outlines* chosen, or with no document language set, the
tags are still written but the claim is left out and the export sheet says why.  Run
menu:File[Check Accessibility…] first to find undescribed objects and low-contrast text.
|===

== Compression

[cols="1,3"]
|===
|Option |Effect

|*Color and grayscale images*
|*Automatic* (default) uses JPEG for photographs and lossless for everything else; *JPEG* with
a *Quality* of Maximum, High, Medium, Low or Minimum; *Lossless*; *None*.

|*Downsample images above*
|Reduces images whose resolution exceeds the threshold to the target: for example, downsample
above 450 ppi to 300 ppi for print, or above 150 ppi to 100 ppi for screen.  Off keeps every
image at its placed resolution.

|*Monochrome images*
|*CCITT Group 4* (default), *Lossless*, *None*, with their own downsampling threshold.

|*Compress text and line art*
|Lossless compression of everything that is not an image.  Always on except for debugging.
|===

== Fonts

[cols="1,3"]
|===
|Option |Effect

|*Embed fonts*
|*Subset* (default) embeds only the glyphs used, which is what every viewer needs.  *Complete*
embeds whole fonts, for files someone will edit.  *Convert text to outlines* writes paths
instead of text: nothing depends on fonts, but the text cannot be searched or selected, and
files are larger.

|*Always outline*
|Fonts whose license forbids embedding are outlined regardless, and the export sheet lists
them (xref:print-fonts.adoc[Fonts and printing]).  PDF/X requires embedding or outlining.
|===

== Color

[cols="1,3"]
|===
|Option |Effect

|*Colors*
|*Keep document colors* (default): sRGB stays sRGB, Display P3 stays Display P3 (tagged with
its profile; PDF 1.7 or later), Lab stays Lab, OKLab is written as Display P3, CMYK stays
CMYK, spot colors stay spot.  *Convert to CMYK* converts everything to the destination
profile, each color from its own space.  *Convert to RGB* converts to sRGB (or the chosen RGB
profile), pulling wide-gamut colors in when the profile is narrower.  See
xref:color-management.adoc[Color management].

|*Destination profile*
|The CMYK or RGB profile to convert to, and the profile named in the PDF/X output intent.
Defaults to the document's working profile.  A PDF without a PDF/X standard that keeps
Display P3 colors also names Display P3 as its output intent, so viewers know what the
document was made for.

|*Preserve spot colors*
|Keeps spot colors as named separations for the printer.  Off converts them to process using
their definitions (xref:spot-process.adoc[Spot and process colors]).

|*Preserve overprint*
|Keeps overprint settings on objects.  On by default; PDF/X requires it to be honored.

|*Embed profiles*
|Tags images and the document with their profiles.  Required by PDF/X-4, forbidden by
PDF/X-1a (which uses the output intent only).  Display P3 objects are always written with
their profile when kept; turning this off converts them to the destination RGB profile.
|===

== Pages and marks

[cols="1,3"]
|===
|Option |Effect

|*Page size*
|*Page* writes each page at its size.  *Page plus bleed* adds the document's bleed on every
side (xref:printing.adoc[Printing]).  *Custom* lets you type a size and centers the page in
it.

|*Bleed*
|Uses the document bleed, or a value you type.  Sets the PDF's bleed box; the trim box is
always the page.

|*Marks*
|*Crop marks*, *Registration marks*, *Color bars*, *Page information* (file name, page, date,
plate names), each on or off, with *Offset* from the trim and *Weight*.  Marks need room:
the page size becomes *Page plus bleed and marks* automatically.

|*Page boxes*
|Written from the above: media box (everything), bleed box, trim box, art box (the artwork's
bounds).  Layout programs read the trim and bleed boxes to place the PDF correctly.
|===

== Interactive

[cols="1,3"]
|===
|Option |Effect

|*Links from URLs*
|Objects and text with attached URLs become clickable links (xref:urls.adoc[Attaching
URLs]).

|*Notes as comments*
|Object notes from the Object panel become PDF comment annotations positioned on the object
(xref:names-notes.adoc[Names and notes]).  Useful for review PDFs.  Off for print.

|*Bookmarks from page names*
|Named pages become bookmarks in the PDF's navigation pane.

|*Open password*
|Requires a password to open the file.  *Permissions password* restricts printing, copying
and editing for anyone without it.  Not available with PDF/X.
|===

== PDF/X

PDF/X is what printers mean by "send us a print-ready PDF".  Choosing a standard sets the
options it requires and checks the result before the file is written; anything that cannot
be made to comply is listed with what {product} did about it.

[cols="1,2,2"]
|===
| |PDF/X-1a:2001 |PDF/X-4:2010

|Ask for it when
|The printer's workflow is older, or they say "X-1a".
|Any current printer; the default.

|Transparency
|Flattened on export (xref:export-vector.adoc[Exporting vector artwork]).
|Kept live; the printer's RIP flattens.

|Colors
|CMYK and spot only; every RGB object and image is converted to the destination profile.
|CMYK, spot, and profile-tagged RGB (Display P3 included) and Lab all allowed.

|Fonts
|Embedded or outlined.
|Embedded or outlined.

|Output intent
|Required; the destination profile.
|Required; the destination profile.

|Not allowed
|Transparency, RGB, layers, passwords, JavaScript, comments.
|Passwords, JavaScript.  Comments and links are written only if you turn them on.
|===

Overprint is preserved in both.  Bleed and marks are set in *Pages and marks*.  The
resulting file identifies its standard in its metadata so a preflight tool can confirm it.

== What the PDF keeps

Everything {product} draws is representable in PDF 1.4 or later: paths, text, gradients of
every shape (as smooth shadings), transparency and blend modes, clipping, images with alpha,
spot colors, Display P3 and Lab colors (PDF 1.7 or later for P3), overprint, live effects
(vector effects are expanded to paths; raster effects
are embedded as images with alpha at the document's raster effects resolution,
xref:raster-effects.adoc[Raster effects]).  Text stays selectable and searchable unless
outlined; text on a path is written as positioned glyphs, so it selects but re-flows as a
line.  Textured, pattern and PostScript fills are rendered to images.  Pages of any size up
to the PDF maximum of 200 inches are written at full size; larger pages use the PDF scaling
feature that modern readers honor.  With *Tagged PDF* on, the alt text, *Decorative*
settings and reading order from the Object panel are kept too, so the PDF reads aloud in the
order you arranged (xref:names-notes.adoc[Names, notes and alt text]).

== Working with others

PDF export reads the document at the instant you click btn:[Export] and never changes it.
The fonts embedded are those on your Mac (xref:font-substitution.adoc[Font substitution]);
a colleague on another Mac with a different font installed for the same name gets their
copy.  For a reproducible handoff, export from the same Mac each time, or embed the fonts in
the document (xref:print-fonts.adoc[Fonts and printing]).

=== Client

* The PDF writer is {product}'s own (`WTInterchange.PDFWriter`), fed by a `WTRender` backend
  that emits PDF content-stream operators rather than through `CGPDFContext`.  Reason:
  `CGPDFContext` cannot write `Separation`/`DeviceN` color spaces for spot colors, overprint
  graphics states, output intents, page boxes beyond media/crop, PDF/X identification, optional
  content groups, or embedded files, and gives no control over object streams or
  linearization.  The operator set of PDF is the Core Graphics drawing model, so the renderer's
  display list maps one-to-one; REND-001's "screen equals PDF" guarantee is met by rendering
  the corpus through both backends and diffing.
* Shadings: axial (type 2) and radial (type 3) for linear and radial gradients; contour,
  cone and rectangular gradients as type 4/6/7 meshes; gradients with more than the
  document's blend steps are written as smooth shadings regardless (steps are a print concept).
* Transparency: `ExtGState` with `/CA`, `/ca`, `/BM`, soft masks for masked objects; blend
  groups for knockout/isolated groups mapped from the document's group settings.  PDF/X-1a runs
  the `Flattener` (IO-017) first.
* Fonts: CFF and TrueType subsets built from Core Text glyph data with `ToUnicode` CMaps so
  text is searchable; Type 3 is never written.  Variable fonts are instanced to a static (xref:type-specifications.adoc#TYPE-048[TYPE-048])
  subset.
* Images: `DCTDecode` for JPEG (re-using the original JPEG bytes when the placed file is a
  JPEG and no resampling is needed), `FlateDecode` for lossless, `CCITTFaxDecode` for mono,
  `SMask` for alpha, ICC-based color spaces when embedding profiles.
* Vector colors by space (CMS-015 supplies the objects): sRGB as `/ICCBased` sRGB (or
  `/DeviceRGB` when profiles are not embedded), Display P3 as one shared `/ICCBased` object
  carrying the Display P3 profile (ICC v4, hence the PDF 1.7 gate; below 1.7, or with *Embed
  profiles* off, converted to the destination RGB profile and reported), CIELAB as `/Lab`
  with the D50 white point, OKLab converted to Display P3 (PDF has no OKLab), CMYK as
  `/ICCBased` Working CMYK or `/DeviceCMYK`.  Gradient stops of one gradient are written in
  one space -- the widest among its stops -- since a shading has one color space.  A PDF
  without a standard that keeps P3 objects gets an `/OutputIntents` entry naming Display P3
  (`GTS_PDFA1`-style dictionary without the PDF/A claim); PDF/X keeps the CMYK output intent
  and, in X-4, the P3 objects tagged.
* PDF/X: output intent dictionary from the destination profile, `GTS_PDFXVersion` in XMP,
  trapped flag `/False`, validation pass over the object graph before writing with a report
  sheet of fixes made (RGB converted, transparency flattened, comments dropped).
* Linearization is a second pass over the finished object set.  Encryption: AES-256 (PDF 2.0
  R6) or AES-128 (R4 for 1.6--1.7), never RC4.
* Annotations: `/Link` with `/URI` actions from `CommonProps.url`; `/Text` annotations from
  `CommonProps.note` at the object's top-left; outline items from page names; `EmbeddedFile`
  with `AFRelationship /Source` for the package.
* Marks are drawn by the PRINT epic's marks renderer into the margin area.
* Tagged PDF (`tagged`): the writer emits a structure tree (`/StructTreeRoot`,
  `/MarkInfo << /Marked true >>`, `/ParentTree`) with one `/Document` element per file and a
  `/Sect` per page whose kids follow `Page.readingOrder` (OBJ-041).  Each readable node
  (OBJ-040 `isReadable`) becomes a `/Figure` with `/Alt` from `accessibleDescription`
  and a `/BBox`; its content is wrapped in a marked-content sequence (`/Figure <</MCID n>>
  BDC … EMC`).  A group with `alt` is one `/Figure` around all its content.  Text blocks emit
  `/P` per paragraph (`/H1`--`/H3` when the paragraph style is marked as a heading by the
  TYPE epic, else `/P`), `/Span` per line with `/ActualText` where ligatures or outlined
  glyphs would otherwise mis-read; text on a path is one `/Span`.  Decorative nodes, page
  backgrounds, marks, guides and rasterized effects of decorative nodes are `/Artifact`
  sequences.  Links from WEB-005 become `/Link` structure elements holding the annotation
  (`/OBJR`) with `/Contents` from `NavigationProps.alt`.  `/Lang` on the catalog is
  `DocumentInfo.language`; `/ViewerPreferences << /DisplayDocTitle true >>` and the XMP
  `pdfuaid:part = 1` claim are written only when the language is set, every font is embedded,
  no text is outlined and no readable node lacks a description -- otherwise the tags stay and
  the sheet lists the reasons.  PDF/X modes keep tagging (both standards allow it).  The
  structure tree is built from the same node walk the content stream uses, so `/MCID`s and
  content never diverge.
* Undo: none.

NOTE: Deviations recorded by IO-025 (`WTInterchange/PDF`).  The writer is fed the `Flattener`'s
scene for the PDF target (transparency, soft masks and linear/radial gradients kept; text kept)
rather than a `WTRender` backend emitting operators, so screen and PDF share the display list
through the flattener.  *Fonts*: TrueType (`glyf`) fonts are embedded as `CIDFontType2` subsets
(`FontFile2`, `Identity-H`, `CIDToGIDMap /Identity`, `/W` widths, `ToUnicode`), glyph ids kept and
unused glyphs emptied; fonts with CFF outlines and variable-font instances are embedded as Type 3
fonts whose procedures hold the instance's outlines (256 glyphs per resource) with `ToUnicode`, in
place of CFF subsets -- text stays selectable and searchable; fonts whose OS/2 `fsType` forbids
embedding are outlined and reported.  Glyphs on one baseline are shown with one `TJ`, the
differences between Core Text's positions and the font's advances written as adjustments.
*Gradients* are shading patterns (types 2 and 3) over a 1024-sample function of WTRender's OKLab
ramp; a translucent ramp adds a luminosity soft mask of its alpha; Rectangle, Contour and Cone
gradients render as images (no type 4/6/7 meshes yet).  A Gradient Mask is a luminosity soft mask
whose DeviceGray group paints the mask factor as a shading -- no image.  *Colours*: sRGB is
`/ICCBased` sRGB (or `/DeviceRGB` without profiles); extended-range colour values are written
through a shared Display P3 `/ICCBased` object with a Display P3 output intent at PDF 1.7 and 2.0,
and clipped into sRGB with a note otherwise; Lab and CMYK wait for colour spaces in the display
list.  *Images*: `FlateDecode` with an `SMask` for alpha, the placed JPEG's bytes under
`DCTDecode` when nothing resamples it, JPEG re-encoding under *JPEG*, downsampling by redrawing;
`CCITTFaxDecode` is not written.  Link annotations come from `ExportNodeInfo.url` (the IO-027 sheet
option is `linksFromURLs`).  Page boxes: media, trim, bleed (with *Page plus bleed*) and art.  Not
written yet and reported in the summary: linearization, object streams, layers as optional
content and the embedded package; PDF/X standards and *Convert to CMYK* are refused until IO-026
and the CMS epic; encryption is IO-027's.  Tests open every file in PDFKit, rasterize its pages
with Core Graphics and compare them with the reference renderer (at most 2% of pixels beyond 40/255
at 2×), check text search per font kind, and run Ghostscript (`-dPDFSTOPONERROR`) over the corpus
when `/opt/homebrew/bin/gs` exists; `qpdf` and `verapdf` are not installed on the build Mac.  *For
IO-032*: every flat node keeps its `NodeID` and `PDFStreamWriter.write(_:)` is the one node walk
producing content, so marked content and the structure tree can be added around it.
