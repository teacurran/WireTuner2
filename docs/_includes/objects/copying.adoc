{product} copies objects through the clipboard, by dragging, and with two shortcuts that skip
the clipboard entirely: *Clone*, which drops a copy exactly on top of the original, and
*Duplicate*, which drops one a little to the side and can repeat a transformation as it goes.
Copies go between documents and to and from other applications in the formats those
applications understand.

A copy is a new object.  It has no memory of where it came from: editing the original later
does not touch the copy, and the copy can be edited, moved or deleted by anyone without
affecting the original.  (For copies that *do* follow their source, use symbols:
xref:library.adoc[Library and symbols].)

=== Power duplicating

Duplicate remembers what you did to the previous duplicate.  Move it, and the next Duplicate
moves the new copy the same distance; rotate it, and the next one rotates the same amount --
and both at once, if you did both.  This is the quickest way to make a row, a ring or a
spiral of copies.

To power-duplicate:

. Select an object and choose menu:Edit[Duplicate].
. Transform the duplicate: move it, rotate it, scale it, skew it or reflect it, with the
  tools, the Transform panel or the transform handles.  You can combine moving with any one
  of the others, and moving, scaling and rotating together; scaling and skewing cannot be
  combined.
. Without deselecting, choose menu:Edit[Duplicate] again.  The new copy receives the same
  transformation relative to the one before.
. Repeat step 3 for each further copy.

Selecting anything else, or editing the duplicate in another way, resets the remembered
transformation.

== Copying by dragging

To copy by dragging within a document:

. With the Pointer tool, press on the selection and wait a moment for the pointer to change.
. Hold kbd:[Option] and drag.  A plus sign beside the pointer shows a copy is being made.
. Release.  The copy is selected; the original stays put.

The *Option-drag copies* preference (menu:WireTuner[Settings… > Object], on by default) can
turn this off, in which case kbd:[Option]-drag is a plain move.

To copy by dragging between documents:

. Open both documents and arrange the windows so you can see both.
. Drag the selection from one window and drop it in the other.  The original stays in the
  source document.

You can also drag artwork out to another application that accepts drops, and drag artwork
or files in (xref:importing.adoc[Importing artwork]).

== Copying between documents

Pasting into another document brings the objects with every attribute they had.  Colors they
use are added to the destination's Swatches panel if not already present
(xref:swatches.adoc[Swatches]); styles come along by name.

Which layer the copy lands on depends on the *Remember layer info* preference
(menu:WireTuner[Settings… > General]):

* Off (default): the copy goes to the active layer.
* On: each object goes to the layer with the same name as the one it came from, created if
  necessary.  If the destination has the same layer names in a different order, the copies
  stack in the destination's order.

== Copying attributes

To copy the look of one object to others:

. Select the object whose strokes, fills, effects (and, for text, type attributes) you want.
. Choose menu:Edit[Special > Copy Attributes].
. Select the objects to change and choose menu:Edit[Special > Paste Attributes].

Paste Attributes replaces the whole attribute stack of each target.  Objects that cannot take
some attribute (a bitmap given a stroke) ignore that part.  The Eyedropper tool does the same
job interactively (xref:applying-color.adoc[Applying color]).

== Working with others

Pasted, cloned and duplicated objects appear for collaborators the moment your change
arrives, exactly where you put them.  Because a copy is a brand-new object, nothing anyone
does to the original reaches the copy, and nothing done to the copy reaches the original.

If you cut an object and someone else edits it before you paste, the paste brings back what
you cut -- their edit is not in your clipboard.  Their edit lands on the object you cut,
which is gone; after an offline stretch the review lists it as an edit to something that was
deleted and offers to restore it.

Paste In Front and Paste Behind put the copy next to the object you selected.  If that object
is moved to another layer or group at the same moment, the copy follows it there.  If it is
deleted at the same moment, the copy still lands where it was -- on top of the surrounding
objects.

== Specification

=== Data model

Pasting creates nodes.  Every pasted node gets a *new* node id (the `CreateNode` op's id);
nothing in the document links it to its source.  A `ClipboardPayload` is the native pasteboard
type and is not part of the document schema, but it is a protobuf so both documents agree on
its contents:

[source,protobuf]
----
// proto/wiretuner/clipboard/v1/clipboard.proto
// Native pasteboard type "com.villagecompute.wiretuner.objects".  Never stored in a document.
message ClipboardPayload {
  // Subtrees, in stacking order (bottom first).  Each carries its full NodeProps,
  // with the register values current at copy time and no OpIds.
  repeated ClipboardNode nodes = 1;
  // Name of the source layer of each top-level node, for "Remember layer info".
  repeated string layer_names = 2;
  // Swatches, styles, symbols and brushes the nodes reference, by their source id,
  // so the paste can resolve references into the destination (matched by name,
  // created if missing).
  repeated ClipboardAsset assets = 3;
  // Bounds of the copied selection in source pasteboard coordinates, for Paste In Front's
  // "original position" and for cross-document placement.
  Rect bounds = 4;
  // Source document id; a paste into the same document may reuse swatch refs directly.
  string source_document = 5;
}
message ClipboardNode {
  NodeProps props = 1;              // kind and all registers, denormalized
  repeated ClipboardNode children = 2;
  OpId source_id = 3;               // for resolving connector/blend references within the payload
}
message ClipboardAsset {
  OpId source_id = 1;
  NodeProps props = 2;              // swatch / style / symbol / brush props
}
----

Paste writes one `CreateNode` per node (children after parents), with `NodeRef`s rewritten:
refs inside the payload map to the new ids; refs to assets map to the destination's matching
asset by name or to a freshly created one.  A `NodeRef` to something not in the payload
(a connector's endpoint left behind) is written unset.

Copy Attributes uses the same payload with a single `ClipboardNode` whose props carry only the
appearance stack and text defaults; Paste Attributes rewrites the target's
`AppearanceProps.stack` (an `ElementDelete` of every element then `ElementInsert` of the
copies, in one change).

=== Merge semantics

* *Paste* is pure creation: it can never conflict.  Concurrent pastes by two people simply
  both appear.
* *Cut* is `SetDeleted(true)` on the source nodes.  A concurrent remote edit lands on the
  deleted node and is retained; the review sheet lists `edit vs delete` and offers *Restore*.
  The pasted copy does not carry the remote edit -- the payload was captured at cut time.
* *Paste In Front/Behind* creates nodes under the anchor's current parent with a position
  generated between the anchor and its neighbor.  If the anchor was concurrently moved to
  another parent, the move algorithm's order decides where the anchor is when the create
  applies; since `CreateNode` carries an explicit parent, the copy lands in the parent the
  paster saw.  This is the correct outcome for "paste into a group": the copy stays in the
  group even if the anchor left it.  If the anchor was deleted, the copy still lands at its
  position (deleted nodes keep their position).
* *Clone / Duplicate* are creations with positions directly above the source: same rules.
* *Paste Attributes* writes the target's stack sequence.  Concurrent recolor of a stack
  element by someone else edits an element that is now a tombstone; retained, and restorable
  by undoing the paste.
* *Remember layer info* may create a layer: `CreateNode` under `layers` with the source's
  name.  Two people pasting concurrently with the same missing layer name create two layers
  with one name; read-time normalization does *not* merge them (renaming is the user's job,
  and the Layers panel shows both).

=== Offline behavior

Copy and paste are local.  The system pasteboard is per Mac, so cross-document copies are
between documents open on the same Mac.  Pasting bitmaps creates blob references that queue
for upload (SYNC-008).

=== Server

Nothing beyond storing and relaying changes.

=== Client

* `WTModel.Clipboard`: `copy(selection) -> ClipboardPayload`, `paste(payload, into:parent,
  at:position, placement:)`.  `WTInterchange` provides the PDF, SVG, image and RTF writers and
  readers for the other pasteboard types (shared with export and import:
  xref:export-formats.adoc[Export formats]).
* `NSPasteboard` types: `com.villagecompute.wiretuner.objects` (exported by the app, conforming
  to `public.data`; objects on the pasteboard as `com.wiretuner.objects`, the name earlier builds
  wrote, are still read; `WTModel`'s `ClipboardPayload.pasteboardType` still holds that name and
  the app no longer writes it), `com.adobe.pdf`, `public.svg-image`,
  `public.tiff`, `public.png`, `public.rtf`, `public.utf8-plain-text`.  Copy writes lazily
  via `NSPasteboardItemDataProvider` for the expensive formats.
* Power-duplicate state: `WTModel.DuplicateMemory { sourceIds, matrix }` set by Duplicate,
  updated by any transform command applied to exactly that selection, cleared by any other
  command or selection change.
* Undo: a paste is one change `Paste N objects`; undo sets the created nodes deleted.
* Preferences: *Clipboard formats* (all on), *Convert colors to* (CMYK and RGB),
  *Clipboard image resolution* (144 ppi), *Option-drag copies* (on), *Remember layer info*
  (off).

NOTE: As built by OBJ-010 to OBJ-012 (`WTModel/Clipboard.swift`, `NodeCopier.swift`,
`WTApp/Document/ObjectEditing.swift`).  Deviation: `clipboard.proto` is not in `proto/` yet (proto
track), so `ClipboardPayload` is encoded by hand in the sketched message's wire format (nodes 1,
layer_names 2, bounds 4, source_document 5; `ClipboardNode` props 1, children 2, source_id 3) and
carries no assets (swatches, styles, symbols and brushes are not nodes yet; colours are inline).  A
copied root's transform is its pasteboard transform (enclosing groups baked in) and a paste
re-expresses it in the destination parent's space.  Copies go through `NodeCopier`, which is generic
over every kind: `CreateNode` with the full props, then one `ElementInsert` per SEQUENCE field found
through the merge table (nested ones after their parent element), then the children; SET members and
TEXT fields are not copied yet, a group's `clip_path` is rewritten to the copied child and its
`layer_origins` dropped.  `Paste` places on top of the active layer (centred on the visible area),
or `inFront`/`behind` an anchor inside its parent (never below a clip path); *Remember layer info*
finds the layer by name or creates it once per paste.  Only the native pasteboard type is written
and read (the PDF, SVG, image and text formats are WTInterchange's), so Copy Special and Paste Special
are not delivered.  *Power duplicating*: `DuplicateMemory` holds the transformations applied to
exactly the last duplicates since they were made (the window's `ObjectEditing` is the tools'
`CommandSink` and records every `MoveObjects`/`TransformObjects` on them); Duplicate applies it, or the
10 pt offset when nothing was recorded; any other command or selection clears it.  menu:Edit[Duplicate]
keeps kbd:[Cmd+D] from the shortcut catalog and Clone has no default key (the guide's kbd:[Cmd+Option+D]
and kbd:[Cmd+Shift+D] are left to the shortcut presets).  Paste In Front is kbd:[Cmd+Option+V] and
Paste Behind kbd:[Cmd+Option+Shift+V].

NOTE: As built: a copy keeps its attribute stack's order.  The three lists of a stack share one
position space, which a node's typed props cannot show, so `NodeTree` records the stack order read
from the document (`stackOrder`: the list of each row, bottom first) and `NodeCopier` inserts the
stack as one run in that order through `PasteAttributes.insert` -- the path Join and Split use --
with each attached effect attached to the copy of its element; before, each list was positioned on
its own and Paste, Clone and Duplicate regrouped an interleaved stack.  A tree without a matching
order stacks fills, then strokes, then effects.  The pasteboard carries the order as `ClipboardNode`
field 4 (`stack_order`, one byte per row naming its `AppearanceProps` list); a payload with an
unknown list number reads without an order.  Copies of text blocks, blends, extrusions, images and
placed SVG animations keep their paste offset (their transforms were not written before).

NOTE: As built by OBJ-013 (`WTApp/Tools/PointerTool.swift`, `WTApp/Document/ObjectDragging.swift`).
kbd:[Option]-drag copying was OBJ-008's (`DuplicateObjects` on release); this adds the plus-sign cursor
(`NSCursor.dragCopy`) whenever the release would copy -- kbd:[Option] pressed before or after the drag
began, with *Option-drag copies paths* on -- so releasing kbd:[Option] before the drop shows the arrow
and moves.  A Pointer move of the selection whose pointer leaves the window's content becomes an
`NSDraggingSession` (the move itself is abandoned): one item carries the objects under the native type
(the clipboard's `ClipboardPayload`), a second is an `NSFilePromiseProvider` for "<document> objects.pdf"
written by the export pipeline (the Export sheet's PDF defaults with *Selection*).  Every document
window's canvas takes the native type: the objects are pasted centred on the drop point on the window's
active layer and selected, in one change (`Paste` with `.top(layer:center:)`, *Remember layer info* as
for Paste).  Deviations: a drag out of the window always copies -- the source document is never changed,
even when the drop is in another window of the same Mac (the page's "between documents" is a copy) -- and
it begins only at the window's edge, not at the canvas's, because dragging to the canvas edge
autoscrolls.  Only the native type and the PDF promise are written (the other pasteboard formats are
OBJ-015's).  The Finder drop and the drag between windows are exercised by unit tests of the items, the

NOTE: As built by OBJ-014 (`WTModel/AttributePaste.swift`).  `AttributePayload(copying:from:)` reads the object's stack
in stack order and, for text, the look attributes of its first character (font, face, size, leading, range kerning,

data fields, mentions, inline graphics, language or line-break controls, which belong to the words).  Deviations: the
payload goes on the pasteboard under its own type `com.villagecompute.wiretuner.attributes` (same `ClipboardPayload`

without anchors.  `PasteAttributes` deletes every live element of each target's stack in one `ElementDelete` and inserts

payload does not name are cleared.  A text block takes no object stack and a path no type attributes (ignored parts);
locked objects are skipped.  Label `Paste attributes` or `Paste attributes to N objects`.  Found while building: a
`NodeCopier` copy (Paste, Clone, Duplicate) positions each of the three lists on its own, so a copied stack whose lists
interleave (a stroke below a fill) comes out regrouped by list; Join and Split copy stacks through `PasteAttributes.insert`

NOTE: As built by OBJ-015 (`WTInterchange/Clipboard/ClipboardFormat.swift`, `ClipboardWriter.swift`,
`ClipboardReader.swift`; `WTModel/ClipboardFormats.swift`).  `ClipboardSettings` holds the three
