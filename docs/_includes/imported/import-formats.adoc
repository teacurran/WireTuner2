{product} imports vector drawings, bitmap images, placed files and text.  This page lists every
format the Import sheet accepts, what each one turns into once it is in the document, and the
options the btn:[Options…] button offers for it.  The mechanics of placing a file -- the Import
command, dragging from the Finder, pasting -- are on xref:importing.adoc[Importing artwork].
The vector formats -- PDF, Illustrator, SVG, DXF and EPS -- also open as documents of their own with
menu:File[Open File…] or from the Finder, converted the same way, with a page per PDF page or
Illustrator artboard and the file's layers as layers
(xref:creating-opening.adoc#opening-other-file-types[Opening other file types]).

== PDF

A PDF page is converted into native objects: paths with their fills and strokes, text, images,
and clipping groups.  Linear and radial gradients are kept as gradients; shadings {product}
cannot represent (meshes, free-form shadings) become a 10% black fill so the shape stays.  Text
uses the fonts installed on your Mac; a font the PDF embeds but you do not have is offered for
substitution (xref:font-substitution.adoc[Font substitution]).  Comments (notes) in the PDF are
placed on a layer named *Notes* and link rectangles on a layer named *URLs*, each with its
target set as the object's URL (xref:urls.adoc[Attaching URLs]).  A PDF saved from Illustrator
comes in the way an Illustrator file does, with its Illustrator layers (<<adobe-illustrator,Adobe
Illustrator>>).

To import a PDF:

. Choose menu:File[Import…], select the PDF and click btn:[Options…].
. Set the options and click btn:[OK], then btn:[Import].
. Click or drag to place the content.

[cols="1,3"]
|===
|Option |Effect

|*Pages*
|*All* or a page range (`1`, `2-4`, `1,3,7`).  When you import more than one page, each page's
content is grouped separately and the groups are placed in a row, left to right, with the
*Keep both offset* between them.  Page size and orientation are not imported; to get one
document page per PDF page, open the PDF instead (xref:creating-opening.adoc[Creating and
opening documents]).

|*Text*
|*Editable text* keeps text as text blocks, one per line or paragraph as the PDF structures it.
*Convert to paths* turns every glyph into a path so the appearance is exact even without the
fonts.

|*Import notes*
|Places comments on the *Notes* layer as text blocks.  On by default.

|*Import links*
|Places link areas on the *URLs* layer as unfilled rectangles carrying the URL.  On by default.

|*Keep page clip*
|Wraps each page's content in a clipping group the size of the page's crop box, so artwork
that bleeds beyond the page is hidden as it would be in a viewer.  Off by default; when off,
everything the page contains is imported unclipped.
|===

TIP: If a page arrives as a single object, it is a clipping group made by *Keep page clip*.
Select it and choose menu:Edit[Cut Contents] to release the objects.

[[adobe-illustrator]]
== Adobe Illustrator

Illustrator files saved with the *Create PDF Compatible File* option (the default since
Illustrator 9) contain a PDF, and {product} imports that PDF with the PDF options above.  Live
blends become groups of the blended shapes; gradient meshes become paths with a 50% black fill.
Illustrator layers become groups named after the layers; hidden layers are left out of an import
(the import says so) and layers with nothing on them are skipped.

Opened as a document rather than imported, an Illustrator file keeps its artboards as pages, each
named after its artboard, and its layers as layers, bottom to top in the same order, with the same names and each object on its own
layer.  A layer that is hidden in Illustrator opens hidden with its artwork, a locked one opens
locked, one set not to print becomes a background layer and one shown as outlines draws as
keylines.  Two layers with the same name are told apart by a number after the second name
(*Art*, *Art 2*).  When {product} cannot match the layers to the artwork with certainty, the file
opens the way its PDF reads -- usually with all the artwork on one layer -- and the open report says
so; no artwork is left out either way.  A PDF saved from Illustrator is treated the same way when
you open or import it: its Illustrator layers, hidden layers and artboard names come with it.
Artboard names are read from files saved by Illustrator CS4 to 2019; files saved by Illustrator
2020 or later open with their artboards as unnamed pages.

Older Illustrator files (versions 1.1 through 8) and Illustrator EPS files are PostScript-based.
{product} reads their drawing operators directly -- paths, fills, strokes, text and placed
images -- without a PostScript interpreter, which covers everything the format was designed to
carry.  A file that uses PostScript constructs outside that set is placed as an EPS instead.

[[freehand]]
== FreeHand

FreeHand documents and templates from FreeHand 3 to FreeHand MX (11) open in {product} as editable
artwork, and most of what FreeHand could do comes in as the same live feature here, because
{product} follows FreeHand's model:

* *Layers* become layers when you open the file, and groups named after them when you import it
  into a document.  A hidden layer opens hidden with its artwork; it is left out of an import (the
  import says so).  The Guides layer is never artwork.
* *Pages*: every page of a multi-page document comes in; opening the file gives you its pages,
  importing places the whole pasteboard spread at its natural size.
* *Paths, rectangles, ellipses, compound paths and groups* keep their shapes and fill rules.
  Rectangles and ellipses arrive as paths.
* *Paste Inside* becomes a clipping group whose clipping path keeps its own fill and stroke, drawn
  as FreeHand drew them.
* *Colours*: named colours become swatches of the same name -- CMYK colours stay CMYK -- and
  White, Black and Registration are the document's own.  A colour from a spot library (PANTONE,
  TOYO, DIC, HKS) becomes a spot colour; check other spot colours in the Swatches panel, because
  FreeHand 9 and later record the choice in a way {product} cannot read.
* *Fills*: basic, graduated and radial fills (with all their colours), lens fills (transparency,
  magnify, lighten, darken, invert, monochrome), tiled fills and pattern fills stay live.  Custom
  and textured fills become their colour.
* *Strokes*: width, colour, dash and arrowheads.  Pattern and custom strokes become basic strokes.
* *Text*: text blocks keep their frame, paragraphs, fonts, sizes, colours and alignment; text
  attached to a path stays on its path.  A font you do not have is kept by name for font
  substitution.  Text blocks with several columns or rows arrive as one frame.
* *Symbols* become symbols in the Library and their instances stay instances when you import the
  file; a file opened as a document shows its instances as groups.
* *Images* placed in the file come in as images.
* *Blends* come in as groups of their steps; envelopes, perspective projections, brush strokes,
  3D extrusions, shadows, glows and the other live effects FreeHand added in version 10 and MX come
  in without the effect.

The import notice lists whatever was approximated or left out of a file.

== SVG

SVG files are converted to native objects.  Shapes, paths, groups, gradients, clipping, opacity,
dashes and embedded or referenced images are imported.  Text can be kept editable or converted
to paths.  CSS in `<style>` elements and `style` attributes is applied; filters, masks,
patterns, animation and scripts are not, and the parts they affect are imported without them.
The document's `viewBox` sets the natural size, at 96 pixels per inch.

[cols="1,3"]
|===
|Option |Effect

|*Text*
|*Editable text* or *Convert to paths*, as for PDF.

|*Flatten groups*
|Replaces the file's nested groups with one group around everything.  Off by default.
|===

== AutoCAD DXF

DXF is the exchange format of CAD applications.  {product} reads ASCII and binary DXF and
imports the two-dimensional entities: lines, polylines, arcs, circles, ellipses, splines,
hatches as filled paths, text and multiline text in the default font, and block references
expanded in place.  Three-dimensional entities are flattened to the drawing's top view;
anything without a two-dimensional appearance is ignored.  Each layer becomes a group named after
it when you import the file, and a layer when you open it.  A layer that is off or frozen opens
as a hidden layer with its artwork; it is left out of an import (the import says so).

[cols="1,3"]
|===
|Option |Effect

|*Import invisible block attributes*
|Imports attribute entities that the file marks invisible.  Off by default.

|*Convert white strokes to black*
|CAD drawings are often drawn white on a dark screen.  On by default.

|*Convert white fills to black*
|As above, for filled entities.  On by default.

|*Units*
|How to read the file's drawing units when the file does not say: inches, millimeters, or
points.  Default inches.
|===

== EPS

An EPS file is placed, not converted.  {product} shows the preview the file carries (a TIFF or
EPSI preview, or a PDF-compatible stream when the EPS was written by a recent Illustrator) and
keeps the PostScript for output: an EPS export writes it through unchanged, and printing and
exports to PDF and other formats use the preview.  An EPS with no preview shows as a gray
box of its bounding-box size with the file's name.

You can move, scale, rotate and skew a placed EPS, and crop it with Paste Inside
(xref:clipping-paths.adoc[Clipping paths]).  You cannot edit its contents or apply fills,
strokes or effects to it while it is placed.

[[converting-eps]]
=== Converting a placed EPS

Most EPS files saved by a recent Illustrator carry a PDF-compatible copy of the artwork.  Such a
file can be turned into ordinary objects:

. Select the placed EPS.
. Choose menu:Object[Convert to Editable], or Control-click it and choose *Convert to
  Editable*.

The artwork arrives as a group named after the file, at the size and position the preview had,
converted as a PDF page would be (paths, text as editable text, images and clipping groups, as
under *PDF* above).  The placed file is replaced, so EPS exports no longer pass its PostScript through.
One undo step.  An EPS that carries only PostScript cannot be converted -- {product} does not
interpret PostScript -- and stays placed; an alert says so.  In a shared document the file must
have downloaded to your Mac first.

Desktop Color Separations (DCS 1.0 and 2.0) files are placed as EPS files using their composite
preview.  {product} does not separate through DCS plates; to print separations, work from the
original image instead.

== SVG animations

An SVG file that contains animation (CSS, SMIL or script) is placed as a live object rather
than converted: it plays on published pages and in Preview in Browser and exports unchanged
into SVG and HTML output.  The Import options sheet can force either treatment.  See
xref:svg-animation.adoc[SVG animations and browser preview].

== Bitmap formats

All bitmap formats behave the same way once imported: one image object with the file's pixel
dimensions, resolution, color mode and alpha channel (xref:bitmaps.adoc[Working with bitmap
images]).  Format-specific notes:

TIFF:: Alpha channels, 16 bits per channel, CMYK and LAB, and embedded color profiles are all
read.  Multi-page TIFFs import their first page.

JPEG:: 8-bit RGB, CMYK and grayscale.  JPEG is lossy: every save from an external editor
recompresses it, so prefer TIFF or PNG for images you expect to edit again.  A grayscale JPEG
can be tinted with a fill color.

PNG:: 8- and 16-bit, palette and truecolor, with alpha.  A PNG that carries an editor's private
vector objects, layers or frames imports as its flattened picture; that private data is not
read.

GIF:: Up to 256 colors, with one transparent color honored as alpha.  Animated GIFs import their
first frame; for animation see xref:animation.adoc[Animation].

BMP, Targa:: Read at their native depth; Targa alpha is honored.

Photoshop (PSD):: Imported as the flattened composite Photoshop saves in the file, with
transparency.  Layers are not imported separately.  To edit the layers, use
xref:external-editors.adoc[Edit With…] and Photoshop.  To keep spot channels, export from
Photoshop to a format {product} reads; DCS is placed as an uneditable EPS.

HEIC, WebP, AVIF:: Read through macOS's image support, including alpha where the format has it.
HEIC photos from iPhones carry their orientation as metadata; {product} applies it on import so
the picture appears upright.

== Working with others

Import options are a per-user setting on your Mac; a collaborator importing the same file with
different options gets a different result, and both results are just objects in the document.
Everything else about collaborating on imported artwork is on xref:importing.adoc[Importing
artwork]: a vector import appears for others all at once, a bitmap as a placeholder until its
pixels have uploaded, and a placed EPS likewise since its file is stored like an image.

ifdef::spec[]
== Specification

=== Data model

Bitmaps use `ImageProps` from xref:importing.adoc[Importing artwork].  Vector imports emit
ordinary nodes.  EPS needs a kind of its own (placed SVG animations have theirs on
xref:svg-animation.adoc[SVG animations and browser preview]):

[source,protobuf]
----
// proto/wiretuner/doc/v1/placed_file.proto (sketch)

enum PlacedFileFormat {
  PLACED_FILE_FORMAT_UNSPECIFIED = 0;
  PLACED_FILE_FORMAT_EPS = 1;
}

// A file kept as-is and shown through its preview.  ATOMIC as a whole: the preview, bounding
// box and file describe one placed file and are replaced together by "Update from source".
message PlacedFileContent {
  PlacedFileFormat format = 1;
  bytes blob_sha256 = 2 [(buf.validate.field).bytes.len = 32];      // the original file
  string source_name = 3 [(buf.validate.field).string.max_len = 256];
  // Bounding box from the file (EPS %%BoundingBox), in points; natural size and origin.
  Rect bounds = 4 [(wt.crdt.field).merge = MERGE_ATOMIC];
  // Preview blob: a PNG rendered from the TIFF/EPSI preview or the PDF-compatible stream.
  // Empty when the file carries none; the renderer then draws a gray box with source_name.
  bytes preview_sha256 = 5;
  int32 preview_width = 6;
  int32 preview_height = 7;
}

// NodeProps.kind case `placed_file` = 171 (IMG block).
message PlacedFileProps {
  CommonProps common = 1;
  PlacedFileContent content = 2 [(wt.crdt.field).merge = MERGE_ATOMIC];
  // Link record for the Links panel, as ImageProps.source.
  NodeRef source = 3 [(wt.crdt.field).on_dangling = REF_FALLBACK_UNSET];
}
----

The file's facts are one ATOMIC register (`content`) rather than the whole kind message, so
the name, notes and transform on `CommonProps` and the `source` link stay independent registers
as for every node.

=== Merge semantics

* A vector import is a batch of `CreateNode` ops; it never conflicts with anything.
* `PlacedFileProps` is ATOMIC LWW: two concurrent *Update from source* operations keep the
  later; the review sheet lists it as *same register* with both previews.
* Import options are local preferences and never merge.
* Read-time normalizations: a `placed_file` whose blob is unavailable renders the preview if
  cached, else the gray box; a `bounds` of zero area reads as 1 × 1 inch so the node remains
  selectable.

=== Offline behavior

Every converter runs on the client, so every format imports offline.  Placed EPS and SVG
animation files upload their blob and preview blob through the same queue as images.

=== Server

Nothing beyond storing and relaying changes and blobs.

=== Client

* Converters live in `WTInterchange` behind one protocol: `Importer.probe(url) -> Descriptor`
  (format, preview image, natural size, options schema) and
  `Importer.convert(url, options) -> ImportResult` (a subtree of `WTModel` node prototypes plus
  blobs to register).  The import sheet's btn:[Options…] renders the options schema with a
  SwiftUI form, so adding a format never touches the sheet.
* PDF: `CGPDFDocument` + a content-stream scanner (`CGPDFScanner`) producing paths, text runs
  (with `CGPDFFont` decoding to Unicode where a ToUnicode map exists, else per-glyph outlines
  via *Convert to paths*), images (`CGPDFDictionary` XObjects re-encoded to PNG/JPEG blobs),
  shadings, and clip stacks.  Annotations give notes and links.  PDFKit is used for the sheet
  preview only.
* Illustrator legacy: a tokenizer for the Adobe Illustrator PostScript subset (the
  `Adobe_Illustrator_AI5` operator set: `m l c v y`, `f F s S b B`, `N n`, `u U` groups,
  `Lb`/`LB` layers, `Tx`/`TX` text, `XI` raster).  Files that reach an operator outside the set
  fall back to placement.
* SVG: XML parser (`XMLParser` or libxml2 via `Foundation`) with a small CSS cascade, units to
  points at 96 px/in, `transform` stacks to `CommonProps.transform`, gradients to the ATTR
  epic's gradient message, text through Core Text for glyph outlines when converting to paths.
* DXF: a group-code reader for ASCII and binary, entity handlers for the two-dimensional set,
  block expansion, bulge arcs converted to Béziers (GEO-001), splines from control points.
* EPS: DSC header parse (`%%BoundingBox`, `%%HiResBoundingBox`), preview extraction (TIFF
  section of a Windows EPS binary header, EPSI hex bitmap, or the embedded PDF stream when
  present, rendered with `CGPDFDocument`), PostScript body kept verbatim in the blob for
  print pass-through (PRINT epic).
* Bitmaps: ImageIO through IMG-002.  HEIC orientation is applied by re-encoding as PNG when
  the EXIF orientation is not identity, so `PixelSource` dimensions are the upright ones.

NOTE: Deviation recorded by IMG-008.  The converters do not produce `WTModel` node prototypes:
`WTInterchange` sits below `WTModel` for importing, so every converter returns a neutral
`ImportedScene` (`WTInterchange/Import/ImportedScene.swift`) and `WTModel` turns it into ops
(*Imported scene to document*, below).  The protocol works on bytes, so tests need no files:
`Importer.probe(_ data:, name:, format:) -> ImportDescriptor` (natural size, pixel size and mode,
page count, a preview, whether the file is placed) and `Importer.convert(_ data:, name:, format:,
options:, context:) -> ImportedScene`; `optionsSchema(for:)` returns an `ImportOptionsSchema`
(fields of kind toggle, choice or text with defaults) that the sheet renders.
`ImportRegistry.convert(contentsOf:)` checks the 200 MiB limit before reading a file, and
`ImportRegistry.format(of:name:)` recognises a file by its bytes before its extension (a PNG
named `.jpg` imports as PNG; a PDF-compatible file named `.ai` stays Illustrator).  Option values
persist per format through `ImportOptionsStore` (a JSON value per format in `UserDefaults`,
normalized against the schema on read so a stale value never reaches a converter).  Converters
read preferences from `ImportContext`: *Downsample images larger than* in pixels, the size
limit, and *Keep both offset* (the gap between PDF pages placed in a row).
`ImportedScene.exportScene()` draws a converted scene through WTRender's display list, which the
sheet preview and the round-trip tests use.  The per-format typed options are
`PDFImportOptions`, `SVGImportOptions` (with the *Animation* choice of
xref:svg-animation.adoc[SVG animations]: automatic, place or convert) and `DXFImportOptions`
(the three filters and *Units*).  IMG-008's `WTApp`/`WTModel` half -- the sheet, per-format
persistence, the "Import _file_" change and the merge test -- is described after the mapping
table below.

NOTE: IO-040 (xref:decisions.adoc#D-082[D-082]) adds opening a file as a document to the protocol:
`Importer.opensAsDocument(_:)` (the vector formats; bitmaps say no) and `Importer.document(...) ->
ImportedDocument` -- one `ImportedPage` per PDF page or Illustrator artboard, layers kept as layer groups
-- with `ImportRegistry.documentFormats` and `document(contentsOf:)` for the app.  A new importer is
opened by the app as soon as it is registered; the default `document` is its converted scene on one
page.  The mapping to pages and layers is on xref:creating-opening.adoc[Creating and opening documents].

==== Imported scene to document

What `WTModel` implements to place an `ImportedScene` (one change labelled "Import _file_", or
"Place _file_" for bitmaps and placed files).  Coordinates are points with y down and the
scene's `bounds` top-left at the origin; the placement transform (click point, or marquee fit)
is applied to the top node only.

[cols="1,3"]
|===
|`ImportedScene` |Document

|`subtree`
|The node created on the current layer (the fallback rule on xref:importing.adoc[Importing
artwork]): for `kind == .vector` one `group` named after the file holding `nodes` in order; for
`.bitmap` the single `image` node; for `.placed` the single placed node.  Siblings take
fractional positions in order, back to front.

|`layers`
|Each `ImportedLayer` goes onto the document layer of that name (*Notes*, *URLs*), created at the
top of the layer list when missing, in the same change.

|`ImportedGroup`
|`group` node, `GroupProps.kind` `GROUP_KIND_GROUP`; `name` → `CommonProps.name`, `transform`
→ `CommonProps.transform`; `opacity` < 1 → a `TransparencyEffect` (Basic, 100 − opacity × 100)
in `appearance.effects`.  With a `clip`: `GROUP_KIND_CLIP` whose first child is a `path` node
made from the clip (no fills or strokes, `even_odd` from its rule, the clip's own `transform`)
and `clip_path` referencing it (OBJ-027).  `role == .layer` is a group too (Illustrator, DXF and
PDF optional-content layers arrive as groups named after the layer); its `layerState` is used only
when the file is opened as a document.

|`ImportedPath`
|`path` node: one `Contour` per `ImportedContour` (`closed`), its points from
`ImportedContour.pathPoints` -- `anchor`, `in_handle` and `out_handle` as offsets (zero =
retracted), `kind` `POINT_KIND_CURVE` when `smooth`, else `POINT_KIND_CORNER`; `even_odd` from
`fillRule`; `fill` → one Basic fill (`.solid`) or one gradient fill (`.gradient`: WTRender's
`Gradient` maps field for field onto `GradientFill` -- kind, behavior, repeat count, axis in the
path's own coordinates, stops); `stroke` → one Basic stroke with width, cap, join, miter limit,
dash and phase (a width of 0 is a hairline); `opacity` as for groups; `url` →
`CommonProps.url`; `name`, `transform` as for groups.

|`ImportedText`
|`text` node (point text, `auto_width`): the runs' strings concatenated with a line break
between runs whose baselines differ, each run's `fontName` (a PostScript name, resolved through
font substitution when missing), `fontSize` and fill as character marks; `transform` →
`CommonProps.transform`, the first run's `origin` the block's baseline origin.

|`ImportedImage`
|`image` node: `PixelSource` from `pixels` (`blob_sha256`, `format` = the blob's UTI,
dimensions, `mode`, `bits_per_channel`, `has_alpha`), `dpi_x`/`dpi_y`, `source_name` and
`CommonProps.name` from `name` (the file name for a bitmap import), `transform` →
`CommonProps.transform` (it maps the natural rect).  The blob goes into the local cache and
`blobs_pending` (SYNC-008).  `ImageProps.source` is the link record's `asset` node for a bitmap
imported from a file (xref:linking-embedding.adoc[Linking and embedding]) and unset for images
that came inside a vector file or from the pasteboard.

|`ImportedPlacedFile`
|`.eps` → `placed_file` (`PLACED_FILE_FORMAT_EPS`, `blob_sha256`, `bounds`, `source_name`,
and from `preview` -- the PNG blob and its pixel size -- `preview_sha256`, `preview_width` and
`preview_height`, left empty when there is none);
`.svgAnimation` → `svg_animation` with an `asset` node for the blob, `natural_size` from
`bounds`, `duration_ms` and `kinds` from the case; the poster is WEB-025's.

|`ImportedPaint.swatch`
|A Basic fill (or stroke, or text fill mark) whose `ColorRef.swatch` names the document's swatch of
that name when it is one of the protected White, Black and Registration (FreeHand's
`[Registration]` reads as Registration) or holds the same colour and spot choice; otherwise a swatch
created in the same change at the end of the list (`SwatchProps` name, value, spot), `-N` suffixed
when the name is taken.  The reference caches the swatch's colour.  All of a scene's swatches are
written before its nodes.

|`ImportedPaint.pattern`, `.lens`, `.tiled`
|`PatternFill` (colour, bitmap rows), `LensFill` (type, colour, amount 0...100, magnification
1...20, centrepoint, objects only), `TiledFill` (the tile's paths and groups as the `Subtree`
through `Subtrees.tile`, moved so its bounds start at the origin; angle, scales in percent -- 0 or
not finite read 100 -- and offset).  A tile keeps no clip reference, so its clipping groups are
plain groups; text, images and placed files have no tile drawing.  A pattern stroke is a
`PatternStroke` (colour, width, bitmap).

|`ImportedStroke` arrowheads
|`BasicStroke.start_arrowhead` / `end_arrowhead`: the outline's contours (at most 64) in stroke
widths, filled, named.

|`ImportedGroup.clipAppearance`
|The clip path keeps its fill and stroke (they draw below and above the contents, clip-group
rendering, OBJ-028); without it the clip path is geometry only, as for PDF and SVG.

|`ImportedGroup.Role.instance(symbol:)` with `ImportedScene.symbols`
|Each `ImportedSymbol` is a `symbol` node after the document's (name; origin the artwork's control
bounds' centre, as *Convert to Symbol* sets it) with its artwork as children; symbols used inside
other symbols come first.  An instance group is an `instance` node of that symbol whose transform
is the translation to the origin, then the group's transform, then the placement; its name is the
group's.  A group naming a symbol the scene does not hold is imported as the plain group.

|`ImportedText.frame`, `.path`, `.alignment`; `ImportedTextRun.family`, `.style`
|A frame makes area text: the block's origin is the rectangle's top-left corner (the transform
without a baseline offset), `width` and `height` set, `auto_width` off.  A path makes text on a
path: `TextOnPathProps.mode` along, the path a child `path` node (no paint) in the block's space.
An alignment other than left is written on every paragraph (each newline's registers and
`tail_paragraph`).  A run's family and style, when given, are the marks' font family and style
instead of the PostScript name's lookup.

|`ImportedScene.blobs`
|Every blob once, in first-use order: stored and queued before the change that references them;
two imports of the same bytes share one blob (content addressing).

|`notes`

object set to no stroke (or fill) writes the key with the value record 0; libfreehand dropped
zero values, so the object took its style's stroke -- a frame rectangle with neither fill nor stroke
came in with the Normal style's 1 pt black outline.  Patch 0003 (`tools/freehand/patches`) keeps the
zero; `FreeHandConverter.style` reads a zero fill or stroke as None over the parent's, an absent key
as inherited, and a zero "contents" as no Paste Inside.  *Closed paths*: libfreehand keeps a path's
closed flag apart from its segments (its last curve returns to the start, no `Z`); a contour is now
closed when the path is or when it ends where it began (libfreehand's own rule, `FH_EPSILON`), so its
stroke joins there.  *Opening named colours*: opening a file as a document (`DocumentImport`) wrote
every named colour as an inline colour; it now writes `ImportedDocument.swatches` first, as an
import does, against the state with the template so the file's White, Black and Registration are
the document's own.  The logo's letter cut out of a stroked panel drew filled because GEO-003 could
not resolve its stroke outline (D-091).  Tests: `FreeHandNoneAndClosingTests` (FreeHand 10 files
written byte by byte), `DocumentImportTests.namedColoursOpenAsSwatchesWithTheirCMYK`.
