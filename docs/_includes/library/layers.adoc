Layers split an illustration into stacked planes, the way a traditional illustrator draws the
parts of a picture on separate sheets of tracing film.  Every object sits on exactly one layer,
each layer keeps its own front-to-back order of objects, and the layers themselves stack in the
order the Layers panel shows them.  A new document has three layers: *Foreground*, where drawing
and importing happen until you choose another layer; *Guides*, which holds ruler guides and
guide paths; and *Background*, a non-printing layer for reference material.  You can hide, lock,
reorder, merge, recolor and remove layers, and you can decide which ones print.

== The Layers panel

The Layers panel lists every layer in the document, frontmost at the top, and under each layer's
disclosure triangle the objects on it (<<objects,Objects in the Layers panel>>).  Each layer row carries,
from left to right: a visibility check mark, a Preview/Keyline circle, a padlock, the layer's
highlight color swatch, and the layer name.  A pen icon to the right of a name marks the
*active layer*, the one new objects and imports land on.

To show the Layers panel, do one of the following:

* Choose menu:Window[Layers].
* Click the Layers button in the Main toolbar.

A horizontal *separator line* divides the list.  Layers above it are *foreground layers* and
print; layers below it are *background layers*, which never print and whose objects are drawn
dimmed on screen.  The Background layer starts below the line; any layer can be moved there.

[cols="1,3"]
|===
|Column |What it does

|Check mark
|Shows or hides the layer.  Hidden layers cannot be edited.  A hidden layer can still be
printed if *Include invisible layers* is turned on in the output options
(xref:output-area.adoc[Setting the output area]).

|Circle
|A filled circle means the layer draws in Preview; a hollow circle means it draws in Keyline
(outlines only).  This affects the screen only, never printing or export.  The document-wide
view modes on xref:document-view.adoc[Viewing the document] combine with the per-layer setting:
a layer set to Keyline is always drawn as outlines.

|Padlock
|Locks the layer so its objects cannot be selected, moved or edited from the canvas, while
remaining visible.

|Color swatch
|The layer's *highlight color*: the color of selection outlines, points and transform handles
for objects on this layer.  It has no effect on the objects' own colors.

|Name
|Click to make the layer active.  Double-click to rename.
|===

The panel's options menu (the control at the top right of the panel) holds:

[cols="1,3"]
|===
|Command |What it does

|*New*
|Adds a layer directly above the active layer and makes it active.

|*Duplicate*
|Copies the selected layer with all of its objects; the copy sits above the original.

|*Remove*
|Deletes the selected layers and everything on them, after a confirmation when any of them is
not empty.

|*Merge Selected Layers*
|Combines the selected layers onto the lowest one of them.

|*Merge Foreground Layers*
|Combines every layer above the separator, except Guides, onto the lowest foreground layer.

|*Move Objects to Current Layer*
|Moves the selected objects onto the active layer.

|*All On* / *All Off*
|Shows or hides every layer at once.

|*Locate Object*
|Shows the row of the selected object (<<finding-rows,Finding an object's row>>).
|===

The same commands are on the context menu of a layer row (kbd:[Control]-click or right-click),
which adds *Move Selection to This Layer* for the row you clicked.

== Objects in the Layers panel [[objects]]

Every layer row has a disclosure triangle.  Click it to list the objects on the layer, frontmost
at the top, the same order they stack in on the page.  Objects that hold other objects have
triangles of their own: a group lists its members, a clipping group its contents with the clip
path at the bottom, a blend its key objects, an extrusion, envelope or perspective object the
shape it holds, and a chart the artwork it repeats.  kbd:[Option]-click a triangle to open or
close everything under it at once.

Each object row shows, from left to right: an icon for the kind of object, a small picture of the
object, its name, an eye and a padlock.  The picture is the object as it draws, on white, shrunk to
fit the row; it appears a moment after the row scrolls into view and changes when the object does.
An object you have named shows its name.  One you have not shows what it is -- *Path*,
*Compound Path*, *Rectangle*, *Group*, *Clip Group*, *Clip Path*, the symbol's name for a symbol
instance, the start of the text for a text block -- in dimmed italics, so you can see at a glance
which objects still need names.

To find an object by name:

* Type in the *Find objects by name* field at the top of the panel.  Only the objects whose names
  (or, for unnamed ones, what the row says) contain what you typed are listed, with the layers and
  groups they are in opened around them.  Clear the field to see everything again.

=== Finding an object's row [[finding-rows]]

Selecting an object on the canvas opens the rows above it, but in a long list its row can still be
far from where you are looking.  To bring the row of the selected object into view, do one of the
following:

* Choose menu:Object[Locate Object].
* kbd:[Control]-click the object on the canvas and choose *Locate Object*.
* Choose *Locate Object* from the Layers panel's options menu.

The Layers panel opens if it was closed, the layer and the groups above the object open, and its
row is selected in the middle of the list.  A search that hides the row is cleared.  When several
objects are selected, the row of the first one is shown.  If the object is out of view in the
window, the window scrolls to it as well.

=== Selecting objects from the panel

The panel and the canvas share one selection.  Selecting an object on the canvas highlights its
row and opens the layers and groups above it so the row shows; selecting rows in the panel
selects their objects on the canvas.

To select an object from the panel, do one of the following:

* Click its row.  This selects the object alone -- for a member of a group, the member itself, as
  the Subselect tool would.
* kbd:[Cmd]-click rows to add objects to the selection or take them out.
* kbd:[Shift]-click a row to add every object row between it and the last one you clicked.

Objects on hidden or locked layers, and objects hidden with menu:View[Hide Selection], are not
selected from the panel, as they are not on the canvas.  A locked object can be selected but not
changed.

=== Moving through the rows with the keyboard

Click a row (or the list) and the keys move through it, selecting as they go:

* kbd:[Down] and kbd:[Up] select the next or the previous row and its object on the canvas.  On a
  layer row they select the layer in the panel and nothing on the canvas.  Hold kbd:[Shift] to
  add the rows you move over to the selection.  The separator line is skipped.
* kbd:[Right] opens a closed layer or group; pressed again, it moves into it, to its first row.
* kbd:[Left] closes an open layer or group; on any other row it moves to the layer or group the
  row is in.
* Hold kbd:[Option] with kbd:[Right] or kbd:[Left] to open or close everything inside the row too.
* kbd:[Return] (or kbd:[Enter]) starts renaming the selected row.  Type the name and press
  kbd:[Return] again: the name is kept and the keys go back to the list, ready for the next row.
* Type the first letters of a name to jump to the row that starts with them.

Moving onto the row of an object that cannot be selected -- on a hidden or locked layer, or hidden
with menu:View[Hide Selection] -- highlights the row and selects nothing on the canvas; the next
key goes on from there.  The keys never make a layer active or move objects, as clicking a layer
name can.

=== Naming objects

Names are what make a long list readable.  You can name any object -- a single line, a path, a
group -- and the name is shared with everyone working on the document.

To name an object, do one of the following:

* Double-click its name in the Layers panel, type a name and press kbd:[Return].  Press kbd:[Esc]
  to keep the old one.
* kbd:[Control]-click its row and choose *Rename…*.
* Select the object and type in *Name* on the Object panel's root row, or choose
  menu:Object[Name…] (xref:names-notes.adoc[Names and notes]).

Deleting the whole name gives the object back its default label.  Names travel with the objects
you export: SVG files carry them as element ids (xref:export-vector.adoc[Exporting vector
artwork]), and importing an SVG file names its objects after its elements.

=== Hiding and locking single objects

The eye and the padlock on an object row act on that object alone.

* Click the eye to hide the object on this Mac, as menu:View[Hide Selection] does; click it again
  to show it.  Hiding an object is a view of your own: it is not hidden for anyone else, and it
  still prints and exports.  menu:View[Show All] shows every hidden object.  To hide something for
  everyone, put it on a layer and hide the layer.
* Click the padlock to lock or unlock the object (xref:arranging.adoc[Arranging objects]).  A lock
  is shared, like a layer's.

The row's context menu has the same commands, as *Hide*/*Show* and *Lock*/*Unlock*, and *Select*.

=== Coloring objects from the panel

You can color an object by dropping a color on its row, which is handy when the object is small,
covered by others or out of view.

To color an object from the Layers panel:

. Drag a swatch from the Swatches panel, or a color from the Color Mixer, the Tints panel or a
  color well, over the object's row.
. Release the mouse.  The object's fill takes the color.  Hold kbd:[Cmd] as you release to color
  its stroke instead, as when dropping a color on the canvas (kbd:[Shift] keeps it the fill).

Dropping on a group's row colors every object in the group.  Layer rows, locked objects and
objects on hidden or locked layers do not take colors.  The color is one change that undoes in one
step; a swatch dragged from another document is added to this document's swatches first.

=== Reordering and regrouping objects

Dragging object rows changes how objects stack, which layer they are on and which group they are
in, without changing where they are on the page.

To move objects in the stacking order, onto another layer, or into or out of a group:

. Select the rows to move (or start with one).
. Drag them.  A line shows where they will land: between two rows, they go there; onto a layer
  or a group row, they go to its top; onto any other object row, beside it.
. Release the mouse.  The objects keep their order among themselves, and everything moves as one
  change that undoes in one step.

Some rows stay where they are: a clip path stays at the bottom of its clipping group, and the key
objects of a blend and the shapes inside an extrusion, envelope, perspective object or chart move
only with the object that holds them.  Locked objects, and objects on a locked layer, do not move,
and nothing can be dropped onto a locked layer or into a locked group.  Dragging objects onto the
Guides layer turns them into guides; dragging guides onto another layer turns them back.  Rows
cannot be dragged while the search field is filled in.

== Creating layers

You can set up all of your layers before drawing or add them one at a time as an illustration
grows.  A new layer becomes the active layer immediately, so anything you draw or import next
lands on it.

To add a layer:

. Show the Layers panel (menu:Window[Layers]).
. From the panel's options menu choose *New*.
. Double-click the new layer's name and type a name of your own.

To duplicate a layer together with the objects on it:

. Deselect everything (menu:Edit[Select > None], or press kbd:[Tab]) so the selection is not
  moved onto the new layer by accident (see the *Clicking a layer name moves selected objects*
  preference below).
. Click the layer's name in the Layers panel.
. From the options menu choose *Duplicate*.

To rename a layer:

. Double-click the layer name in the Layers panel.
. Type the new name and press kbd:[Return].  Press kbd:[Esc] to keep the old name.

The Guides layer cannot be renamed.

== Selecting layers and the objects on them

Clicking a layer name makes it the *active layer*, marked with a pen icon.  The next object you
draw, paste or import goes onto it.  Selecting an object on the canvas highlights the name of
its layer in the panel, so the panel doubles as a "which layer is this on?" readout.

To make a layer active:

. Deselect everything (menu:Edit[Select > None] or kbd:[Tab]) unless you intend to move the
  selection to that layer.
. Click the layer name.

To select every object on one layer:

* kbd:[Option]-click the layer name.

To select several layers (for merging or removing):

* kbd:[Cmd]-click layer names to add or remove individual layers.
* kbd:[Shift]-click to select a contiguous range.

By default you can select objects on any visible, unlocked layer.  If you prefer to work on
one layer at a time, turn on the *Edit current layer only* preference in the *Object* category
of Preferences: the canvas then selects only objects on the active layer, and objects on other
layers behave as if locked (xref:preferences.adoc[Setting preferences]).

== Moving objects between layers

An object's layer decides which other objects it can overlap: a layer's objects always draw
above everything on the layers below it, whatever their individual front-to-back order
(xref:arranging.adoc[Arranging objects]).  You can move objects between layers with the Layers
panel, with menu commands, or by cutting and pasting.

To move the selected objects to a layer with the Layers panel:

. Select the objects.  Their layers' names are highlighted in the panel.
. Click the name of the destination layer.  The objects move there and go to the front of that
  layer, keeping their order relative to each other.

This works because the *Clicking a layer name moves selected objects* preference (in the
*Panels* category of Preferences) is on by default.  Turn it off if you find yourself moving
things by accident; you can still move objects with the commands below.

To move objects to a layer with a command:

. Deselect everything and click the destination layer in the Layers panel to make it active.
. Select the objects on the canvas.  They may come from several layers.
. Do one of the following:
* From the Layers panel options menu choose *Move Objects to Current Layer*.
* kbd:[Control]-click the destination layer's row and choose *Move Selection to This Layer*.

To move objects by cutting and pasting:

. Select the objects and choose menu:Edit[Cut] (kbd:[Cmd+X]).
. Make the destination layer active and choose menu:Edit[Paste] (kbd:[Cmd+V]).
  With *Remember layer info* turned off (the default), pasted objects land on the active layer.

Grouping objects that live on different layers pulls the whole group onto the active layer,
as does joining or clipping them (xref:grouping.adoc[Grouping objects]).  With *Remember layer
info* turned on, ungrouping, splitting or releasing a clipping path returns each object to the
layer it came from.

=== Remembering layer information

The *Remember layer info* preference (in the *General* category) makes objects carry the name
of their layer with them:

* Ungrouping, splitting a join or releasing a clipping path puts each object back on the layer
  it was on before.
* Pasting into another document puts each object on the layer of the same name there.  If the
  destination has no layer with that name, {product} creates one.

To copy objects between documents and keep their layers:

. Turn on *Remember layer info* in Preferences and click btn:[OK].
. In the source document select the objects and choose menu:Edit[Copy] or menu:Edit[Cut].
. Switch to the destination document and choose menu:Edit[Paste].

== Reordering layers

Dragging a layer name up or down the list changes where its objects draw: above everything on
the layers now below it, beneath everything on the layers above.

To move a layer in front of or behind another layer:

. Deselect everything (kbd:[Tab]) so that clicking a layer does not move objects onto it.
. Drag the layer name to its new position.  A horizontal insertion line shows where it will
  land.

=== Foreground and background layers

Layers below the separator line are *background layers*: they never print or export, and their
objects are drawn dimmed on screen so a scanned sketch or a reference image does not compete
with the artwork.  The Background layer starts there; any layer can join it.

To make a layer non-printing, do one of the following:

* Drag the layer below the separator line.
* Drag the separator line above the layer.
* Hide the layer.  (Unlike the first two, a hidden layer still prints when *Include invisible
  layers* is on in the output options.)

Dragging a background layer back above the separator makes it a printing layer again and draws
its objects at full strength.

== Merging layers

When an illustration is finished, merging layers tidies the document.  Objects on merged layers
keep their front-to-back order: everything that was on a higher layer stays in front of
everything that was on a lower one.  The Guides layer never takes part in a merge.

To merge selected layers:

. In the Layers panel select the layers: kbd:[Cmd]-click to add layers one by one, or
  kbd:[Shift]-click to select a range.
. From the options menu choose *Merge Selected Layers*.  The layers merge onto the lowest
  selected layer, which keeps its name and settings.

To merge every foreground layer:

* From the options menu choose *Merge Foreground Layers*.  Every layer above the separator
  except Guides merges onto the lowest of them.

== Removing layers

To remove a layer:

. Select the layer (or several, with kbd:[Cmd]-click or kbd:[Shift]-click).
. From the options menu choose *Remove*, or kbd:[Control]-click the row and choose *Remove*.
. If a layer is not empty, a sheet warns that its objects will be removed too.  Click
  btn:[Remove] to proceed.

Removing a layer is undoable, and a removed layer can also be brought back from
xref:history.adoc[History].  The Guides layer cannot be removed, and a document always keeps at
least one printing layer.

== Showing and hiding layers

Hiding a layer hides its objects without removing them.  If you hide the active layer, objects
you draw next are invisible until you show the layer again, so {product} shows a warning strip
at the top of the canvas while the active layer is hidden.

To show or hide layers, do one of the following in the Layers panel:

* Click the check mark column beside a layer.  A check mark means visible.
* Drag up or down the check mark column to show or hide a run of layers at once.
* kbd:[Option]-click the check mark column to show or hide every layer.
* Choose *All On* or *All Off* from the options menu.

== Preview and Keyline per layer

Each layer can draw as it will print (Preview) or as outlines (Keyline).  The circle to the
left of the name is filled for Preview and hollow for Keyline.  The setting affects the screen
only.

To switch a layer between Preview and Keyline, do one of the following:

* Click the circle beside the layer.
* Drag through the circle column to switch a run of layers.
* kbd:[Option]-click any circle to switch every layer.

== Locking and unlocking layers

Locking protects a layer's objects from accidental edits while keeping them visible.  A closed
padlock means locked.  Objects on a locked layer cannot be selected with the mouse, moved,
edited, or made the target of a paste, and the layer cannot be made active.

To lock or unlock layers, do one of the following:

* Click the padlock beside a layer.
* Drag through the padlock column to lock or unlock a run of layers.
* kbd:[Option]-click any padlock to lock or unlock every layer.

== The Guides layer and guide paths

The Guides layer holds ruler guides, guides typed into the Guides editor, and any path you turn
into a guide (xref:grid-guides.adoc[Using the grid and guides]).  You can hide, lock, move and
recolor the Guides layer, but not rename, merge or remove it.

To show or hide guides:

* Click the check mark column beside the Guides layer.

To change the guide color:

. Open Preferences (kbd:[Cmd+,]) and choose the *Colors* category.
. Click the *Guide color* well and pick a color.

To draw guides in black instead of the guide color:

* Click the circle beside the Guides layer (Keyline draws guides black; Preview draws them in
  the guide color).

To put guides in front of the artwork:

* Drag the Guides layer to the top of the list.  Guides on a lower layer draw beneath the
  objects above them.

To turn a path into a guide:

. Select the path.
. Click the Guides layer in the Layers panel.  The path moves there, takes on the guide color,
  and behaves as a guide for snapping.

To turn a guide path back into an ordinary path:

. Double-click the guide path.
. In the Guides sheet click btn:[Release], then btn:[OK].  The path returns to the layer it came
  from.

== Layer highlight colors

Giving layers different highlight colors tells you at a glance which layer a selected object
belongs to: its selection outline, points and transform handles draw in the layer's color.
The objects' own fills and strokes are untouched.

To change a layer's highlight color, do one of the following:

* Drag a color from the color well in the Swatches panel or the Color Mixer onto the swatch
  beside the layer name (xref:swatches.adoc[Using the Swatches panel]).
* Drag the swatch of another layer onto it.
* Drag a stroke or fill color swatch from the Object panel's Properties list onto it.
* With the Eyedropper tool, drag a color from an object on the canvas onto it.
* Double-click the swatch to open the system color panel.

By default only selection handles and points use the highlight color; path segments of a
selected object draw in the color too when *Highlight selected paths* is turned on in the
*General* category of Preferences.

== Working with others

Layers are shared: everyone with the document open sees the same list, in the same order, with
the same visibility, lock and print settings.  When a collaborator adds, renames, reorders,
hides or locks a layer, the Layers panel updates within a moment, and the change carries their
name in xref:history.adoc[History].

* *Two people rename the same layer.*  The later rename wins for everyone.  If yours lost, the
  next sync review lists the layer with both names so you can put yours back.
* *Someone removes a layer while you are drawing on it.*  Your new objects are not lost.  They
  appear on the document's default layer (the lowest printing layer) with a note in the sync
  review offering to restore the removed layer, which puts them back where you drew them.
* *Someone merges layers while you are editing on one of them.*  Objects you added to a merged
  layer follow it onto the layer it merged into.
* *Locking is a courtesy, not a padlock on other people.*  When you lock a layer, everyone's
  tools stop selecting its objects.  A collaborator who already had one of those objects
  selected, or who was in the middle of dragging it, can finish that edit; the lock only stops
  new edits.  If you need exclusive control of part of a document, work on a
  xref:branches.adoc[branch].
* *Hiding a layer hides it for everyone.*  Use it the way you would on a shared drawing board:
  say so, or hide only layers you own.  A per-person "hide for me" view is planned.
* *Two people name the same object.*  The later name wins for everyone, as with layer names.
* *Two people drag the same object to different places.*  The later drag wins; both people see the
  object in one place, and the review sheet lists *move vs move*.  Dragging different objects at
  the same time keeps both moves.
* *Someone deletes a group while you drag an object into it.*  Your object goes into the group
  and so goes with it; undoing the delete, or restoring the group from
  xref:history.adoc[History], brings both back.
* *Someone moves an object while you drag it into a group.*  As with ungrouping a moved member,
  the later of the two places wins; if theirs does, the object can appear offset by the group's
  transform, and the review sheet lists it as a *Position* conflict.
* *Hiding an object from its row is yours alone*; locking it is everyone's.
* *Offline.*  Everything on this page works offline.  When you reconnect, layer changes merge
  like any other: both people's new layers appear, reorders combine, and the review sheet lists
  only the places where you and a collaborator touched the same layer or the same object
  (xref:collaboration.adoc[Working together]).

== Specification

=== Data model

Layers are children of the well-known `layers` node (xref:crdt-model.adoc[CRDT model]).  Their
order among the `layers` children is the stacking order, bottom first; a layer's own children
are its objects, again bottom first.  The panel lists both in reverse.

[source,protobuf]
----
// proto/wiretuner/doc/v1/layer.proto (sketch)
syntax = "proto3";
package wiretuner.doc.v1;

// Roles a layer can play.  Exactly one Guides layer exists per document; the document
// template creates it.  Every other layer is ORDINARY (`LAYER_ROLE_UNSPECIFIED`).
enum LayerRole {
  LAYER_ROLE_UNSPECIFIED = 0;  // an ordinary layer (buf lint: the zero value is UNSPECIFIED)
  LAYER_ROLE_GUIDES = 1;     // ruler guides and guide paths; not renameable, mergeable or deletable
}

// Properties of a node of kind `layer`.  Name lives in CommonProps.name.
// The whole message is STRUCT (the default): each flag is an independent choice, so one person
// hiding a layer while another locks it keeps both.  Field blocks: 1 common, 2-19 LIB, 20-29 WEB
// (animation).
message LayerProps {
  CommonProps common = 1;
  // Fixed at creation; readers ignore later writes (the client never issues them).
  LayerRole role = 2;
  // Objects on the layer are drawn and selectable.  Shared.
  bool visible = 3;
  // Objects on the layer cannot be selected or edited from the canvas.  Advisory: it constrains
  // each client's own tools and is never enforced against remote ops (see Merge semantics).
  bool locked = 4;
  // True above the separator line.  False = background layer: never printed or exported,
  // drawn dimmed.  A property of the layer, not a position, so it moves with the layer
  // through any reorder.
  bool printing = 5;
  // Draw this layer as outlines regardless of the document view mode.  Screen only.
  bool keyline = 6;
  // Selection highlight color for objects on this layer.  ATOMIC (annotated: a message field
  // defaults to STRUCT).
  Color highlight = 7 [(wt.crdt.field).merge = MERGE_ATOMIC];
  // Set when this layer is deleted by a merge: the layer its objects were moved onto.  Readers
  // route objects that arrive on this layer afterwards to the target (see Merge semantics).
  NodeRef merged_into = 8 [(wt.crdt.field).on_dangling = REF_FALLBACK_UNSET];
}

// Extension to CommonProps (common.proto, owned by PROTO-003), on every object:
//   // Name of the layer the object was on before it was grouped, joined, clipped or turned
//   // into a guide, or the name of its layer in the document it was copied from.  Written
//   // only when the "Remember layer info" preference is on; read by ungroup, split, guide
//   // release and cross-document paste.  Empty = no memory.
//   string origin_layer = 14 [(buf.validate.field).string.max_len = 256];
----

Why a flag and not a separator node::
A separator that is itself a child of `layers` (a well-known node whose position marks the
boundary) is faithful to the panel, but under concurrent reordering it produces results nobody
asked for.  Priya drags the separator down two rows to make two layers print; at the same time
Tom drags a third layer, which was printing, to the bottom of the list, below where he saw the
separator.  Both moves apply; depending on the fractional positions generated, Tom's layer may
land above or below Priya's new separator position, so whether it prints is decided by a random
suffix.  With a `printing` flag the printing status is a register on the layer: Tom's drag
below the separator writes `printing = false` and Priya's separator drag writes `printing = true`
on the two layers she crossed; each layer ends up with the value of whichever person last
touched *that layer*, which the review sheet can show.  The separator is then a derived
position: the boundary between the printing and non-printing groups.

Ordering rule::
The panel orders layers by `(printing desc, position, node id)`: printing layers first, then
background layers, each group in tree order.  Rendering uses the same order, so a background
layer is always drawn beneath every printing layer even if a merge left it with a higher
position.  Moving a layer across the separator writes both a `MoveNode` (to keep the tree order
consistent with the display) and `SetFields(printing)`; dragging the separator writes only the
flags of the layers it crossed.  Nothing depends on the tree order agreeing with the flag; the
`MoveNode` is cosmetic so that later drags produce sensible neighbors.

Objects on the Guides layer::
An object whose parent is the Guides layer is a guide.  It renders in the guide color (or black
when the layer is Keyline), snaps as a guide, never prints, and is hit-tested only for the
double-click that opens the Guides sheet.  The DOC epic's xref:grid-guides.adoc[grid and guides]
page owns ruler guides, which are also nodes on this layer.

Objects in the panel::
The object tree adds no field (xref:decisions.adoc#D-092[D-092]).  It is the node tree read on
demand: a live layer's rows are `LayerOrder.objects(on:)` (its own live objects and those routed
to it from deleted layers) frontmost first; an object's rows are its live child objects, frontmost
first, for the kinds that hold objects (`group` -- a clip group's clip path is its bottom row --
`blend`, `extrude`, `envelope`, `perspective`, `chart`, `text`).  A symbol instance has no rows:
its artwork is the symbol's.  A group with no live members has no row.  The row's name is
`CommonProps.name`, else a default label derived from the kind (Clip Group, Clip Path, Compound
Path for a path of several contours, the symbol's name, the first 40 characters of a text block's
first line).  The padlock is `CommonProps.locked`; the eye is the local `hidden` set of
menu:View[Hide Selection] (xref:selecting.adoc[Selecting], "Data model"), view state that is never
sent.

Delete layer versus add objects to it::
*Remove* sets `deleted = true` on every object the deleting client can see on the layer, then on
the layer, all in one change labelled "Remove layer <name>".  Marking the objects individually
matters: it lets the review sheet's *Restore* bring back one object without the whole layer, and
it distinguishes the objects the deleter meant to remove from ones that arrive concurrently.
An object a collaborator created on, moved onto, or pasted into that layer at the same time is
*not* marked deleted; it becomes a live child of a deleted layer.  Read-time normalization: a
live object whose layer is deleted is presented as being on the layer's `merged_into` target if
that resolves to a live layer, otherwise on the *default layer*.  The review sheet lists the
object as "added to a layer that was removed" with *Restore layer* (writes `deleted = false` on
the layer only; its individually deleted objects stay deleted) and *Leave it* (writes a
`MoveNode` onto the default layer so the state matches what is displayed).  Nobody writes the
move automatically: every client would write it at once.

Default layer::
The live, printing, non-Guides layer with the smallest node id.  If no such layer exists (every
printing layer was deleted concurrently, or all were dragged below the separator), the
non-Guides layer with the smallest node id is treated as live and printing for reading.  The
client refuses locally to delete the last printing layer, so this arises only from concurrent
deletes.

Merge layers::
`Merge Selected Layers` is one change: for each source layer from lowest to highest, a
`MoveNode` per object onto the target with fresh positions above the target's existing
children (preserving relative order), then `SetFields(merged_into = target)` and `deleted =
true` on each source.  A concurrent edit to a moved object applies to it wherever it is.  A
concurrent new object on a source layer is routed to the target by the normalization above.
A concurrent move of a source layer above the separator is moot -- it is deleted.  Two people
merging overlapping selections onto different targets: every object ends up on one of the two
targets (LWW per object's move), both source layers are deleted, and the review sheet lists
the objects under *move vs move*; nothing is lost.

Duplicate layer::
One change: `CreateNode` for the layer (copying `LayerProps`, name suffixed " copy") plus a deep
copy of every visible object.  Concurrent edits to the originals do not reach the copies.

Delete layer versus edit objects on it::
The edit applies to the deleted object.  The review sheet lists *edit vs delete* per object,
and its *Restore* restores the object; since its layer is deleted, the restored object is
displayed on `merged_into` or the default layer until *Restore layer* is also chosen.  The
sheet groups these rows under the layer with a single *Restore layer* button.

Concurrent lock and edit::
`locked` is advisory.  Each client checks it before its own tools select, drag, or paste onto
the layer.  A remote change to an object on a layer that is locked locally applies unchanged;
there is no rejection path and the server does not know what a lock is.  The UX consequence,
stated in the guide: a lock stops new edits by everyone whose client has received it, but an
edit already in progress (a drag, or a text edit in an open block) finishes.  The Layers panel
shows who locked a layer (from History) in the row's tooltip.

Guides layer invariants::
Clients never rename, merge, delete or write `role` on the Guides layer.  Read-time
normalization guards the tree anyway: if the Guides layer node is deleted it is treated as
live; if more than one layer carries `LAYER_ROLE_GUIDES` (possible only through a bug or a
malicious client), the one with the smallest node id is the Guides layer and the rest read as
ORDINARY (`LAYER_ROLE_UNSPECIFIED`).

Remember layer info::
`origin_layer` is written by group, join, clip and path-to-guide commands when the preference is
on, and by copy (into the pasteboard payload, not the document) so that paste into another
document can match by name.  A paste that creates a missing layer creates it above the active
layer in the same change as the pasted objects.  Two people pasting into the same document
with the same missing layer name at once create two layers of that name; the review sheet
lists nothing (no overlap) and the user sees two layers, which merge cleanly with *Merge
Selected Layers*.

What the review sheet shows::
Layer rows appear in the conflict list under the layer's name with the kinds above.  A layer
that was deleted on one side and had objects added on the other is a single row with a count
("3 objects added to removed layer Sketch").  Rows for objects moved between layers show the
source and destination layer names in the *Position* line.

=== Offline behavior

Every command on this page works offline.  Coalescing (xref:offline.adoc[Offline]) collapses
repeated toggles of one flag into the last value and repeated reorders of one layer into the
last move.  The object tree reads the local state only, so it lists, names, locks and reorders objects
offline like everything else; repeated drags of one object coalesce into its last move.  A layer created and removed offline disappears from the outbox entirely.
