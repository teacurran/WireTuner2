Extensions are {product}'s specialized commands and tools -- path operations, color
utilities, distortion tools, chart pictographs, animation helpers.  They are all built in,
organized under the *Extensions* menu and on two toolbars, and can be switched off
individually if you never use them.

== Using extensions

To use an extension, do one of the following:

* Choose it from the menu:Extensions[] menu.  Extensions with related jobs are grouped in
  submenus.
* Choose menu:Window[Toolbars > Extension Tools] and click a tool.
* Choose menu:Window[Toolbars > Extension Operations] and click an operation.

Operations act on the selection and are disabled when nothing suitable is selected.  Tools
stay active until you choose another tool, like any tool in the Tools panel; each tool
extension also lives in a Tools panel flyout (xref:toolbars.adoc[Toolbars]).

To repeat the last extension::
Choose menu:Extensions[Repeat <name>] or press kbd:[Cmd+Shift+=].  It applies the last
operation you used, with the same settings, to the current selection.  Tools are not
repeated.

To double-click a tool extension for its options::
Double-click it in the Extension Tools toolbar or the Tools panel, as for any tool.

== Managing extensions

To turn extensions off or on::
. Choose menu:Extensions[Other > Manage Extensions…].
. Uncheck an extension to remove it from the menu and the toolbars; check it to bring it
  back.  Categories can be toggled as a whole.
. Click btn:[Done].  Changes apply at once; no restart.

Turning an extension off hides it; artwork made with it is unaffected, and a document that
uses a hidden extension's tool (a chart, a connector) still opens and edits normally.  The
list is per Mac.

There is nothing to install: everything listed here ships with the application, and
{product} does not load third-party plug-ins in this version.

== Working with others

Extensions change the document the same way any command does, so their results reach
collaborators as you apply them: a Union someone performs replaces the source paths in your
view too; a chart they build appears as they build it.  Which extensions you have turned on
is your own setting and does not affect what you see of other people's work.  Each
operation's page describes the case of two people applying it to one object at the same
time; the general rule is that both operations happen and the later one's result is what
remains.

== Specification

=== Data model

None.  The enabled/disabled list is local (`wt.extensions.disabled`, a string set in
`NSUserDefaults`).  What each extension writes into the document is specified on its page.

=== Merge semantics

None on this page.  An operation extension is an ordinary `WTModel` command producing one
change (for example Union: create the result node, set `deleted` on the sources when *Path
operations consume original paths* is on); concurrency is covered on the operation's page.

=== Offline behavior

Everything works offline.

=== Server

Nothing beyond storing and relaying changes.

=== Client

* `WTApp/Extensions`.  `ExtensionRegistry` holds `ExtensionDescriptor { id, title, category,
  kind: .operation(commandId) | .tool(toolId), toolbar: Set<.tools|.operations>, helpSlug }`.
  The menu, both toolbars, the Manage Extensions sheet and Repeat are generated from it;
  feature epics register their operations and tools here in addition to the command and tool
  registries.
* Repeat records the last executed operation's command id and its parameters (the sheet
  values) in `ExtensionRepeatState`; the menu title updates via `validateMenuItem`.
* Manage Extensions is a SwiftUI outline of categories with checkboxes, writing the disabled
  set; menus and toolbars observe it.
* Disabled extensions remain registered so documents referencing them render and edit; only
  the UI entry points hide.

NOTE: Deviations recorded by BASIC-031 and BASIC-032.  Operation commands are
`extension.<id>`, Repeat is `extension.repeat` and Manage Extensions… `extension.manage` (a plain
command, so it cannot be turned off); tool extensions are the tool registry's `tool.<id>` commands.
The tool extensions are grouped for Manage Extensions under the category their operation shares
(Distort: Mirror, Roughen, Bend, Fisheye Lens, Smudge, Shadow, 3D Rotation; Chart: Chart) and under a
*Tools* category for the rest, which has no submenu.  A turned-off operation keeps its registry entry
and its place but loses its menu item (the command palette lists it disabled, "Turned off in Manage
Extensions"); a turned-off tool extension leaves the Extension Tools toolbar but keeps its Tools
panel flyout slot.  An operation's settings are an `ExtensionParameters` string map: `run(nil)` asks
(its sheet) and returns what it captured, Repeat passes the captured map back (an empty one when
nothing was captured); choosing any tool, from the Tools panel, a shortcut or a toolbar, disables
Repeat.  Manage Extensions is a sheet on the front document window, or a window of its own when none
is open.  Where the Extensions menu sits in the menu bar is `MenuTreeBuilder.standardMenuOrder`'s
business.

NOTE: As built by the control reachability audit (rch; `WTApp/Menus/ReachabilityFeatures.swift`).
*Reverse Direction* runs menu:Modify[Alter Path > Reverse Direction] (paths and connectors, one change)
and *File Info…* runs menu:File[Document Info…].  *Remove Overlap* and *Trap…* are still stubs
("… is coming soon"): no model command removes a path's self-overlap in place (proposed DRAW-060), and no
page specifies trapping (proposed PRINT-060).  `ControlReachabilityTests` fails when any other
extension, menu item or toolbar item is a stub or placeholder.
