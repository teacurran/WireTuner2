Preferences shape how {product} behaves for you: how close you must click to select, whether
new text blocks grow as you type, which colors guides use, how much you want to be asked when
your offline work meets someone else's.  Most preferences follow you from Mac to Mac through
your account; a few describe the machine you are sitting at and stay there.  This page lists
every preference by category.

== The Preferences window

To open Preferences::
Choose menu:WireTuner[Preferences…] or press kbd:[Cmd+,].  The window has a category list
on the left and the settings for the chosen category on the right.  Changes apply as you make
them; there is no OK button.

To restore every preference to its default::
Click btn:[Restore Defaults] at the bottom of the window and confirm.  This resets every
category, including your panel layout; keyboard shortcut sets are not touched.

To restore one category::
Hold kbd:[Option]; the button becomes btn:[Restore This Category].

Synced and local preferences::
Categories marked *synced* below are stored with your account and applied on every Mac you
sign in on; the newest change from any Mac wins.  Categories marked *local* describe this
Mac.  Turn syncing off with *Sync preferences with my account* in the *Sync and
collaboration* category; each Mac then keeps its own copy.

== Working with others

Preferences are about you, not the document.  Two people with different *Pick distance* or
*Snap distance* values work on the same drawing without noticing.  The only preferences with a
visible effect on others are the presence ones: turning off *Show my cursor and selection to
others* makes you appear in the collaborator list without a cursor on anyone's canvas.

Because synced preferences follow your account, a change you make on your laptop reaches your
desktop the next time it is online.  If you change the same preference on two Macs while one
is offline, the later change wins when both have synced; nothing asks.

== Specification

=== Data model

Preferences are not document data.  Synced categories are one `Preferences` message in
`account.v1` (PROTO-009); local categories live in `NSUserDefaults` under the `wt.` prefix.
The message is versioned by field addition only, and every field is `optional` so "unset"
means "default", which lets defaults change in later versions without rewriting stored
preferences.

[source,protobuf]
----
// proto/wiretuner/account/v1/preferences.proto (sketch; account.v1 has no wt.crdt options --
// it is not a CRDT.  Merge is per field, newest `updated_at_ms` wins, resolved by the server.)
message Preferences {
  // One entry per synced preference; the key is the preference id below.  Storing a map
  // rather than typed fields keeps the schema stable while feature epics add preferences.
  map<string, PreferenceValue> values = 1;
}

message PreferenceValue {
  oneof value {
    bool bool_value = 1;
    int64 int_value = 2;
    double double_value = 3;
    string string_value = 4;
    Color color_value = 5;        // doc.v1 Color, for guide and grid colors
    StringList list_value = 6;    // default line weights, DXF options, ...
  }
  int64 updated_at_ms = 10;       // client wall time; ties broken by the server's receipt order
  string device = 11;             // wt-device that wrote it (for the account's device list UI)
}

message StringList { repeated string items = 1; }
----

Preference ids are dotted, lower-case, category first: `general.pick_distance`,
`general.smart_guides`, `general.option_measurements`, `general.trackpad_rotate`,
`object.option_drag_copies`, `text.smart_quotes_style`, `document.new_template`,
`import.embed_images`, `export.eps_tiff_preview`, `spelling.ignore_uppercase`,
`colors.guide_color`, `sync.undo_levels`, `sync.auto_merge_below`, `sync.ask_overlap_count`,
`sync.ask_overlap_share`, `sync.always_ask`, `sync.suggest_review_after_hours`,
`sync.keep_both_offset`, `sync.share_presence`, `sync.show_cursors`, `sync.show_selections`.
Local ids use the same names in `NSUserDefaults` (`wt.panels.label_style`,
`wt.redraw.preview_drag`, `wt.sounds.snap_point`, `wt.sync.enabled`,
`wt.sync.snapshot_interval_minutes`, `wt.object.external_editors`, `wt.import.paste_formats`,
`wt.export.copy_formats`, `wt.colors.color_management`, `wt.colors.smart_guide_color`,
`wt.document.remember_window`).

Team floors for the review thresholds arrive in `Welcome` as part of the document's team
policy (COLLAB epic) and are applied as `max(user, team)` for counts and hours, `min` for
`auto_merge_below`.

=== Merge semantics

Not a CRDT.  `AccountService.SetPreferences` sends only the entries the client changed, each
with `updated_at_ms`; the server keeps, per key, the entry with the greater `updated_at_ms`
(receipt order on ties) and returns the full map.  A client applies the returned map
wholesale.  Clock skew between two of one user's Macs can make an older edit win; this is
accepted -- preferences are cheap to re-set and the alternative (vector clocks per
preference) is not worth it.  Document data is never affected by a preference change.

=== Offline behavior

Preferences read and write locally at once; changed synced entries queue in a small
`preferences_outbox` table in the app-level store (not a document store) and are sent on
the next `AccountService` call or within 30 s of connectivity.  A fresh sign-in on a new Mac
fetches the map before the first document opens; if that fetch fails, defaults apply and the
fetch retries.

=== Server

`AccountService.GetPreferences` / `SetPreferences` (PROTO-009) with the per-key
newest-wins rule above, stored as one JSONB column per account (`account.preferences`),
size-limited to 64 KiB.  Team policy floors are a `team` table column read by the session's
`Welcome`.

=== Client

* `WTApp/Preferences`.  `PreferenceStore` is an `@Observable` actor-backed facade over
  `NSUserDefaults` (local) and the synced map, exposing typed accessors generated from a
  `PreferenceCatalog` (id, category, scope, type, default, range, title, help slug).  Feature
  code reads `prefs.general.pickDistance`; the catalog is the single place a preference is
  declared, and this page's tables are generated from it in the docs build (`docs` track
  follow-up).
* The window is `NSWindow` + `NSSplitViewController` (sidebar `NSOutlineView` of categories,
  SwiftUI form per category via `NSHostingController`).  Fields commit on change; numeric
  fields validate against the catalog range and revert with a beep.
* `Restore Defaults` clears every catalog id from both stores and pushes a `SetPreferences`
  with explicit default values so other Macs reset too; kbd:[Option] scopes it to the
  visible category.
* Sync thresholds are read by `WTSync` (SYNC-006) at reconcile time; `Keep both offset` by
  the review sheet (SYNC-007); presence flags by SYNC-009; undo levels by APP-011; snapshot
  interval by SYNC-001.  Changing a value takes effect at the next use, without restart.
* Deviation recorded by APP-010.  `PreferenceStore` is a `@MainActor @Observable`
  class, not an actor: every read is synchronous on the main actor, and observers get an
  `AsyncStream` of changes.  Every preference, synced or local, is stored in `UserDefaults`
  (suite `com.villagecompute.wiretuner`, which is the app's own domain) under `wt.<id>`, so
  synced values are available offline and at launch; synced keys are also handed to a
  `SyncedPreferenceBackend` (a local stub until BASIC-023), and a remote map is applied
  wholesale to synced keys while *Sync preferences with my account* is on.  Keys are typed
  constants, `PreferenceCatalog.General.pickDistance`, read as `store[key]`.  The page's 123
  rows map to 128 keys: *Smart quotes* (on/off and style), *Font substitutions* (the list and
  the default substitute), *Search for missing links* (on/off and a local folder) and
  *Monitor, composite and separations profiles* (three local keys) hold more than one value.
  The window's sidebar is a SwiftUI `List` in the `NSSplitViewController`'s sidebar item
  rather than an `NSOutlineView`; forms are generated from the catalog (toggle, number field
  with stepper and unit, pop-up, colour well, text, space-separated list, and a chooser whose
  btn:[Choose…] is disabled until BASIC-022).  The menu item keeps the macOS title
  menu:WireTuner[Settings…].
* Sounds: `NSSound(named:)` from the system alert set, played through `ToolManager`'s snap
  callback, gated by `NSWorkspace` UI sound setting.
* *Smart guides*, *Show measurements while holding Option* and *Smart guide color* are read
  by OBJ-039 (xref:moving.adoc#smart-guides[Smart guides]); menu:View[Smart Guides] writes
  `general.smart_guides` through the store so the menu check mark and the preference never
  disagree.  *Rotate canvas with trackpad* is read by BASIC-034
  (xref:document-view.adoc[Setting the document view]).
