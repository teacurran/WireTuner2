{product} lets you make the application yours: change any keyboard shortcut or switch to the
shortcuts of another application, put the buttons you use on any toolbar, and save the
arrangement of panels you like so you can come back to it.  Shortcut sets follow your account
between Macs; toolbars and panel layouts stay with the Mac.

== Keyboard shortcuts

Every menu command, tool and many commands that have no menu (the Tools/Commands category)
can have shortcuts.  Shortcuts are grouped in *sets*; you can switch sets, copy one and edit
the copy, and share a set with someone else.

=== Shortcut sets

To choose a set::
. Choose menu:Edit[Keyboard Shortcuts…].
. Choose a set from the *Shortcut set* pop-up at the top of the window.

The built-in sets are:

[cols="1,3"]
|===
|Set |What it is

|{product} (default) |{product}'s own Mac shortcuts.  Every shortcut in this guide is from this set.
|Illustrator |Adobe Illustrator's Mac shortcuts where a command corresponds; {product}'s shortcuts for the rest.
|QuarkXPress |Likewise.
|Photoshop |Likewise, for the commands the two share (zoom, hand, selection, transforms).
|===

Built-in sets cannot be edited.  Assigning a shortcut while a built-in set is chosen offers
to make a copy first.

To make your own set::
. Click btn:[+] beside the pop-up.
. Name the set.  It starts as a copy of the current set.

To rename, duplicate or delete a set::
Use the btn:[⋯] menu beside the pop-up.  Deleting the active set switches to the {product}
set.

Your sets sync with your account, so they are on every Mac you sign in on.  To give a set to
someone else, choose *Export Set…* from the btn:[⋯] menu; they choose *Import Set…*.  The
file is a small text file you can also keep in version control.

=== Assigning a shortcut

To assign a shortcut::
. Choose menu:Edit[Keyboard Shortcuts…] and choose an editable set.
. In the *Commands* list, expand a category.  Categories mirror the menu bar; commands with
  no menu item are under *Tools/Commands*.  Or type in the search field to filter.
. Select the command.  Its description appears below the list; *Current shortcuts* lists what
  it already has.  A command can have several shortcuts; the first one shows in the menu.
. Click in the *Press new shortcut* field and press the keys.
. If the shortcut is already used, *Currently assigned to* names the other command.  With
  *Go to conflict on assign* checked, clicking btn:[Assign] selects that command in the list
  so you can give it something else; otherwise btn:[Assign] just takes the shortcut away from
  it.
. Click btn:[Assign].

Changes apply at once; there is no OK.  btn:[Revert] undoes every change made since the
window opened.

To remove a shortcut::
. Select the command.
. Select the shortcut under *Current shortcuts*.
. Click btn:[Remove].

Shortcuts reserved by macOS (kbd:[Cmd+Tab], kbd:[Cmd+Space], kbd:[Cmd+Q], kbd:[Cmd+H],
kbd:[Cmd+,] and the others listed in System Settings) cannot be assigned; the field shows why.
Single letters and digits without modifiers are allowed and are what tools use; they are
ignored while you type in a text block or a field.

NOTE: Extensions cannot be given shortcuts individually; *Repeat Extension*
(kbd:[Cmd+Shift+=]) can.  Extensions that are also tools (Roughen, Mirror and the rest) take
shortcuts as tools.

=== Finding a command without its shortcut

The command palette (kbd:[Cmd+/]) searches the same list of commands the Keyboard Shortcuts
window does and runs the one you pick, showing its shortcut beside it
(xref:workspace.adoc[The workspace]).  It is the quickest way to reach a command you have not
bound yet, and the results list is a good place to notice which shortcut you keep forgetting.
The palette's own shortcut can be changed like any other, under *Help* in the Commands list.

=== Printing or exporting a quick-reference card

To print a card of the current set::
. Choose menu:Edit[Keyboard Shortcuts…].
. Click btn:[Print…].  A preview sheet shows the card, grouped by menu, with the option to
  include commands that have no shortcut.
. Click btn:[Print] for the system print dialog, or btn:[Save as PDF] to write it to a file.

To export the set as text::
Choose *Export as Text…* from the btn:[⋯] menu.  The file is comma-separated -- command,
shortcut, description -- ready for a spreadsheet or word processor where you can reorder and
format your own card.

== Customizing toolbars

The Main toolbar is customized the macOS way; the other toolbars and the Tools panel share
one Customize Toolbars window.

To customize the Main toolbar::
Choose menu:View[Customize Toolbar…], then drag items between the sheet and the toolbar.
Drag the default set back in to reset it.

To add a button to another toolbar or the Tools panel::
. Choose menu:Window[Toolbars > Customize…].
. In the *Commands* list, expand a category, or search.  Selecting a command highlights its
  button on every toolbar that has it; clicking a button on a toolbar selects its command in
  the list.
. Drag the command's button from the window onto a toolbar.  The other buttons make room.

To remove a button::
Drag it off the toolbar while the Customize Toolbars window is open, or kbd:[Cmd]-drag it off
at any time.  Disabled buttons cannot be dragged.  Removing a button cannot be undone, but
you can drag it back from the Customize window, or choose menu:Window[Toolbars > Reset
Toolbars] to restore every toolbar's default set.

To move a button between toolbars::
kbd:[Cmd]-drag it to the other toolbar.

To put the same button on two toolbars::
kbd:[Cmd+Option]-drag it.

To move a toolbar::
Drag its handle (xref:toolbars.adoc[Toolbars]).

Toolbar contents are local to this Mac.

== Panel layouts

To save the current arrangement of panels::
Choose menu:Window[Panel Layout > Save Layout…] and name it.  The layout records which groups
exist, which panels are in them, where they dock or float, their sizes and which are
collapsed.

To switch layouts::
Choose a layout from menu:Window[Panel Layout].  The current arrangement is always kept as
*Current*, so switching away and back loses nothing.

To update a saved layout::
Arrange the panels, then choose menu:Window[Panel Layout > Save Layout…] and pick the
existing name.

To delete a layout::
Choose menu:Window[Panel Layout > Manage Layouts…].

To return to the factory arrangement::
Choose menu:Window[Panel Layout > Reset to Default].

Layouts are local to this Mac: they depend on your displays.

Scripts you install appear in the Shortcuts settings as their own *Scripts* group, so any script
can be given a key (xref:scripting.adoc[Scripting and automation]).

== Working with others

Nothing on this page touches the document.  Your shortcuts, toolbars and layouts are invisible
to collaborators, and theirs to you.  Shortcut sets travel between your own Macs through your
account; if you edit a set on two Macs while one is offline, the later edit wins when both
have synced.  A set you export and send to a colleague is a copy; changing yours afterward
does not change theirs.

== Specification

=== Data model

Shortcut sets are account data, stored beside preferences (xref:preferences.adoc[Preferences]).
Toolbars and layouts are local files.  The command palette's usage history is a local file
too (`~/Library/Application Support/WireTuner/palette-recents.json`: up to 500 entries of
`{query_prefix, item_id, count, last_used_ms}`), never synced and never document data.

[source,protobuf]
----
// proto/wiretuner/account/v1/preferences.proto (continued sketch)
message ShortcutSets {
  repeated ShortcutSet sets = 1 [(buf.validate.field).repeated.max_items = 32];
  string active_set_id = 2;            // built-in ids are "builtin.wiretuner" etc.
}

message ShortcutSet {
  string id = 1;                       // UUID for user sets
  string name = 2 [(buf.validate.field).string = {min_len: 1, max_len: 64}];
  string based_on = 3;                 // built-in id the set was copied from
  // Whole set replaced on write: a set is edited in one window on one Mac at a time;
  // field-level merging of key bindings would produce sets nobody composed.
  repeated Binding bindings = 4 [(buf.validate.field).repeated.max_items = 2000];
  int64 updated_at_ms = 5;
}

message Binding {
  string command_id = 1;               // registry id, e.g. "view.zoomIn", "tool.pen"
  repeated string keys = 2;            // canonical form "cmd+shift+k", "p", "6"; first is shown in menus
}
----

Export format is the same message as JSON (`.wtkeys`), with a header comment.  Built-in sets
are JSON resources in the app bundle, validated at build time against the command registry.

=== Merge semantics

Not document data.  `ShortcutSets` is one entry in the preferences map (`sync.shortcut_sets`)
and follows the newest-wins rule per set id: the client sends changed sets only, the server
keeps the newer `updated_at_ms` per set, deletions are tombstoned for 30 days so a Mac that
was offline does not resurrect a deleted set.  Toolbar contents and panel layouts never
merge.

=== Offline behavior

Everything on this page works offline; set changes queue with preferences.  Export and
Import are local files.

=== Server

Stores `ShortcutSets` inside the account preferences JSONB; the per-set newest-wins rule
runs server-side in `SetPreferences` (BASIC-023).

=== Client

* `WTApp/Shortcuts`.  APP-005's `CommandRegistry` is the source of the Commands list;
  `ShortcutResolver` maps the active set's bindings onto `NSMenuItem.keyEquivalent` and
  `keyEquivalentModifierMask`, and onto the tool shortcut table (BASIC-008).  Unmodified
  single keys are handled in `CanvasView.keyDown` when no field or text session has focus.
* Conflict detection is a dictionary from canonical key string to command ids; macOS-reserved
  keys are a fixed list plus whatever `NSEvent` reports as consumed by the system
  (`performKeyEquivalent` returning false is not enough -- the list is explicit).
* The window is an `NSWindow` with an `NSOutlineView` for commands (search via
  `NSSearchField` filtering the outline), a SwiftUI detail form, and a key-capture field that
  records the next `NSEvent` (`keyDown` with `charactersIgnoringModifiers` + modifier flags).
* Printing: an `NSView` laid out per menu with `NSPrintOperation`; *Save as PDF* uses the
  same view with `dataWithPDF(inside:)`.  Export as Text writes RFC 4180 CSV.
* Customize Toolbars: `ToolbarHost` (BASIC-011) enters edit mode while the window is open;
  drag sources are command ids; `NSToolbar` handles the Main toolbar natively.
* Panel layouts: files under `~/Library/Application Support/WireTuner/Layouts/<name>.json`
  (format in xref:panels.adoc[Using panels]); the menu is rebuilt from the directory.

`shortcut_sets_value` entries per set id (the greater `updated_at_ms`, the change on a tie), drops tombstones 30 days
after they were written (its own clock), and stamps the entry with the newer of the two; any other pair of values
stays newest-wins for the whole entry.  `PreferenceSync` runs the same merge on its outbox: a change queued while
another is queued joins it, a queued set the server already has at the same or a newer stamp is dropped on fetch
(`ShortcutSetSync.unsent`), and the queued sets lie over the server's in the delivered map.  `ShortcutSetStore`
hands `onSyncChange` the entry of every change made on this Mac -- the changed sets, a tombstone for a deleted one,

takes away are deleted) -- and `applySynced(_:)` applies a merged value (`ShortcutSetSync.apply`: a newer set replaces
or joins, a newer tombstone deletes, a set the value does not mention stays, the newer choice wins and falls back to

outbox merges them), every map the sync delivers hands its merged shortcut sets to `applySynced`, and `syncValue`
(every set) is queued at launch with sync on and whenever *Sync preferences with my account* is turned on.  Tests:
