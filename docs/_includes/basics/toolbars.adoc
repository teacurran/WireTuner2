Toolbars put commands and tools where the pointer already is.  {product} has seven: the Main
toolbar across the top of the document window, the Tools panel down its left edge, and five
smaller toolbars -- Text, Info, Envelope, Extension Tools and Extension Operations -- that you
show when you need them.  Any toolbar can float or dock; all of them can be customized
(xref:customizing.adoc[Customizing your environment]).  This page describes each toolbar and
lists every tool in the Tools panel with its shortcut and the page that documents it.

== Showing, hiding, docking

To show or hide one toolbar::
Choose its name from menu:Window[Toolbars].  A check mark marks the visible ones.

To show or hide the Tools panel::
Choose menu:Window[Tools].

To show or hide every visible toolbar at once::
Choose menu:View[Toolbars].  Choosing it again brings back the same set.

To dock or undock a toolbar::
Drag it by the textured handle at its left (or top) end.  A highlight shows where it will
land: the strip under the Main toolbar, the left or right edge, or the bottom above the status
bar.  Drop it on the pasteboard to make it a floating, resizable palette.  The Tools panel
docks vertically at a side edge or horizontally at the top or bottom.

To see what a button does::
Pause the pointer over it.  The tooltip shows the name and the shortcut.  Turn tooltips off in
the *Panels* preferences (xref:preferences.adoc[Preferences]).

== The Tools panel

The Tools panel holds the tools you draw, select, edit and color with.  It has four sections:
*Tools*, *View*, *Colors* and *Snap*.  A tool with a small triangle in its corner hides a
*flyout* of related tools.

To select a tool::
Click it, or press its shortcut key.  Shortcut letters work whenever the canvas has focus and
no text is being edited; when you are typing in a text block, use the Tools panel.

To select a tool from a flyout::
Press and hold on the tool that shows the triangle, then choose from the menu that appears.
The chosen tool takes that slot until you choose another.  Pressing a flyout tool's shortcut
selects it directly.  Pressing the *visible* tool's shortcut again cycles through the flyout.

To set a tool's options::
Double-click the tool.  Tools with options (Pointer, Subselect, Lasso, Polygon, Spiral, Arc,
Pencil, Variable Stroke Pen, Calligraphic Pen, Freeform, Knife, Eraser, Trace, Graphic Hose,
Chart, the path-effect tools and the transformation tools) open a small sheet; the page for
each tool lists its options.

To use the previous tool for one action::
Hold kbd:[Cmd] to get the Pointer while any drawing tool is active, kbd:[Space] to get the
Hand, kbd:[Cmd+Space] to get the Zoom tool and kbd:[Cmd+Option+Space] to zoom out.  Release
the key to return to the tool you were using.

== The Text toolbar

Font family, style and size; leading; alignment; and buttons for attach to path, flow inside
path, run around selection, convert to paths, the Text Editor and spelling.  Fully described
on xref:type-tools.adoc[Type tools].  Docks under the Main toolbar by default when shown.

== The Info toolbar

A read-only readout that follows the pointer and the current tool: pointer position, and while
dragging, the change in position, the angle, the center of rotation, the radius or the number
of sides -- whatever the tool can report.  It also names the kind of object under the pointer.
Units follow the document.  Shown with menu:Window[Toolbars > Info].

== The Envelope toolbar

Create, Show Map, Copy as Path, Release and Remove for envelopes, plus the envelope preset
pop-up (xref:perspective.adoc[Perspective and envelopes]).

== The Extension Tools and Extension Operations toolbars

Both toolbars are made of extensions (xref:extensions.adoc[Extensions]).  *Extension Tools* holds the tools listed above under Freeform, Effects and "Objects that link
and repeat" in one row.  *Extension Operations* holds one-click path operations: Union,
Divide, Intersect, Punch, Crop, Transparency, Expand Stroke, Inset Path, Add Points, Correct
Direction, Reverse Direction, Remove Overlap, Simplify, Blend, Emboss, Fractalize, Trap
(xref:combining-paths.adoc[Combining paths], xref:expand-stroke.adoc[Expand stroke],
xref:inset-path.adoc[Inset path], xref:path-effects.adoc[Path effects]).

== Working with others

Toolbars and tools are yours.  Which tool you hold, which toolbars you show and where they
sit never affects anyone else.  What the tools *do* -- draw, move, color -- writes into the
shared document and reaches collaborators as you work; each tool's page explains what happens
when two people use it on the same object at once.

Collaborators can see which tool you are using: the Presence page explains the cursor labels
(xref:presence.adoc[Presence]).  Nothing changes offline; every tool works, and your work
syncs later.

== Specification

=== Data model

None.  Toolbar contents and positions are application state in the layout file
(xref:panels.adoc[Using panels]); tool state is transient.  The stroke and fill wells read and
write the selection's appearance registers, specified on xref:applying-color.adoc[Applying
color].  The snap buttons write four booleans that are `local_only` view state
(`ViewState.snap_*`, xref:document-view.adoc[Setting the document view]).

=== Merge semantics

None on this page.

=== Offline behavior

Nothing needs the network.

=== Server

Nothing beyond storing and relaying changes.

=== Client

* `WTApp/Tools`.  `ToolRegistry` holds `ToolDescriptor { id, title, icon, shortcut:
  [KeyEquivalent], group: FlyoutGroup?, section: .tools|.view, options: (() ->
  NSViewController)?, helpSlug, make: () -> any Tool }`.  The `Tool` protocol is APP-003's.
  Every tool in the table above is registered at startup; until its epic delivers it, the
  registration points at `UnimplementedTool`, which shows a "coming soon" HUD on mouse down
  and never writes a change, so the panel is complete from day one and each epic replaces one
  `make` closure.
* Flyouts are `NSMenu`s shown after a 250 ms press-and-hold or on drag; the slot remembers the
  last chosen member per layout.  Shortcut cycling: pressing the visible tool's key advances
  to the next member of its group.
* Temporary tools (kbd:[Cmd], kbd:[Space], kbd:[Cmd+Space], kbd:[Cmd+Option+Space]) are
  APP-003's `ToolManager.pushTemporary`, restored on key-up even mid-drag.
* The Main toolbar is an `NSToolbar` with `allowsUserCustomization = true`; items are built
  from the command registry (APP-005) so the standard customization sheet lists every
  command.  The other toolbars are `ToolbarView`s: `NSStackView` rows of `NSButton`s in a
  `ToolbarHost` that supports dock strips (top, left, right, bottom) and floating `NSPanel`s,
  sharing the drag code with panels.
* Tool option sheets: `NSViewController`s hosting SwiftUI forms, presented as sheets on
  double-click; options persist in `NSUserDefaults` per tool id (they are preferences, not
  document data).
* The Info toolbar observes `ToolManager.infoPublisher` (a struct of optional readouts) and
  renders only the fields the current tool sets.
* Accessibility identifiers follow `tool.<id>` and `toolbar.<name>.<command>` (TEST-002).

NOTE: Deviations recorded by BASIC-008 and BASIC-009.  `ToolDescriptor` has `symbolName`,
`shortcuts: [KeyEquivalent]` (letter first; the first is the menu key, the rest are
`Command.alternateKeys` in the default set; an empty list is the decision "no shortcut"),
`group: FlyoutGroup?` and `options: (() -> NSViewController)?`.  `ToolCatalog` registers 42
tools: the 40 of the Tools section and Zoom and Hand; Keyline and Fast Mode are the View menu's
commands and the Colors and Snap controls are commands too (`ToolPanelCommands`: Swap
kbd:[Shift+X], None kbd:[/], Default kbd:[Shift+D], and the four snap toggles in the View menu),
which is how the table's 43 "tools and controls" are counted.  "Effects flyouts" is one flyout
(Extrude, Blend, Perspective); the tools under "Objects that link and repeat" have buttons of
their own.  Shortcut cycling: the key of a flyout's visible member, while that member is current,
advances to the next member, and so does the key of the flyout's first member while another
visible member is current; any other key selects its tool.  A flyout is a SwiftUI `Menu` with a
primary action (a click selects the visible member, press-and-hold opens the list, which also
offers the tool's options), not a 250 ms timer.  The Tools panel is a panel of the panel framework
(two columns in a side dock, one row when its host is wider than tall), so it docks left, right,
top and bottom and floats as a panel group until BASIC-011's `ToolbarHost`.  The wells show the
first selected object's fill and stroke; Swap, None and Default change the colours new objects get
and are disabled while something is selected, until the appearance commands land.  The snap
toggles are window view state saved with the window state (`SnapSettings`) until the local
store's `view` table.  Tools with options open a placeholder sheet; option persistence arrives with
each tool.  `UnimplementedTool` shows its "coming soon" HUD as a text layer over the canvas for
1.5 s and in the status bar.

NOTE: Deviations recorded by BASIC-011.  There is no separate `ToolbarHost`: each of the five
toolbars is a one-panel group of the panel framework (as the Tools panel is, BASIC-009), closed in
the factory layout and docked in the top strip when shown, so it docks at any edge and floats with
the panels' drag code; the group's tab strip is the handle, and the drop highlight is the
framework's (its 2 pt insertion line is not drawn yet).  Their panels are left out of the Window
menu's panel list (`PanelDescriptor.showsInWindowMenu`) and listed under menu:Window[Toolbars]
(`toolbar.show.<name>`): the five toolbars, a line, then *Customize…* (`toolbars.customize`) and
*Reset Toolbars* (`toolbars.reset`), grouped by `MenuPath.subsection`.  menu:View[Toolbars] (`view.toolbars`) hides and restores the five toolbars and the
Tools panel (not the Main `NSToolbar`); the set it hid is kept in
`Application Support/WireTuner/Toolbars.json` with the customized buttons.  A `ToolbarView` is an
`NSStackView` of `NSButton`s, a row when its host is wider than tall and a column otherwise, and
revalidates its buttons after every window update.  The Text toolbar's font family, style, size and
leading fields, its alignment buttons and the Envelope toolbar's buttons and preset pop-up are
disabled placeholder commands (`text.*`, `envelope.*`, no menu item) until the type and envelope
epics register them.  The Info toolbar reads `ToolManager.info` (`ToolInfo`: position, delta, angle,
centre, radius, sides, object kind), published through `onInfoChange`: the pointer position on
every pointer event (the canvas tracks `mouseMoved`), merged with the readouts of a tool conforming
to `ToolInfoPublishing`; until their epics land, the stub transformation tools report the drag's
angle about the press point, Polygon its default five sides and every other stub the drag's delta
(`ToolReadout`).  Readouts are in points until the document's units reach the toolbar.

NOTE: Deviations recorded by BASIC-010.  The Main toolbar is `MainToolbarController`'s
`NSToolbar` (identifier `com.villagecompute.wiretuner.main`, icon-only, unified compact), whose item
identifiers are `command.<id>`; every registered command is allowed, and NSToolbar's own autosave
keeps the customized set (shared by every window, restored at relaunch).  Save Version, Import,
Share, Lock and Unlock are placeholder commands (Lock and Unlock say "Nothing is selected" with no
selection); the panel buttons run the Window menu's panel commands; tooltips show the active set's
key.
