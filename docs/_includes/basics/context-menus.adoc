A context menu is the short menu that appears where you click, listing the commands that make
sense for what is under the pointer.  {fh} offered them only on Windows; {product} has them
everywhere on macOS -- on objects, on empty pasteboard, on pages, and inside panels.

== Opening a context menu

Do any of the following:

* Hold kbd:[Control] and click.
* Click with the right (secondary) mouse button.
* Tap with two fingers on a trackpad, or click the corner you have set as the secondary click
  in System Settings.

The menu is for the item under the pointer.  If that item is part of the current selection,
the commands apply to the whole selection; if it is not, clicking selects it first (as the
Pointer tool would) and the commands apply to it alone.  kbd:[Control]-clicking empty
pasteboard opens the pasteboard menu without changing the selection.

NOTE: {fh} for Windows had a preference to make the right mouse button zoom instead of
opening menus.  {product} has no such option -- use kbd:[Cmd+Space] or pinch to zoom
(xref:document-view.adoc[Setting the document view]).

Every command in a context menu is also somewhere in the menu bar, with the same shortcut,
so nothing is reachable only by context menu.

Common items, on every object:

Cut, Copy, Paste, Clear, Duplicate, Clone; Group, Ungroup; Lock / Unlock; Arrange ▸ (Bring to
Front, Bring Forward, Send Backward, Send to Back); Align ▸; Transform ▸ (Rotate…, Scale…,
Skew…, Reflect…, Move…); Hide Selection; Add to Library…; Name…; Note…; Link…; Select ▸ (All,
None, Invert Selection, Superselect, Subselect); Object Panel.

=== A multiple selection

The common items only, plus Combine ▸ (Union, Divide, Intersect, Punch, Crop, Transparency,
Blend, Join) and Align ▸.  Kind-specific items appear when every selected object is the same
kind.

=== Empty pasteboard or page

View ▸ (magnification levels from 6% to 25,600%, Fit to Page, Fit All), Paste, Paste Behind,
Select All, Show All, Page ▸ (Add Page, Duplicate Page, Remove Page, Page Setup… -- the last
three only when over a page), Rulers, Grid, Guides, Document Panel.

=== A guide

Lock Guide / Unlock Guide, Release Guide (to a path), Edit Guides…, Delete Guide
(xref:grid-guides.adoc[Grid and guides]).

=== A collaborator's cursor or selection outline

Follow <name>, Go to <name>'s Page, Hide <name>'s Cursor (xref:presence.adoc[Presence]).

== Text context menu

With the Text tool active and the pointer in a text block, the context menu is the text menu:
Cut, Copy, Paste, Font ▸, Size ▸, Style ▸, Leading ▸, Alignment ▸, Special Characters ▸,
Spelling ▸, Editor…, Convert Case ▸, Attach to Path, Run Around Selection…, Convert to Paths.
It applies to the selected characters, or to the whole block when nothing is selected.  {fh}
offered this menu on Windows only.

== Working with others

Context menus act on what you have selected; the result reaches your collaborators the same
way as the menu-bar command would.  If someone else is editing the object you kbd:[Control]-
click, the menu still opens -- there are no locks -- and their selection outline stays
visible beneath yours so you know you are both there.  The commands themselves are described
on each feature's page, along with what happens when two people apply them to one object at
once.

The *Follow* and *Go to page* items on a collaborator's cursor change only your view.

=== Data model

None.  Context menus are views over the command registry.

=== Merge semantics

None.  Every command's merge behavior is specified where the command is.

=== Offline behavior

Nothing here needs the network.  Items that require it (Share…, Follow when the collaborator
is no longer connected) are disabled with a tooltip explanation.

=== Server

Nothing beyond storing and relaying changes.

=== Client

* `WTApp/Menus`.  APP-005's command registry gains a `contexts: Set<MenuContext>` on each
  command (`.path`, `.text`, `.bitmap`, `.group`, `.blend`, `.clip`, `.connector`,
  `.symbolInstance`, `.chart`, `.envelope`, `.multiple`, `.pasteboard`, `.page`, `.guide`,
  `.presence`, `.swatch`, `.layer`, `.style`, `.symbol`, `.tint`, `.pageThumbnail`, `.tab`,
  `.panelTab`, `.textEditing`).  `ContextMenuBuilder.menu(for: HitTarget)` filters the
  registry by the target's contexts and the command's validation, keeping the menu-bar
  order and the same key equivalents so the menu shows shortcuts.
* Hit target resolution reuses REND-003: `canvas.hitTest(point)` returns the topmost object,
  a guide, a page, a presence marker, or nothing.  The selection change on click of an
  unselected object goes through the selection model (APP-006) before the menu opens.
* Panels present menus through `NSTableView`/`NSCollectionView` `menu(for:)` overrides that
  call the same builder with the panel's row model as the target.
* Text context menus are built while `TextEditingSession` is active and apply to the session's
  selection range.
* Every menu item carries the accessibility identifier `menu.<commandId>` (TEST-002).
