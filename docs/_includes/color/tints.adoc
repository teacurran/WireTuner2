A tint is a lighter version of a color: the same ink, printed at a percentage.  A 40% tint of
your brand blue is still your brand blue at the press -- one plate, screened -- which is why
tints, and not paler mixes, are how print work gets its lighter shades.  In {product} a tint
always belongs to a *base color*.  Change the base and every tint of it changes; remove the
base and its tints go with it.  The Tints panel makes, applies and names tints; show or hide it
with menu:Window[Tints].

== The panel

[cols="1,3"]
|===
|Element |Purpose

|Base color pop-up

|Preset bar
|Ten chips, 10% to 100%.  Click one to set the percentage.

|Slider and field

|btn:[Apply]
|Applies the tint to the selected objects, honouring the Swatches panel's Fill / Stroke /

== Making and applying a tint

To make a tint:

. Choose the base color: pick it from the pop-up, or drag a swatch from the Swatches panel
  onto the Tints panel's color well.  An unnamed color cannot be a base -- add it to the
  Swatches panel first.
. Set the percentage: click a preset chip, drag the slider, or type 1--100 and press
  kbd:[Return].

To apply the tint, do one of the following:

* Drag from the color well onto an object's fill or stroke (the kbd:[Shift] and kbd:[Cmd]
  rules from xref:applying-color.adoc[Applying color] apply).
* Drag from the color well onto the stroke or fill well in the Tools panel.
* Click btn:[Apply] with objects selected.

A tint applied this way is an *unnamed tint*: it still follows its base color, but it is not
in the Swatches panel.  menu:Extensions[Colors > Name All Colors] names unnamed tints along
with unnamed colors.

To add the tint to the Swatches panel:

* Click btn:[Add to Swatches], or
* Drag from the color well onto the btn:[Add] arrow or below the list in the Swatches panel.

The new swatch is listed under its base, indented, and named with the percentage first:
`40% Grape`.  Its name updates when the base is renamed (`40% Plum`) unless you rename the
tint yourself.  A named tint is spot if its base is spot and process if the base is process;
it has no kind of its own.

To change a named tint's percentage:

. kbd:[Option]-click the tint in the Swatches panel to load it into the Tints panel.
. Set the new percentage.
. Drag the color well back onto the tint's swatch.

Everything using the tint updates.  To give a tint a *different base*, drop a different base
swatch onto the tint's swatch while holding kbd:[Option]; dropping without kbd:[Option]
replaces the tint with a plain copy of the dropped color.

== Removing tints and bases

Removing a tint from the Swatches panel leaves objects that used it looking the same, as an
unnamed tint of the base.  Removing a base color removes all its named tints too; objects
that used any of them keep their colors as unnamed colors, and the Swatches panel's *Restore
Deleted Colors…* brings the base and its tints back together
(xref:swatches.adoc[Swatches]).

A tint mixes its base toward white in the base's own color space: CMYK inks toward 0, sRGB and
Display P3 toward (1, 1, 1), CIELAB toward L = 100, OKLab toward L = 1
(xref:spot-process.adoc[Spot and process colors]).

== Working with others

Tints follow their base for everyone: when a collaborator adjusts the brand blue, your 40%
tint of it changes on your screen too, because it is the same ink.  Two people setting the
same tint's percentage at once cannot both win; the later value stands.

If someone removes a base color at the very moment you are making a tint of it, your tint
survives: it is listed with a small warning badge ("base color removed") and keeps the color
it had.  Choose a new base for it by dropping a swatch on it with kbd:[Option], or restore the
base with *Restore Deleted Colors…*.

=== Data model

A named tint is a swatch node with `parent` set (xref:swatches.adoc[Swatches]); an unnamed
tint is `ColorRef.tint` (xref:applying-color.adoc[Applying color]).  The tint's name is
`CommonProps.name`; when it is empty the panel shows the derived name `<percent>% <base
name>`, which is how the name follows a base rename without any write.  *Add to Swatches*
leaves the name empty unless the user typed one.

Resolution of a tint swatch's color:

. Resolve the base: the `parent` node's resolved color if it exists, is a swatch and is not
  deleted; otherwise `parent.cached`.
. Scale by `tint_percent`: CMYK components multiply by `p/100`; RGB components move toward
  white: `c' = 1 − (1 − c) × p/100`.
. A tint's `spot` is its base's; its own `spot` register is ignored.

Chains: if the base is itself a tint, resolve it first and multiply the percentages.  A chain
containing a loop (only reachable through concurrent re-basing) is cut at the link whose
tint node has the smallest node id; that link reads its `cached` base color.  Depth is bounded
by the loop rule; a chain of 1,000 tints is legal and slow, and the panel warns above depth 8.

=== Merge semantics

[cols="1,1,3"]
|===
|Field |Policy |Concurrent case

|`tint_percent`
|ATOMIC
|Two people set one tint's percentage: LWW; live, the loser sees the slider move.  Percent
vs base recolor: independent -- both keep, which is right.

|`parent`
|ATOMIC (NodeRef)
|Re-base vs re-base: LWW.  Re-base vs delete of the new base: dangling → cached, badge.
Re-base A onto B while B is re-based onto A: a loop, cut by the rule above.  Neither
writer's tint disappears.

|`parent` vs base deletion
|reference fallback
|*Remove base* deletes the base and every tint it can see in one change.  A tint created
concurrently (or its `parent` written concurrently) is not in that change; after merge it is
live with a dangling parent.  It renders from `cached`; the Swatches panel shows the "base
color removed" badge; the Object panel shows objects using it as unnamed tints; the review
sheet lists "made a tint of a color that was deleted" with *Restore* on the base.  Nothing
is hidden or auto-deleted.

|`value` on a tint
|ATOMIC, ignored
|A stale `value` from a swatch that was later turned into a tint is ignored while `parent`
is set; clearing `parent` (the plain-drop case) writes `value` in the same change.
|===

Read-time normalizations::
* `parent` set but `tint_percent` zero or unset (malformed): reads as 100%.
* `parent` pointing at a non-swatch: reads `cached`, then black.
* Loops cut as above.

Undo::
Add tint, apply tint, set percentage, re-base and remove are each one change.  Undo of
*Remove base* restores base and tints together.
