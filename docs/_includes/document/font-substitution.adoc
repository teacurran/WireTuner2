When you open a document that uses fonts not installed on your Mac, {product} shows the *Missing
Fonts* sheet and lets you choose what to display in their place.  You can *substitute* a font --
a stand-in on your Mac only, leaving the document untouched -- or *replace* it, which changes the
document for everyone.  If a team font library is available, fonts in it are fetched
automatically and the sheet never appears for them.

== What happens when a font is missing

Text keeps its font name.  On your Mac it is drawn in a substitute -- the one you chose, or the
default substitute, *Helvetica Neue* -- and the Text panel shows the missing font's name in
brackets with a warning badge.  Line breaks are laid out with the substitute's metrics, so the
text may reflow on your screen; the document itself is not changed, and the text prints and
exports in the real font on any Mac that has it.

{product} looks for a missing font in three places before asking:

. The fonts installed on your Mac (including those Font Book has activated).
. Fonts embedded in the document, where their license allows embedding
  (xref:print-fonts.adoc[Fonts and printing]).
. Your team's font library, if your team has one and you are online.  A matching font is
  downloaded and activated for {product} only.

== The Missing Fonts sheet

The sheet opens when a document or an imported file uses a font that none of the sources above
provide.  It lists each missing font with its style and the substitute currently in effect.

To handle missing fonts:

. Select one font in the list, or click btn:[Select All].
. Do one of the following:
* Click btn:[Substitute…] and choose a font and style.  It is used on your Mac for this document
  and, with *Remember this substitution* on, for every document that uses the missing font.
* Click btn:[Replace…] and choose a font and style.  The document's text is changed to the new
  font, for everyone, as one undoable change.
* Do nothing: the default substitute is used.
. Click btn:[Open].  Or click btn:[Cancel] to close the document without applying replacements
  (substitutions cost nothing and are always applied).

*Keep original name* (on by default) means that a substituted font keeps reporting the missing
font's name in the Text panel and in exports, so nothing is lost when the font shows up later.
Turning it off for a font is the same as replacing.

Replacing keeps manual kerning and tracking.  It does not resize anything; if the replacement is
wider, text may reflow -- for everyone.

== The substitution table

Your substitutions are kept in menu:{product}[Settings… > Text > Font substitutions]: a table of
missing font → substitute pairs.  Remove a row to be asked again next time; the *Default
substitute* row sets the fallback used for fonts with no row.  The table is a preference: it is
yours, is synced to your other Macs with your preferences, and never changes a document.

== Team font library

A team can upload licensed fonts to its font library (xref:sharing.adoc[Sharing]).  When you open
a team document that uses one of them, the font is fetched and activated silently; the Missing
Fonts sheet lists only fonts the library does not have.  While offline, fonts you have already
fetched remain available; others are substituted until you reconnect, when the sheet's *Fetch
from team library* button becomes available.

== Working with others

A missing font is missing on *your* Mac, not in the document.  Collaborators who have the font see
the real thing; you see your substitute; the text is the same text.  Presence shows a small font
badge on people who are viewing the document with substitutions, so a reviewer knows whose screen
reflowed.

Replacing a font is an edit like any other: everyone sees the new font.  If two people replace the
same font with different fonts at the same time, the later replacement stands for every run both
of them touched, and the other is told.  If someone replaces a font while you are typing in it,
your new text takes the replacement too.

== Specification

=== Data model

No document fields.  Font names live in text marks (TYPE epic); replacement writes `TextMark` ops
with the new font for every run that carried the old one, in one change labelled "Replace font
<old> with <new>".  Substitutions are in `Preferences.font_substitutions` (a repeated message of
`missing`, `substitute`, `style`) in `AccountService`, plus a per-document, per-Mac cache of which
fonts were substituted (the `view` table) so the badge and the reopen-without-asking behavior work.

=== Merge semantics

Replace vs. replace (same font, different targets):: Each run's font mark is a Peritext mark;
concurrent marks over the same span resolve by OpId, so the later replacement wins per character
range.  Runs only one side touched (text inserted between the two changes) keep that side's font.
Review lists the same-text overlap per paragraph when both sides marked the same characters.

Replace vs. typing in that font:: Typing inserts characters that inherit the surrounding mark; the
replacement mark expands over them if they are inside its span (Peritext expansion), so the new
text takes the replacement.  Typed text *after* the span's end, in a run the replacement did not
cover, keeps the old font; normal Peritext behavior, no review entry.

Substitution:: Never merged: it is not in the document.

=== Offline behavior

* The Missing Fonts sheet works offline; team-library fetching is disabled with the *Fetch from
  team library* button greyed and explained.
* Replacements made offline are ordinary changes.

=== Server

Nothing beyond storing and relaying changes.  The team font library itself is an `AccountService`
feature specified with sharing.

=== Client

* `WTText.FontResolver` (TXT-002) resolves a font name through installed → embedded → team
  library → substitution table → default substitute, and reports which step answered so the
  badge and the sheet can show it.
* Missing Fonts sheet (`WTApp`): SwiftUI sheet on the document window, presented before the first
  render of the document if any font resolved through substitution and no remembered row covers
  it.  btn:[Replace…] and btn:[Substitute…] use `NSFontPanel`-free pickers listing families and
  styles.
* `WTModel.replaceFont(old:new:)` walks every text node's marks and emits one change.
* Preferences pane *Text > Font substitutions* table; *Default substitute* row; *Remember this
  substitution* toggle in the sheet (on by default).

NOTE: As built by TXT-002 (`WTText/FontManager.swift`, `FontResolver.swift`,
`TextLayoutEngine.swift`; `WTRender/GlyphRun.swift`).  `FontManager.resolve(_:)` answers a
`FaceName` with a `FontResolution` (the `FontSource` step -- `installed`, `embedded`,
`teamLibrary`, `substitution`, `defaultSubstitute` -- and the face laid out).  A substitution row
(`FontSubstitution`) is keyed by the missing *face*: a row naming the style (ignoring case) wins
over one naming only the family, and a substitute without a style keeps the run's style, so
`Preferences.font_substitutions`' `missing` wants the style beside the family when DOC-024 fills
it in.  The document's rows (`documentSubstitutions`: the sheet without *Remember*, and the
per-Mac record of them) come before the remembered ones (`substitutions`), and a row whose
substitute is not available is skipped.  The default substitute is Helvetica Neue, or
Helvetica if it is missing too; a run that names no family is the document default, Helvetica,
and is not reported.  Availability is matched by family descriptor, because
`CTFontManagerCopyAvailableFontFamilyNames` leaves out system families such as Courier and
Times (which were read as missing before).  Embedded and team fonts are *activated*:
`activate(fontsAt:source:)` (or `activate(_:source:)` for bytes, written once by content hash)
registers the file with Core Text for the process only, so WTText's lookup, WTRender's glyph
runs (by PostScript name) and PDF output all find it and nothing is installed; faces an
installed font already provides are skipped (installed wins), an embedded face whose `OS/2.fsType`
is restricted or bitmap-only is refused (`FontActivationError.notLicensedForEmbedding`), and an
embedded face wins over a team-library one.  `FontEmbedding` reads `fsType` (the least
restrictive usage bit applies): `allowsDocumentEmbedding` (installable or editable, with
outlines) is the test for *where licensed* before a font is embedded in a document, and
`allowsPrintEmbedding` the print check's.  `fileURL(of:)` names the file to upload;
`families()` and `styles(of:)` feed the pickers.  `teamLibraryFamilies` is the library's
catalog: a missing family in it is reported in `FontReport.teamLibraryPending` and left out of
`facesNeedingSheet`, which lists the faces the default substitute answered.  Every layout's
`FontReport` now carries `resolutions` for every named face (`substitutedFaces` for the badge),
and `FontManager.report(for:)` gives the same report for a set of faces without laying out,
for the sheet before a document's first render and for PRINT-014.  Anything that changes an
answer bumps `generation`: the resolver drops its fonts, the layout engine
(`TextLayoutEngine(fonts:)`, one manager per document or `FontManager.shared`) typesets again
the paragraphs whose faces now resolve differently, and activation calls
`GlyphFont.fontsChanged()` so WTRender drops cached fonts and outlines (`GlyphFont.isAvailable`
says whether a PostScript name loads that face).  Tests write their own TrueType fixtures.
Still to do elsewhere: the sheet, the preference table and the badge (DOC-024, `WTApp`); the
team library's catalog and fetch through `AccountService` and caching fetched fonts as blobs
(server and `WTSync`/`WTApp`); embedding a document's fonts as blobs and activating them on open
(`WTModel`/`WTApp`); and repainting canvases after an activation, since tiles keep what they drew.
