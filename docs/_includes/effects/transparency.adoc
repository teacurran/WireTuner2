Transparency lets an object, or one of its fills or strokes, show what lies behind it.  In
{product} transparency is a live effect: an attribute in the Object panel's appearance list, next
to strokes, fills and the other effects on xref:live-effects.adoc[Live vector effects].  There
is no separate opacity slider on the object -- the *Basic* transparency effect is the opacity,
and because it is an effect you can put it on the object as a whole, on a single fill, or on a
stroke, and stack it above or below other effects.  Three kinds are available:

Basic:: The whole shape at one level of transparency.
Feather:: The shape fades out toward its edge.
Gradient Mask:: A gradient decides how transparent each part of the shape is, using any gradient
type {product} draws (xref:gradients.adoc[Gradients]).

== Basic transparency

To make an object, fill or stroke transparent:

. Select the object, or select the fill or stroke in the Object panel's appearance list.
. Click btn:[Add Effect] and choose menu:Transparency[Basic].
. Enter a *Transparency* value from 0 (fully opaque) to 100 (invisible), or drag the slider.

Transparency applied to the object affects the combined result of all its fills and strokes:
the stroke does not show through the fill where they overlap, the way a sheet of colored film
looks.  Transparency applied to a single fill lets other fills and strokes of the same object
show through it.

== Feather

Feather fades the shape from opaque at its centre to transparent at its outline.  It is the
softest way to sit a shape into a background.

To feather an object:

. Select the object, fill or stroke.
. Click btn:[Add Effect] and choose menu:Transparency[Feather].
. Set its options:

[cols="1,3"]
|===
|Option |What it does

|*Radius*
|How far inside the outline the fade begins, in points.  A radius larger than half the shape's
width makes the whole shape translucent.

|*Softness*
|0--100: the shape of the fade.  Low values keep the interior opaque and fade sharply near the
edge; high values fade gently across the whole radius.
|===

Feather is drawn as pixels at the raster effects resolution, like the effects on
xref:raster-effects.adoc[Live raster effects]; Basic and Gradient Mask stay resolution
independent.

== Gradient mask

A gradient mask uses the *lightness* of a gradient to set transparency: where the gradient is
white the shape is fully transparent, where it is black fully opaque, and gray in between.
Colors in the gradient are converted to their gray equivalents.  Every gradient type is
available -- linear, radial, contour, cone and the rest -- with the same editing as gradient
fills.

To apply a gradient mask:

. Select the object, fill or stroke.
. Click btn:[Add Effect] and choose menu:Transparency[Gradient Mask].
. Edit the gradient in the effect's settings exactly as you edit a gradient fill: choose the
  type, drag color swatches onto the ramp, move and remove stops, set the angle, and drag the
  gradient handles on the canvas (xref:gradients.adoc[Gradients]).  Only the gray value of
  each stop matters; the ramp shows the stops in gray so you can judge the result.

TIP: Start from black-to-white for a straight fade; a black-white-black ramp gives a bar that
is transparent in the middle.

== How transparency composites

* Objects are composited in stacking order.  A transparent object shows whatever is below it in
  the same layer and in lower layers, including the page color; layers set to be non-printing
  are not shown through.
* Within one object, a fill or stroke with its own transparency effect shows the object's
  lower fills and strokes through it.  An object-level transparency effect applies to the
  flattened object.
* Transparency inside groups composites within the group first, then the group over the page.
  A Basic transparency on a group therefore does not double up where its members overlap.
* Transparent objects are exported to PDF as native transparency (soft masks and constant
  alpha) so they stay editable and crisp; PostScript and older formats receive a flattened
  version, rasterized where necessary at the raster effects resolution
  (xref:export-pdf.adoc[Exporting PDF], xref:printing.adoc[Printing]).
* Transparency effects are included in graphic styles and copied with the object.

== Working with others

Transparency effects merge like every other effect.  Two people adjusting the same
transparency slider at once end with the later value, and the merge review lists the other
after an offline session; two people adjusting different options of a Feather (one the radius,
one the softness) both get their way.  Editing a gradient mask's stops concurrently keeps
everyone's stops, because stops merge individually as they do in gradient fills.  Nothing here
needs the network.

=== Data model

[source,protobuf]
----
// Addition to proto/wiretuner/doc/v1/effects.proto
message TransparencyEffect {
  enum Style { STYLE_UNSPECIFIED = 0; STYLE_BASIC = 1; STYLE_FEATHER = 2; STYLE_GRADIENT_MASK = 3; }
  Style style = 1;
  uint32 amount = 2 [(buf.validate.field).uint32.lte = 100];   // BASIC: 0 opaque .. 100 invisible
  double radius = 3 [(buf.validate.field).double.gte = 0];       // FEATHER, points
  uint32 softness = 4 [(buf.validate.field).uint32.lte = 100];  // FEATHER
  // GRADIENT_MASK: the ATTR epic's gradient (type, angle, handles, stops).  STRUCT with its
  // stops as a SEQUENCE, exactly as in a gradient fill, so stop edits merge individually.
  Gradient mask = 5;
}
----

`Gradient` is the message xref:gradients.adoc[Gradients] defines for gradient fills; nothing
is added to it.  The mask ignores each stop's color hue and uses its luminance
(`0.2126 R + 0.7152 G + 0.0722 B` in the document RGB space, or `1 − K` for pure-K CMYK stops)
as `1 − alpha`.

=== Merge semantics

Fields:: `style`, `amount`, `radius`, `softness` are independent registers; `mask` merges as a
gradient fill does (type/angle/handles registers, stops as a sequence).  Every concurrent
combination keeps both sides except the same register written twice, which is LWW and
reviewed.

Style vs. options:: A `style` change concurrent with an edit of another style's option keeps
both, as with every effect.

Mask stops:: Concurrent stop insertions both appear; concurrent edits to one stop's position
and color both apply; delete vs. edit leaves the stop deleted and offers *Restore*.

Read-time normalizations::
* `GRADIENT_MASK` with a mask that has fewer than two live stops renders as Basic with
  `amount` = the luminance of the single stop (or 0 if none).
* Values out of range clamp for rendering.

=== Offline behavior

Nothing beyond the general rules.

=== Server

Nothing beyond storing and relaying changes.

=== Client

Package:: `WTRender` (`TransparencyStage`), `WTApp/Inspector/Effects/TransparencyEditor`,
reusing the ATTR epic's gradient editor view and canvas handles.

Rendering::
* *Basic* at object level: the object's flattened drawables are rendered into a transparency
  layer (`CGContext.beginTransparencyLayer`) and composited with `setAlpha(1 − amount/100)`.
  At fill/stroke level, the drawable itself is drawn with that alpha.
* *Gradient Mask*: the gradient is rendered to a luminosity mask (a `CGImage` in a gray color
  space at the current device resolution, or a shading for PDF output) and applied with
  `clip(to:mask:)` around the drawable or transparency layer.  For PDF, `WTInterchange` emits
  an `/SMask` with a luminosity group containing the gradient shading -- vector, no bitmap.
* *Feather*: goes through the raster stage of xref:raster-effects.adoc[Live raster effects]:
  the alpha channel is eroded by `radius` and blurred with a kernel width of
  `radius × softness/100`, then multiplied into the drawable's alpha.
* Groups composite through a transparency layer per group when any member or the group is
  transparent, giving the documented non-doubling behavior.

Hit testing:: Unchanged by transparency; a fully transparent object (amount 100) is still
selectable by its outline.

Undo:: Slider drags are one undo group; each gradient-editor commit is one change, labelled
as for gradient fills.
