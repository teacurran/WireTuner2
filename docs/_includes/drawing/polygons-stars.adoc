The Polygon tool draws regular polygons -- triangles, pentagons, hexagons, anything up to 360
sides -- and stars.  Like rectangles and ellipses, a polygon stays a live shape: its number of
sides, its star points and its proportions can be changed after drawing, by dragging handles
with the Subselect tool or by typing in the Object panel.  Every polygon is a closed path,
drawn clockwise from its center.

== Setting the Polygon tool options

To set what the Polygon tool draws:

. Double-click the Polygon tool in the Tools panel (it shares a slot with the Spiral and Arc
  tools).
. In the Polygon Tool sheet, set the options below.  The preview updates as you change them.
. Click btn:[OK].  The settings apply to every polygon you draw from now on.

[cols="1,3"]
|===
|Option |Meaning

|Shape
|*Polygon* draws a regular polygon.  *Star* draws a star with one point per side.

|Number of sides
|3 to 360, from the field or the slider.  Above about 20 sides a polygon is hard to tell
from a circle.

|Star points
|For stars only.  *Automatic* picks the inner radius that makes a classic star for the number of
sides (the star's edges align with alternate points).  *Manual* lets you set it with the
*Acute*/*Obtuse* slider: acute stars have long, narrow points; obtuse stars are nearly flat.
|===

== Drawing a polygon or star

To draw a polygon or star:

. Choose the Polygon tool.
. Drag from where the center should be.  The distance you drag sets the radius, and the
  direction sets the rotation: the first vertex points at your pointer.
. Release.

Modifier keys while dragging::
kbd:[Shift]:: Constrains the rotation to the constrain angle and every 45° from it, so a
square-ish polygon sits level.
kbd:[Option]:: Draws from the center.  Polygons always draw from the center, so this changes
nothing for them; it is listed because the same key matters for the other shape tools.
kbd:[Space]:: Repositions the shape while you keep dragging.

== Editing a polygon or star

A selected polygon shows two kinds of handles with the Subselect tool: a diamond at one
vertex (a *peak*) and, for stars, a circle at one inner point (a *valley*).

To reshape a polygon or star by dragging:

. Choose the Subselect tool and click the polygon.
. Drag the diamond handle to move every vertex at once -- outward to enlarge, around the
  center to rotate.
. For a star, drag the circle handle to move every inner point: closer to the center for
  sharper points, further out for blunter ones.  Dragging a valley past the peaks turns the
  star inside out, which is allowed.
. Hold kbd:[Shift] while dragging either handle to keep the vertex or valley on its original
  angle, so you change only the radius.

The Object panel shows the same things as numbers: *Sides*, *Star*, *Radius*, *Inner radius*
(stars, with *Automatic* to let {product} choose it) and *Rotation*.  Changing the number of
sides regenerates the shape around the same center.  To edit individual points, convert the
polygon to a path with menu:Modify[Ungroup]; it cannot be turned back into a live polygon.

== Working with others

Polygons merge property by property.  A collaborator can change a star's number of points
while you drag its valleys; you see the new points appear mid-drag and your inner radius
applies to all of them.  If you both drag the same handle, the later release wins.  Converting
a polygon to a path while someone else is editing it turns their edit into a review item after
they reconnect, the same as for rectangles.

== Specification

=== Data model

`doc/v1/shape.proto` (shared with DRAW-006).  Local space: center at the origin, first vertex
at angle 0 (pointing +x) before `rotation`; `CommonProps.transform` places the shape.

[source,protobuf]
----
// A live regular polygon or star.
message PolygonProps {
  CommonProps common = 1;
  uint32 sides = 2 [(buf.validate.field).uint32 = {gte: 3, lte: 360}, (buf.validate.field).ignore = IGNORE_IF_ZERO_VALUE];
  bool star = 3;
  // Outer radius (vertex distance from center), local units.
  double radius = 4 [(buf.validate.field).double.gte = 0];   // 0 allowed: a sparse write omits it
  // Inner radius for stars.  Ignored when star is false or auto_inner is true.  May exceed
  // radius (an inside-out star).
  double inner_radius = 5 [(buf.validate.field).double.gte = 0];
  bool auto_inner = 6;                        // "Automatic" star points
  // Manual star sharpness, 0 (acute) .. 1 (obtuse); the Acute/Obtuse slider.  Only used to
  // seed inner_radius when the tool draws; stored so the Object panel can show the slider.
  double sharpness = 7 [(buf.validate.field).double = {gte: 0, lte: 1}];
  // Rotation of the first vertex, radians, applied before common.transform.  Kept separate
  // from the transform so a vertex-handle drag (radius + rotation) never collides with a
  // Pointer-tool move (transform).
  double rotation = 8;
  // Angular offset of the valleys from their default (halfway between peaks), radians; set
  // by dragging the circle handle without Shift.
  double valley_offset = 9;
  AppearanceProps appearance = 10;
}
----

=== Merge semantics

Per field:: every field is its own register (STRUCT default).  There is no ATOMIC grouping
because each field is a distinct user decision, and the handle drags write at most two fields
(`radius` + `rotation`, or `inner_radius` + `valley_offset`).

Sides changed vs. radius dragged:: Independent; the merged polygon has the new side count at
the new radius.

Diamond handle vs. circle handle:: Independent registers; both survive.

Same handle from two people:: `radius` and `rotation` are each LWW, so a merged shape can take
one person's radius and the other's rotation.  Both were dragging the same handle, so the
review sheet lists the polygon under *same register* with both handle positions; the merged
state is a legal polygon and renders.  We accept this rather than making `(radius, rotation)`
ATOMIC because a kbd:[Shift]-drag writes only `radius`, and losing a concurrent free rotation
to it would be worse.

Star turned off vs. inner radius edited:: `star = false` hides the inner points; the
`inner_radius` write is kept and reappears when `star` is turned back on.

Convert to path vs. edit:: As for rectangles: the shape node is deleted, the edit is listed as
*edit vs delete*.

Read-time normalizations::
* `sides` outside 3--360 (older client): clamped.
* `auto_inner = true`: `inner_radius` reads as the automatic value for `sides`
  (`radius * cos(2π/sides) / cos(π/sides)` for odd counts, the pentagram-style construction;
  `radius * 0.5` for even counts).
* `radius <= 0`: renders nothing; selectable from the Layers panel.

=== Offline behavior

Works offline; nothing needs the server.

=== Server

Nothing beyond storing and relaying changes.

=== Client

Tool:: `PolygonTool` in `WTApp`.  Mouse-down creates the node at the pressed point with the
current tool settings; each drag event writes `radius` and `rotation` (Shift-constrained
rotation via GEO-005); kbd:[Space] moves `transform`.  A drag under 1 pt is undone locally.
Tool settings (shape, sides, star mode, sharpness) are preferences.

Geometry:: `WTGeometry.polygonPath(props:)` yields `sides` (or `2 × sides` for stars) corner
points, clockwise starting at `rotation`.  The Polygon Tool sheet preview draws the same path
into a small `NSView`.

Handles:: Diamond at vertex 0, circle at valley 0, drawn in the overlay; drags convert the
pointer position into polar coordinates around the local center.

Object panel:: `polygon` section: Sides (stepper 3--360), Star, Radius, Inner radius with
Automatic, Rotation (degrees in the UI, radians stored).

Undo:: One group per drag or field commit.

NOTE: As built by DRAW-010 to DRAW-012.  Deviation: `polygonPath` is `WTModel.ShapeGeometry.polygonPath`
(with `PolygonShape` holding the read-time rules), not WTGeometry's, for the same reason as the
rectangle's (it produces WTModel's `VectorPath` with synthetic point ids).  The automatic inner radius
is clamped at 0 (the odd-count formula is negative for a triangle).  A manual star's inner radius is
seeded from *Acute/Obtuse* between 10% of the radius and the edge midpoints' radius.  `CreatePolygon`
places the centre with `transform` and the first vertex with `rotation`; the tool previews and creates
on mouse-up like the other shape tools.  The Polygon Tool sheet lists the tool's preferences
(`ToolOptionSheets`) without a live preview; the Subselect diamond and circle handles are not
delivered.  The concurrent `radius`/`rotation` conformance vector is left to the CRDT track (the case is
a WTModel merge test).

NOTE: As built by DRAW-010's remainder (`WTModel/PolygonHandles.swift`).  `PolygonHandles.positions(of:in:)` gives the diamond (vertex
0) and, on a star, the circle (valley 0) in pasteboard space for the overlay; `hit(_:on:tolerance:in:)` picks one (the valley first);
`drag(_:of:to:keepAngle:in:)` is the `SetPolygonFields` of a drag event -- polar coordinates about the local centre: the diamond
writes `radius` and `rotation`, the circle `inner_radius`, `auto_inner` off and `valley_offset`, and kbd:[Shift] (`keepAngle`) the
radius only.  The conformance vector `registers/polygon-radius-rotation-concurrent` holds the concurrent `radius` and `rotation`
writes in both engines.  Not built: drawing the handles and routing Subselect drags to them (WTApp).
