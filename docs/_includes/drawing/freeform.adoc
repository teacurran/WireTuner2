The three tools in the Pencil group draw paths that follow your hand: the Pencil draws a plain
line, the Variable Stroke Pen draws a filled shape whose width swells and thins like a brush,
and the Calligraphic Pen draws a filled shape whose width depends on the direction of the
stroke, like a broad-nib pen.  All three turn the motion of the pointer into a smooth path
with as few points as the precision you choose allows, and all three read pressure from a
pen tablet or an Apple Pencil.

== Pencil

To set the Pencil tool options:

. Double-click the Pencil tool in the Tools panel.
. In the Pencil Tool sheet, set:
+
Precision:: 1 to 10.  High values follow every wobble of your hand and place many points; low
values smooth the stroke and place few.
Draw dotted line:: Shows the stroke as a dotted trail while you draw instead of a solid
preview, which keeps drawing responsive on very large documents.  The finished path is always
solid.
. Click btn:[OK].
. Set the stroke and fill for new paths with the color wells at the bottom of the Tools panel
  (xref:applying-color.adoc[Applying color]).

To draw with the Pencil:

. Choose the Pencil tool.
. Drag on the canvas.  The path is fitted when you release.

Modifier keys while dragging::
kbd:[Option]:: Draws a straight segment from the point where you pressed kbd:[Option] to
where you release it, then continues freehand.
kbd:[Shift]:: With kbd:[Option], constrains the straight segment to the constrain angle and
every 45° from it.

To continue a path with the Pencil:

. Select the path.
. Move the Pencil over one of its end points.  A small *+* beside the pointer shows that
  drawing will extend the path.
. Drag.  The new stroke is fitted and joined to the existing path.

== Variable Stroke Pen

The Variable Stroke Pen produces a closed, filled shape -- the outline of a brush stroke --
whose width varies between a minimum and a maximum.  With a tablet, pressure sets the width;
with a mouse, keys do.

To set the Variable Stroke Pen options:

. Double-click the Variable Stroke Pen tool.
. In the Variable Stroke Pen sheet, set:
+
Precision:: 1 to 10, as for the Pencil.
Draw dotted line:: As for the Pencil.
Auto remove overlap:: After each stroke, removes the parts of the outline that overlap
themselves (where the stroke crosses or doubles back), producing a clean composite path.  This
takes a moment on long strokes; you can also do it later with menu:Modify[Alter Path > Remove
Overlap] (xref:combining-paths.adoc[Combining paths]).
Width:: *Min* and *Max* stroke widths, 1 to 72 points, measured across the whole stroke.
. Click btn:[OK].
. Set stroke and fill with the color wells.  A fill and no stroke gives the most brush-like
  result.

To draw with the Variable Stroke Pen:

. Choose the tool.
. Drag on the canvas.

Keys while dragging::
kbd:[Option]:: Draws a straight segment.
kbd:[{startsb}]:: Narrows the stroke from here on (mouse users).
kbd:[{endsb}]:: Widens the stroke from here on.
Pen pressure:: With a tablet, pressure maps to the width between *Min* and *Max* and the
bracket keys are ignored while the pen is in contact.

== Calligraphic Pen

The Calligraphic Pen produces a closed, filled shape like a stroke from a flat nib held at a
fixed angle: wide when you draw across the nib, thin when you draw along it.

To set the Calligraphic Pen options:

. Double-click the Calligraphic Pen tool.
. In the Calligraphic Pen sheet, set:
+
Precision:: 1 to 10.
Draw dotted line:: As for the Pencil.
Auto remove overlap:: As for the Variable Stroke Pen.
Width:: *Fixed* for a constant nib width, or *Variable* with *Min* and *Max* (1 to 72 points)
for a nib whose width follows pressure or the bracket keys.
Angle:: The nib's angle, 0° to 359°, typed or set with the dial.  At 45° strokes drawn from
lower-left to upper-right are thin and those from upper-left to lower-right are wide.
. Click btn:[OK].
. Set stroke and fill.  Choose no stroke and a basic fill for the most pen-like result.

To draw with the Calligraphic Pen:

. Choose the tool.
. Drag on the canvas.

Keys while dragging::
kbd:[Option]:: Draws a straight segment.
kbd:[{startsb}] / kbd:[{endsb}]:: Narrows or widens the stroke (Variable width only).
Pen pressure:: Sets the width between *Min* and *Max* (Variable width only).

To continue a path with the Calligraphic Pen, select it and start dragging from one of its
end points, as with the Pencil.

== Drawing with a pen tablet

{product} reads pressure from any tablet macOS supports (Wacom and compatible tablets, and an
iPad with Apple Pencil connected through Sidecar).  Nothing needs to be enabled: when a pen
is in contact, pressure drives the Variable Stroke Pen and the Calligraphic Pen in *Variable*
mode, and the Freeform and Eraser tools' pressure options (xref:editing-paths.adoc[Editing
paths]).  With the pen lifted, or with a mouse or trackpad, width is set by the bracket keys
and stays at the value you last set until you change it.

== Working with others

A collaborator sees your stroke appear when you release the mouse, as one finished path; they
never see the half-drawn trail.  From then on the path is shared point by point like any other
(xref:vector-basics.adoc[Vector basics]).  Continuing a path that a collaborator is editing
appends your new points to it while keeping their edits.  If someone deletes the path you were
about to continue, your stroke is drawn as a new path instead.  Tool settings -- precision,
widths, nib angle -- are yours alone and never travel with the document.

== Specification

=== Data model

None beyond `PathProps`.  The Variable Stroke and Calligraphic pens store only the fitted
outline; the width profile and nib angle are not kept, so a stroke cannot be re-fitted after
the fact.  Tool settings are preferences.

=== Merge semantics

As for any path.  Specific cases:

Continue a path vs. concurrent edit:: The continuation is an element insert after the end
point's element (or before the start point's, if the stroke began there) plus a handle write
on that end point to smooth the join.  Concurrent edits to other points are untouched.  If the
end point was deleted concurrently, the inserted points still sit after its tombstone, so the
continuation attaches to the new end.

Continue a path vs. delete of the path:: The inserts land on a deleted node and are listed as
*edit vs delete*.  Live, the tool checks the node is still live at mouse-up and, if not,
creates a new path instead (the guide's promise); the race window is the fitting time.

Auto remove overlap vs. concurrent edit:: The cleaned result replaces the contour's points
(delete all, insert new), so a concurrent edit to an original point is *edit vs delete*.
Because the cleanup runs within a second of mouse-up, this is only reachable offline.

=== Offline behavior

Works offline.  A stroke is one `CreateNode`, or one change of inserts when continuing.

=== Server

Nothing beyond storing and relaying changes.

=== Client

* `PrecisionSetting`: tolerance `12/precision` pt divided by zoom; smoothing σ `(10−precision)/3` samples; corners (≥ 60°, two samples each side) are detected before smoothing and each run between corners is smoothed separately.

Input pipeline:: `WTApp.StrokeCapture` collects `NSEvent` samples (position, `pressure`,
`timestamp`, and `tabletPoint` data when present) at the event rate, drawing the preview trail
(solid or dotted per the setting) in the tool overlay.  On mouse-up the samples go to GEO-004's
Schneider fit with an error tolerance derived from precision (`tolerance = 12 / precision` pt
at 100% zoom, scaled by the inverse zoom so precision is in screen terms).

Pencil:: The fitted centerline becomes an open contour of curve points; kbd:[Option] spans
are emitted as straight segments with corner points at both ends.

Variable Stroke Pen:: Width per sample: pressure mapped linearly to `[min, max]` when a pen is
in contact, otherwise the bracket-key width.  The outline is built by offsetting the fitted
centerline by half the (interpolated) width on each side and capping the ends with semicircles
(GEO-003), then, if *Auto remove overlap* is on, unioned with itself (GEO-002).

Calligraphic Pen:: Width per sample: `w = base * |sin(θ_stroke − θ_nib)|` clamped to at
least 0.5 pt, where `base` is the fixed width or the pressure-mapped width.  Outline built as
above but with flat, angled caps.

Tablet:: `NSEvent.pressure` is 0 for mice; `event.subtype == .tabletPoint` marks pen samples.
Sidecar delivers Apple Pencil as tablet events, so no special casing.  Bracket keys are read
through the tool's `keyDown` while a drag is active and update the width from the next sample.

Undo:: One group per stroke, including the overlap cleanup.

NOTE: As built by DRAW-016 and DRAW-017.  `StrokeCapture` (WTApp) collects the pointer samples and the
kbd:[Option] spans; `WTModel.StrokeFit` fits each freehand run with GEO-004's `PrecisionSetting.fit`
at the view's zoom and joins the spans (corner points at span joins and at the stroke's ends, curve
points where the fitted handles are collinear).  A continuation is `ContinuePath` (the stroke's first
point is the end being extended, whose leaving handle smooths the join).  Pressure and tablet
detection are not read by the Pencil (the Variable Stroke and Calligraphic Pens use them), and the
fit-to-golden-corpus check is GEO-004's own test.

NOTE: As built by DRAW-018 and DRAW-020 (`WTApp/Tools/VariableStrokePen.swift`, `PathToolPreferences.swift`).
`CanvasEvent.isTablet` carries `NSEvent.subtype == .tabletPoint` (Sidecar's Apple Pencil arrives
the same way, so nothing else is special-cased).  `StrokeWidthControl` maps a pen sample's pressure
through the *Pressure curve* preference hook (`pressure ^ curve`, 1 linear, in the pen's sheet) onto
*Min*…*Max*, keeps the bracket keys' width (1 pt steps, clamped) for mouse and trackpad samples,
and ignores the bracket keys while the last sample was a pen in contact.  The Variable Stroke Pen
fits the centreline with `StrokeFit` at the sheet's precision (kbd:[Option] spans straight,
kbd:[Shift] constraining them) and offsets it by half the width -- interpolated along the stroke by
arc length from the samples -- with semicircular caps, fitted as one closed contour within 0.03 pt
(GEO-004's `CurveFitter`: GEO-003's offsetter takes a constant width only).  The stroke is one
change "Variable Stroke"; with *Auto remove overlap* GEO-002's `Boolean.normalize` runs off the
main thread afterwards and `RewritePath` (WTModel) replaces the contour, every point new (plus any
further contours), inside the same undo group.  Deviation: a concurrent edit of a point the cleanup
replaced is retained on the point's tombstone, but the review sheet lists the path as *both
edited* -- WTSync's divergence raises *edit vs delete* for deleted nodes, not for deleted point
elements.  The manual protocol for a tablet and for Sidecar is in xref:testing.adoc#tablet-input[Testing];
it has not been run (no tablet or Sidecar iPad on the build machine).
