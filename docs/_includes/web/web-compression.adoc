Artwork headed for a web page has to be small and has to look right in a browser.  {product}
gives you two ways to get there: keep the artwork as vectors (SVG, which browsers render
natively and which stays sharp at every size) or rasterize it into a compressed bitmap.  This
page is about choosing between them and, when you rasterize, choosing a format.  The export
procedures and every option of each format live on xref:export-bitmap.adoc[Exporting bitmap
images] and xref:export-vector.adoc[Exporting vector formats]; xref:publish-html.adoc[Publishing
as HTML] applies these choices to a whole document at once.

NOTE: {fh} offered GIF, JPEG and PNG, plus a movie format for vectors.  {product} keeps the
three bitmap formats, adds WebP and AVIF, and uses SVG -- animated where needed -- for vectors.

== Vector or bitmap?

Export as SVG when the artwork is what {product} is for -- paths, text, gradients, flat color.
An SVG is usually smaller than a bitmap of the same drawing, scales to any screen density, keeps
text selectable and links clickable, and can carry the frame-by-frame animation described in
xref:animation.adoc[Animating objects and text].

Rasterize when the artwork depends on things SVG cannot express well: raster effects, complex
transparency stacks, large placed photographs, or thousands of tiny paths that would make the
SVG bigger than a picture of it.  The output warnings of the HTML publisher tell you which objects
were rasterized and why.

== Choosing a bitmap format

[cols="1,2,2"]
|===
|Format |Best for |Notes

|PNG
|Flat color, sharp edges, text, anything needing transparency.
|Lossless.  Replaces GIF for nearly every job.  8-bit palette mode for small flat images,
24/32-bit for everything else.

|JPEG
|Photographs, scanned art, wide gradients.
|Lossy; the *Quality* slider trades size for artifacts.  No transparency: transparent areas are
filled with the *Matte* color.

|WebP
|Either of the above, when older browsers do not matter.
|Lossy or lossless, with transparency, typically 25--35% smaller than JPEG or PNG at the same
quality.  Supported by every current browser.

|AVIF
|Photographs where every kilobyte counts.
|Lossy, often half the size of JPEG.  Slower to encode; not every tool outside browsers reads
it.  Requires macOS 14 or later to encode.

|GIF
|Legacy pages and simple frame animation for chat and social tools.
|256 colors, 1-bit transparency.  Use PNG for stills; use GIF only where an animated GIF is
required (xref:animation.adoc[Animating objects and text]).
|===

== Settings that matter

These options appear in the Export sheet for every bitmap format (xref:export-bitmap.adoc[Exporting
bitmap images]); the ones below matter most for the web.

Resolution and scale::
Web images are sized in CSS pixels; a 300 × 200 image on a Retina screen needs 600 × 400
pixels to look sharp.  Export at *2×* (the default for the *Web* presets) and let the page scale it
down, or export both *1×* and *2×* and use both in a `srcset`.  Dots per inch are irrelevant to a
browser.

Quality::
For JPEG, WebP and AVIF.  Start at 80; go lower until artifacts appear where they matter.

Colors::
For PNG-8 and GIF: fewer colors, smaller file.  Dithering hides banding in gradients at the cost of
size.

Matte::
The color that shows through transparent areas in formats without transparency, and under
anti-aliased edges in PNG-8 and GIF.  Match it to the page background.

Metadata::
*Strip metadata* removes color profiles and file info; keep the profile only if the image has to
match a print piece (xref:color-management.adoc[Managing color]).

== Web presets

The Export sheet's *Preset* pop-up includes *Web -- PNG 2×*, *Web -- JPEG 80*, *Web -- WebP 80*
and *Web -- SVG*.  A preset fills in the format and every option above; the sheet shows the
estimated file size before you click btn:[Export] so you can compare presets on the same
artwork.  Presets are yours, not the document's, and are edited in the same sheet.

== Working with others

Exporting reads the document and writes a file on your Mac; nothing changes in the shared
document, so collaborators are not affected and nothing needs to sync.  Presets live in your
preferences, not in the document; a teammate who wants the same settings recreates them or
imports your exported preset file.
