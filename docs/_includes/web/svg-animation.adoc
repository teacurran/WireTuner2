{fh} could import movies, place them on a page, send them out for editing, export the document
as a movie, and test the result in a playback window.  {product} does each of those jobs with
*SVG animations*: animated SVG files that every browser plays natively, need no plug-in or
player, stay vector at any size, and are just text a designer can read.

* *Placed SVG animations* -- an animated SVG file placed on a page like an image, shown on the
  canvas as a still *poster frame* taken at a time you choose, played live on a published web
  page and in Preview in Browser, and exported unchanged into HTML and SVG output.
* *Animations you make here* -- the layer-and-page animation of
  xref:animation.adoc[Animating objects and text] exports as an animated SVG, and that file can be
  placed into any other document as a placed SVG animation.
* *Preview in Browser* -- the current page, or the whole document, rendered exactly as
  xref:publish-html.adoc[Publishing as HTML] would and opened in your browser, with links, page
  links and animations playing.

NOTE: {fh}'s *Movie Settings*, *Controller* toolbar and menu:Window[Movie] commands do not exist
in {product}.  Their animation options moved to the Animation panel and the Export sheet; their
testing role is taken by *Preview in Browser*.

== Placing an SVG animation

A placed SVG animation is an object: it has position, size, a stacking order, a name, notes and
links like any other, and it can be transformed, grouped, clipped and put on any layer.  On the
canvas it is a still picture -- the *poster frame* -- rendered from the animation at a time you
choose.  A published web page and Preview in Browser play it.

An SVG file with no animation in it is not placed: it is converted to editable paths, text and
images as described on xref:import-formats.adoc[Import file formats].  {product} decides by
looking for animation in the file (CSS `@keyframes` or transitions, SMIL `<animate>` elements,
or scripts); the Import options sheet lets you override the choice with *Place as animation* or
*Convert to objects*.  Converting an animated file keeps only its first frame.

To place an SVG animation:

. Choose menu:File[Import…] (kbd:[Cmd+R]) and choose an `.svg` or `.svgz` file that contains
  animation, or drag the file from the Finder onto the page.
. Click where the top-left corner should go, or drag to set the size (the animation keeps its
  aspect ratio while you drag; hold kbd:[Shift] to free it).

The file itself is stored with the document, so collaborators get it too.  Files over 50 MB are
refused with a suggestion to simplify them first; most SVG animations are a few hundred
kilobytes.

=== SVG animation attributes in the Object panel

With a placed SVG animation selected, the Object panel (xref:object-panel.adoc[The Object panel])
shows an *SVG Animation* section:

[cols="1,3"]
|===
|Attribute |Meaning

|*X*, *Y*, *W*, *H*
|Position and size in document units, as for any object.  *W* and *H* keep the aspect ratio
unless the lock is opened.

|*Scale X*, *Scale Y*
|Size as a percentage of the file's natural size (its `viewBox`, or its `width` and `height`,
at 72 pixels per inch).

|*Poster frame*
|The time (in seconds, or `mm:ss.ff`) of the frame shown on the canvas, in print, and as the
still image wherever the animation cannot play.  Drag the small scrubber, or type a time.
Default: the first frame.

|*On the web*
|How the animation behaves on a published page: *Play automatically* (default on), *Loop*
(default: as the file says), *Play on hover* (starts when the pointer enters, for pages that
should be still until touched).

|*Duration*
|The animation's length as declared in the file, or *Indefinite* for a looping file with no
end.  Informational.

|*Scripts*
|Whether the file contains script.  Scripts never run inside {product}, and published pages
strip them by default (see *On the web* > *Allow scripts* in the HTML setting), so an animation
that depends on script is flagged here.

|*File*
|The file name, natural size and whether it is compressed (`.svgz`).  btn:[Replace…] swaps the
file for another and keeps position, size and settings; btn:[Reveal] shows the file in the
Finder if you still have the original; btn:[Save a Copy…] writes the stored file out;
btn:[Edit With…] opens it in a text or SVG editor and updates the placed copy when the file is
saved (xref:external-editors.adoc[Editing images in other applications]).
|===

== Preview in Browser

*Preview in Browser* is the quickest way to see a document as the web will see it.  It renders the
current page (or every page) to a temporary folder using the HTML setting currently selected in
the Publish sheet, and opens it in a browser.  Nothing is saved; the folder is discarded when you
quit.

To preview in a browser:

* Choose menu:File[Preview in Browser] or press kbd:[Cmd+Return] to preview the current page.
* Choose menu:File[Preview All Pages in Browser] (kbd:[Cmd+Shift+Return]) to preview the whole
  document, so page links can be followed.

The browser used is set by the *Preview browser* preference (default: your default browser;
xref:preferences.adoc[Preferences]).  Choosing a page again while the browser window is open
replaces its contents; most browsers reload automatically.

If the document has animation settings, the preview plays them; placed SVG animations play.
Links open.  Page links navigate.  Anything the HTML publisher would list in its output
warnings is listed in the same way after the preview opens, unless *Show output warnings* is off
in the Publish sheet.

== Working with others

A placed SVG animation is shared like an imported image: collaborators see a placeholder until
the file finishes syncing to them, then the poster frame.  Two people changing the poster frame
time at once end with the later choice.  Replacing the file is one change; if a collaborator is
moving the animation at the same moment, the new file lands where they moved it.

Preview in Browser is private to you and never touches the document.  If you preview while
someone's latest changes are still on their way to you, they are not in the preview -- preview
again once the sync indicator settles.

=== Data model

A new node kind, `SvgAnimationProps`, in the `NodeProps.kind` block reserved for the WEB epic.
The file is a blob in the `assets` collection, as for images (the IMG epic's `AssetProps`); the
node references the asset.

[source,protobuf]
----
// node.proto -- NodeProps.kind case for a placed SVG animation (WEB block)
message SvgAnimationProps {
  // The asset node holding the SVG blob (assets collection).  Placeholder until the blob
  // has downloaded; if the asset is deleted the node renders as a hatched placeholder.
  NodeRef asset = 1 [(wt.crdt.field).on_dangling = REF_FALLBACK_PLACEHOLDER];
  // Natural size from the viewBox (or width/height), read at import.  ATOMIC: width and
  // height belong together.
  Size natural_size = 2 [(wt.crdt.field).merge = MERGE_ATOMIC];
  // Declared duration in milliseconds; 0 = indefinite.  Informational.
  uint64 duration_ms = 3;
  // Which animation mechanisms the file uses, for the Object panel and export warnings.
  // Informational; recomputed on Replace.
  SvgAnimationKinds kinds = 4;
  // Poster frame time in milliseconds.
  uint64 poster_time_ms = 5;
  // The poster image blob (PNG, rendered at import or when the time changes) so every replica
  // can draw the object before the SVG has downloaded, and so PDF/print never need to
  // evaluate the animation.
  NodeRef poster = 6 [(wt.crdt.field).on_dangling = REF_FALLBACK_PLACEHOLDER];
  // Web playback settings.  STRUCT: each is independent.
  SvgAnimationWebProps web = 7;
  // Placement: CommonProps.transform (ATOMIC) maps natural_size points (at 72 px/in) to the
  // pasteboard, as for bitmaps.
}

message SvgAnimationKinds {
  bool css = 1;      // @keyframes / transitions
  bool smil = 2;     // <animate>, <animateTransform>, <animateMotion>, <set>
  bool script = 3;   // <script> or event attributes; never run in {product}
}

message SvgAnimationWebProps {
  bool no_autoplay = 1;     // inverted so the default (false) plays automatically
  LoopMode loop = 2;        // AS_FILE (default), LOOP, ONCE
  bool play_on_hover = 3;
}

enum LoopMode { LOOP_MODE_AS_FILE = 0; LOOP_MODE_LOOP = 1; LOOP_MODE_ONCE = 2; }
----

The SVG blob is uploaded through `BlobService` like any asset; the poster blob is small and is
uploaded first.  A 50 MB per-file limit is enforced by the client at import and by the server on
upload (`document_blob` limits, IO/IMG epics).

=== Merge semantics

`poster_time_ms`, `poster`:: Written together by one change; each is an ATOMIC register.  Two
concurrent poster changes: LWW on both registers, and since both writes come from the same
change on each side, the greater change wins both (the OpIds of the two ops in one change are
consecutive, and the comparison is by counter, so the two registers agree).  The poster blob of
the losing write is an orphan until GC.
`asset` (Replace…):: ATOMIC.  Replace writes `asset`, `natural_size`, `duration_ms`, `kinds`,
`poster_time_ms` and `poster` in one change; the same consecutive-counter argument keeps them
consistent under a concurrent replace.  A concurrent move (transform) is an independent register
and survives.
`web.*`:: Independent registers.
Edit vs. delete:: Standard: edits to a deleted node apply and return with it.
Blob not yet available:: Renders as a placeholder with a progress ring (the SYNC-008 lazy
download notification).  The poster blob usually arrives first, and then the poster is drawn
even though the SVG is still downloading.

Read-time normalizations: `poster_time_ms` beyond a finite `duration_ms` reads as the last
frame; `natural_size` of zero reads as 320 × 240 so the object is never invisible.

=== Offline behavior

* Placing an SVG animation works offline; the blob and its poster wait in `blobs_pending` and
  upload on reconnect, poster first.
* Preview in Browser works offline for everything already downloaded; animations still pending
  show the poster only, and the warnings say so.
* Web-link publishing is covered on xref:publish-html.adoc[Publishing as HTML].

=== Server

Nothing beyond storing and relaying changes and blobs.  The blob size limit is a configuration
value (`wt.blob.max-size.svg-animation`, 50 MiB).

=== Client

* Import (`WTInterchange.SvgAnimationImporter`): accepts `public.svg-image` and `.svgz`; parses
  with the SVG importer's front end (IMG-012) far enough to read `viewBox`/`width`/`height`,
  detect animation (`@keyframes`, `transition`, SMIL elements, `<script>`, `on*` attributes) and
  compute the declared duration (max of SMIL `dur`/`end` and CSS `animation-duration` ×
  `iteration-count`; indefinite if any is infinite); renders the poster with an offscreen
  `WKWebView` paused at the poster time (`document.getAnimations().forEach(a => a.currentTime
  = t)` for CSS, `svg.setCurrentTime(t)` + `pauseAnimations()` for SMIL) into a PNG at 2× the
  placed size, capped at 4,096 px.  Stores both blobs through the SYNC-008 cache and creates the
  node in one change.  A file with no animation is handed to the SVG importer instead unless the
  options sheet says otherwise.
* Rendering (`WTRender`): draws the poster blob like a bitmap (IMG epic's image drawing path)
  with a small play glyph overlay at the centre in the canvas only (never in exports or print);
  placeholder states as for images.  The canvas never evaluates the animation.
* Object panel *SVG Animation* section: SwiftUI editor registered for `SvgAnimationProps`
  (APP-007) with a poster scrubber backed by `WKWebView` snapshots cached per 100 ms, debounced
  writes on scrub end; *On the web* controls; file information and the *Scripts* flag;
  btn:[Replace…] through the importer keeping `transform` and `web`; btn:[Edit With…] through the
  IMG epic's round-trip (IMG-019) with change detection.
* Export: the HTML publisher (WEB-008) inlines the SVG (scripts stripped unless *Allow
  scripts*), applying the web props by injecting a wrapper `<svg>` with `animation-play-state`
  and hover rules, or emits `<img src>` for files that need isolation; the SVG exporter (IO-019)
  nests it with a `viewBox` mapping; the animated-SVG exporter (WEB-018) nests it inside every
  frame; PDF, bitmap exporters and printing draw the poster.
* Preview in Browser (`WTInterchange.BrowserPreview`): runs the HTML publisher for the current
  page (or all pages) into `NSTemporaryDirectory()/wt-preview/<document>/` with the selected
  HTML setting, and opens `index.html` with the *Preview browser* preference via `NSWorkspace`.
  Re-running writes over the same folder so browsers that watch the file reload.  The folder is
  removed at quit.
* Undo: placing an animation is one step ("Place SVG animation"); every Object panel edit one
  step.
