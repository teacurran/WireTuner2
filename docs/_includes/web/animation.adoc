{product} animates frame by frame, with each frame drawn on its own layer or its
own page.  There are no tweens and no timeline of keyframes; instead you build the frames as
artwork -- often by blending two shapes and releasing the blend to layers -- and the document's
*animation settings* say how to play them: which layers or pages are the frames, how fast, and
whether to loop.  The *Animation* panel plays the result on the canvas, and menu:File[Export…]
writes it as an animated SVG, a GIF, an APNG or an MP4 movie.

NOTE: The layer-and-page animation is previewed in the Animation panel and exported to formats
browsers and video players read today.  The animation commands live under
menu:Extensions[Animate].

== How frames are built

A frame is a layer, a page, or a layer on a page:

Layers::
Each foreground layer in the Layers panel, bottom to top, is one frame.  Layers below the
separator bar are the background: they appear in every frame.  Hidden layers are skipped.
Pages::
Each page, in page order, is one frame.  All layers of a page are drawn together.
Pages and layers::
Every page contributes one frame per foreground layer, page by page, so a four-page document
with three foreground layers gives twelve frames.

Design the motion to run upward through the Layers panel: the first frame is the lowest
foreground layer.  The Layers panel (xref:layers.adoc[Layers]) can show a frame number beside
each layer when the frame source is layers; choose *Show frame numbers* from the panel menu.

Any layer can hold for longer than one frame (*Hold* in the Layers panel's context menu; a hold
of 3 shows the frame for three frame periods) or be left out of the animation entirely (*Exclude
from animation*).  Excluded layers still print and export as stills.

== Releasing objects to layers

*Release to Layers* takes a blend, a group, a text block, or objects attached to a path, takes
it apart, and puts each piece on its own layer -- the fastest way to turn a blend of two shapes
into the frames between them.

To prepare a text block for animation:

. Select the text block and put it where the motion should start.
. Choose menu:Text[Convert to Paths] (xref:text-to-paths.adoc[Converting text to paths]).
. With the result still selected, choose menu:Modify[Join] so the letters act as one path.
. Choose menu:Edit[Clone] and drag the clone to where the motion should end.
. kbd:[Shift]-click to select the original and the clone.
. Choose menu:Extensions[Create > Blend], then release the blend to layers as below
  (xref:blends.adoc[Blends]).

To release objects to layers:

. Select the objects.  A group counts as one object unless you choose *Sequence* below, which
  takes the group apart; a nested group is always one object.
. Choose menu:Window[Layers] so you can watch the layers appear.
. Choose menu:Extensions[Animate > Release to Layers…].
. Choose an *Animate* mode:
+
[cols="1,3"]
|===
|Mode |Result

|*Sequence*
|Each piece goes to its own layer, one after another: frame 1 shows the first piece, frame 2
the second, and so on.

|*Build*
|Pieces accumulate: frame 1 shows the first piece, frame 2 the first and second, frame 3 the
first three.  Earlier pieces are copied onto later layers.

|*Drop*
|The opposite of Build: every frame shows all the pieces except one, dropping them one at a time
in order.

|*Trail*
|Each piece appears on its own layer and on the next *Trail by* layers after it, so a moving
piece leaves a fading trail of its recent positions.  Enter the trail length in *Trail by*.
|===
. Select *Reverse direction* to release the pieces in reverse order, so the motion runs the
  other way.
. Select *Use existing layers* to put the pieces on the layers already in the document, starting
  with the current layer and moving up; the extension adds layers only if it runs out.  Leave it
  unselected to create a new layer for every piece (`Frame 1`, `Frame 2`, …, or continuing the
  numbering if frame layers exist).
. If you chose *Use existing layers*, select *Send to back* to put the released pieces behind
  whatever those layers already hold instead of in front.
. Click btn:[OK].

Releasing a text block converts each character to paths first and gives every character its own
layer.  Releasing a blend puts each step of the blend on its own layer and leaves the blend's
original ends where they were.  Releasing objects attached to a path detaches them.  The whole
release is one undoable step.

== Working with others

Animation settings belong to the document, so a change to the frame rate reaches everyone at
once; the Animation panel updates while it is open.  If two people change the same setting in
the same moment, the later change stands.  Previewing is yours alone: playing the animation on
your canvas does not move anyone else's view, and collaborators see the ordinary document while
you watch it play.

Releasing to layers moves and copies objects, so it behaves like any other rearrangement: if a
collaborator is editing one of the pieces at that moment, their edit lands on the piece wherever
it ended up.  If two people release the same group at the same time, each gets a set of new
layers; the original pieces end up in one set and the other set holds only the copies its mode
made, which the merge review points out so one set can be deleted.

After working offline, changed animation settings merge field by field, and the review shows any
setting both of you changed.

== Specification

=== Data model

[source,protobuf]
----
// document.proto -- extension of the well-known settings node (0:1); the messages are web.proto
message SettingsProps {
  // ... other settings
  // Document animation settings.  STRUCT: each is an independent choice.
  AnimationSettings animation = 70;
}

enum FrameSource {
  FRAME_SOURCE_UNSPECIFIED = 0;   // reads as NONE
  FRAME_SOURCE_NONE = 1;          // not animated
  FRAME_SOURCE_LAYERS = 2;
  FRAME_SOURCE_PAGES = 3;
  FRAME_SOURCE_PAGES_AND_LAYERS = 4;
}

enum AnimationBackground {
  ANIMATION_BACKGROUND_UNSPECIFIED = 0;   // reads as PAGE_COLOR
  ANIMATION_BACKGROUND_PAGE_COLOR = 1;
  ANIMATION_BACKGROUND_WHITE = 2;
  ANIMATION_BACKGROUND_TRANSPARENT = 3;
}

message AnimationSettings {
  FrameSource source = 1;
  // Frames per second.  Validated 0.01..120 (IGNORE_IF_ZERO_VALUE); 0 reads as 12.
  double fps = 2 [(buf.validate.field).double = {gte: 0.01, lte: 120}];
  bool loop = 3;                 // default true (see read-time rule below)
  bool no_autoplay = 4;          // inverted so the proto default (false) means autoplay
  AnimationBackground background = 5;
}

// layer.proto -- extension of LayerProps (Layers pages)
message LayerProps {
  // ... existing fields
  // Frame metadata.  STRUCT.
  LayerFrameProps frame = 20;
}
message LayerFrameProps {
  // Number of frame periods this layer stays on screen.  0 reads as 1.
  uint32 hold = 1 [(buf.validate.field).uint32.lte = 10000];
  // Leave this layer out of the animation (still prints and exports as a still).
  bool excluded = 2;
}
----

`loop` defaults to true at read time when the `animation` message has never been written
(`source` unset); once any field is written the stored value is authoritative.  This keeps a
never-touched document looping while letting the proto default be false.

Release to Layers writes ordinary nodes: `CreateNode` for new layers (parent `layers`, position
above the current layer), `MoveNode` for the released pieces, `CreateNode` for the copies that
Build, Drop and Trail make, and `SetDeleted` for the taken-apart container (blend, group, text
block).  No new node kind.

=== Merge semantics

`animation.*`:: Independent ATOMIC registers under STRUCT.  Concurrent `fps` writes: LWW; the
review sheet shows "Frame rate: mine 12 / theirs 24".  A concurrent `source` change and `fps`
change both apply.
`frame.hold`, `frame.excluded`:: ATOMIC per layer.
Release to Layers:: One change.  Concurrently:
* Another user edits a piece (fill, points): the edit applies to the moved node; nothing is
  lost.
* Another user deletes the container: the release already created the pieces' moves and the
  container's `deleted = true`; the pieces are alive on their new layers.  The review sheet
  lists nothing unless the same registers were written.
* Two users release the same container: both produce moves of the same pieces (LWW per piece,
  so the pieces are split between the two layer sets by OpId) and both create their own copies
  and layers.  The document is consistent but doubled.  The review sheet lists it as "move vs.
  move" on each piece; the guide tells the user to delete one set.  No automatic cleanup.
* Another user renames a layer the release is adding pieces to: independent registers, fine.
Frame order:: Derived from layer order (sibling positions under `layers`) or page order; never
stored, so it cannot conflict.

Read-time normalizations: `fps` of 0 reads as 12; `hold` of 0 reads as 1; a document whose
`source` is `LAYERS` but has no foreground layers has zero frames and exporters offer only stills.

=== Offline behavior

Everything on this page works offline.  Settings edits coalesce in the outbox like any register.

=== Server

Nothing beyond storing and relaying changes.
