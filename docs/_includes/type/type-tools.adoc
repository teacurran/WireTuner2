Type is adjusted from four places that all do the same things: the *Text* section of the
Object panel (the most complete), the Text toolbar (the quickest), the Text menu (with
keyboard shortcuts), and the text block's own handles (for leading and kerning by eye).  This
page maps those four places; the meaning of each setting is on
xref:type-specifications.adoc[Setting type specifications], xref:paragraphs.adoc[Paragraphs]
and xref:tabs-indents.adoc[Tabs, indents and margins].

== The Text section of the Object panel

Select a block with the Pointer tool or a range with the Text tool; the Object panel shows the
text's sections.  The *Text* section comes first, with the *Font* and *Style* pop-ups, the
*Size* field and the *Alignment* pop-up.  Below it, as the selection calls for them:

[cols="1,3"]
|===
|Section |Holds

|*Axes* and *Features*
|A variable font's axes and named instances, and the OpenType features the font offers
(xref:type-specifications.adoc[Setting type specifications]).

|Text effect and text style
|The *Effect* pop-up and its options, and the text style applied from the Styles panel.

|*Text Block*
|Size, inset and border (xref:text-blocks.adoc[Working with text blocks]).

|Text on a path
|Placement of text attached to a path (xref:text-on-path.adoc[Text on a path]).

|Text color
|The text's fill and stroke (xref:text-color.adoc[Text color]).

|*Paragraph*
|Space above and below, indents, hyphenation and the other paragraph settings.

|*Spacing*
|Horizontal scale, word and letter spacing.
|===

The block's own strokes, fills and effects are listed with the rest of its attributes
(xref:attribute-stack.adoc[The attribute stack]).

== Adjusting by dragging

The handles of a selected text block do double duty.  Corner handles resize; the others adjust
type for the whole block:

To adjust leading by dragging::
Select the block with the Pointer tool and drag its *top or bottom center* handle.  Dragging
away from the block opens up the lines; dragging toward the center tightens them.  The Object
panel's leading field follows.

To adjust kerning by dragging::
Drag a *side* handle.  Away from the block spreads the letters (positive range kerning);
toward the center tightens them.

Hold kbd:[Shift] while dragging either handle for coarser steps (whole points of leading, whole
percent of kerning).  Double-clicking these handles toggles auto-expanding instead of adjusting
(xref:text-blocks.adoc[Working with text blocks]), so start the drag deliberately.

== Adjusting with the keyboard

With a range selected or an insertion point placed by the Text tool:

[cols="1,2"]
|===
|Keys |Adjusts

|kbd:[Cmd+Option+←] / kbd:[Cmd+Option+→]
|Kerning at the insertion point, or range kerning of the selection, by 1% of an em.

|kbd:[Cmd+Option+Shift+←] / kbd:[Cmd+Option+Shift+→]
|The same by 10% of an em.

|kbd:[Control+Option+↑] / kbd:[Control+Option+↓]
|Baseline shift by 1 point.

|kbd:[Control+Option+Shift+↑] / kbd:[Control+Option+Shift+↓]
|Baseline shift by 10 points.

|kbd:[Cmd+Shift+,] / kbd:[Cmd+Shift+.]
|Type size by 1 point.
|===

== Working with others

Every adjustment, however you make it, is one change that applies to the characters you had
selected.  A collaborator typing in the same block keeps typing; if they type inside the range
you adjusted, their new characters take the adjustment too, as if they had typed after you.
Two people dragging the same handle at once end with the value of whichever let go later.

== Specification

=== Data model

No new fields.  Leading and kerning drags write `TextMarkValue.leading` and
`TextMarkValue.range_kerning` marks over the block's whole text; keyboard nudges write
`kerning` (span 1, at an insertion point), `range_kerning` or `baseline_shift` over the
selection.

=== Merge semantics

Every control ends in `applyMark` over a span, so the mark rules on
xref:creating-text.adoc[Creating text] apply: per-attribute LWW by OpId where spans overlap,
expansion at the end anchor for all of these attributes except `kerning`.  A handle drag emits
one mark at mouse-up (the live preview is local).  Two concurrent drags: the later OpId wins
over the whole block.  A drag concurrent with a range kerning applied to one word inside:
the word's mark has the greater OpId if applied later and shows through; otherwise the block
mark covers it.  Neither is reviewed unless offline and in the same paragraph.

=== Offline behavior

Nothing beyond outbox coalescing.

=== Server

Nothing beyond storing and relaying changes.

=== Client

The Text toolbar and menu items are declared in the command registry (APP-005) with
validation tied to the editing session's selection.  Handle drags are `Tool` behaviors on the
Pointer tool that distinguish corner, side and center handles by hit region (REND-003) and
report the value to the Object panel live.  Undo grouping: one step per drag, nudge or menu
command; repeated nudges within 1 s coalesce into one step ("Kern").

NOTE: As built by TYPE-019 (`WTApp/Text/TypeNudges.swift`).  The Text tool reads the keys before the
input method: kbd:[Cmd+Option+←/→] (kbd:[Shift] ×10), kbd:[Control+Option+↑/↓] (kbd:[Shift] ×10)
and kbd:[Cmd+Shift+,/.].  Nudges of one kind on one selection add up and are written once a second
passes without another (or when another kind or selection comes, or on `flush`): one change and one
undo step, "Kern", "Baseline Shift" or "Size".  Kerning at an insertion point is a span-1 `kerning`
mark on the character before it (none at the start of the text); over a selection each run's value
moves by the nudges.  Deviation: at an insertion point baseline shift and size change the pending
format of what is typed next, which writes nothing.

NOTE: As built by TYPE-018 (`WTApp/Text/TextBlockHandles.swift`; `WTModel/TypeHandleDrags.swift`, a new file).  A press on a
text block's top, bottom or side handle starts a type drag; once the pointer has moved 3 view points the moved edge
previews dashed with the value beside the pointer ("Leading +2 pt", "Range kerning 5%"), and mouse-up writes one mark over
the whole text, "Leading" or "Kern".  The edge follows the pointer: leading changes by the drag's distance (block space,
away from the block positive) over the number of laid-out lines, range kerning by the distance over the size and the
characters per line less one, as percent of an em.  Leading keeps the mode of the first character's leading (unset reads
as auto, 120%): + and = move by points, % by the equivalent percent of the size; the line height never goes below zero.
Values land on tenths, or with kbd:[Shift] on whole points (+, =) or whole percent (%, kerning).  A press that does not
move writes nothing, so a double-click still toggles auto width or height.  *Deviation*: the live preview is the edge and
the readout on the canvas; the text does not reflow and the Object panel shows the value once it is written.

NOTE: As built by TYPE-017's font and size items (`WTApp/Text/Fonts/`: `FontCommands.swift`,
`FontMenus.swift`, `FontSheets.swift`, `FontToolbarControls.swift`; `WTText/FontChoices.swift`, a new
file).  menu:Text[Font] is filled each time it opens (`MainMenuBuilder.dynamicMenus`, an
`NSMenuDelegate` for the paths `Text/Font`, `Text/Style`, `Context/Font` and `Context/Style`, so the
text context menus get the same lists): *Recently Used* (up to ten, in the user defaults
`text.recent_font_families`, noted by the menu, the toolbar and *Other…*), *Missing Fonts* (the
families the document's text names that WTText's per-document `FontManager` cannot lay out, in
brackets with a warning icon), *All Fonts* (`FontManager.families()`, the document's own marked with
a document icon), then the `text.font.other` command, a sheet with a search field (prefix matches
first, case- and diacritic-insensitive), the family list and the family's faces, whose btn:[OK]
writes `font_family` and `font_style` as one change, "Font".  A family item writes `font_family`
("Font"); menu:Text[Style] keeps its four commands and adds the family's other faces, which go
through `setFontStyleNamed` ("Font Style", with the instance's `axes` on a variable family).
menu:Text[Size] is commands: the nine presets (`text.size.<points>`, checked when the text shares
that size), then *Smaller* (`text.size.smaller`, kbd:[Cmd+Shift+,]), *Larger* (`text.size.larger`,
kbd:[Cmd+Shift+.]) and *Other…* (`text.size.other`, titled "Other (13 pt)…" and checked when the
text shares a size that is not a preset; a sheet taking 1--10,000 points, with or without "pt").
On selected blocks *Smaller* and *Larger* move every run's size by 1 point (kept to 1--10,000) in
one change, "Size"; while the Text tool edits they go to its nudger, so they add up with the keys as
TYPE-019 describes.  The Text toolbar's `text.fontFamily`, `text.fontStyle` and `text.fontSize`
are drawn as their own controls (`ToolbarController.controls`, `ToolbarControl`): an `NSComboBox`
of every family that completes as you type (recent first; a name that is not listed is refused),
an `NSPopUpButton` of the family's faces and an `NSComboBox` of the presets that takes any size;
run from the palette they open the *Other…* sheets.  Every control applies to the Text tool's
selection (a range: one mark; an insertion point: the pending format) or to the selected blocks
whole, one change each.  Mixed text shows *Mixed* in the toolbar and a dash on each value it holds
in the Font and Style menus.  *Deviations*: there is no hover preview (the *Display font preview*
preference is not wired); the toolbar's font controls do not drag while customizing (remove or
move them from the Customize window's list); menu:Text[Align], menu:Text[Leading] and the
toolbar's leading and alignment items are still placeholders.
