Type specifications are the character-level settings: which font, how big, which face, how far
apart the lines and letters sit, where the baseline is, and how wide the glyphs are drawn.  They
apply to whatever is selected -- a range with the Text tool, or every character in the blocks
selected with the Pointer tool.  With no selection they set the defaults for text you create
next (xref:default-attributes.adoc[Default attributes]).  Where to find the controls is on
xref:type-tools.adoc[The type adjustment tools]; this page is what each one means.

== Font, size and style

To choose a font for selected text, do one of the following:

* Choose menu:Text[Font] and pick a family.
* Pick from the *Font* pop-up in the Character section of the Object panel or in the Text
  toolbar.  Hovering a family name previews it on the selection (turn this off with the
  *Display font preview* preference).
* Start typing a family name into the Object panel's font field to filter the list.

To set the size:

* Choose menu:Text[Size] and a preset, *Smaller* or *Larger* for 1-point steps, or *Other…* to
  type any size from 1 to 10,000 points.
* Type a value in the *Size* field of the Object panel or Text toolbar and press kbd:[Return].

To choose a face:

* Choose menu:Text[Font Style] and a face (Plain, Bold, Italic, Bold Italic, and the family's
  other faces such as Light or Condensed).
* Pick from the *Style* pop-up in the Object panel or the Text toolbar.

Fonts are any that macOS can load, including variable fonts, whose named instances appear as
faces.  Bold and Italic applied to a family that lacks that face are synthesized (a heavier
stroke, a slant) and shown with a warning icon in the Object panel, since synthesized faces
print poorly.  A font the document uses that is missing on your Mac is substituted and listed
in the Missing Fonts sheet (xref:font-substitution.adoc[Font substitution]).

NOTE: macOS no longer supports PostScript Type 1 fonts, so {product} does not offer them; a
document that names one gets a substitute.

Type set smaller than the *Greek type below* preference (8 pixels on screen by default) is
drawn as gray bars to keep scrolling fast; selected text is always drawn in full.

== Variable font axes

A variable font carries a whole range of designs in one file -- weight from hairline to black,
width from condensed to extended -- along *axes* you can set anywhere in their range, not only
at the named faces.  When the chosen font is variable, an *Axes* group appears in the Character
section with a slider and a value field for each axis the font offers:

[cols="1,3"]
|===
|Axis |What it does

|*Weight*
|Stroke thickness, typically 100 (thin) to 900 (black).

|*Width*
|Glyph width as a percentage of normal; below 100 condenses, above 100 extends.

|*Slant*
|Lean in degrees; negative values lean right in most fonts.

|*Optical size*
|The design tuned for a given point size: finer details at large sizes, sturdier at small.  Left
at *Auto* it follows the type size; set it to pin one design.

|Other axes
|Any further axis the font defines, under the name the font gives it (Grade, Contrast, Casual…).
|===

The *Style* pop-up lists the font's *named instances* -- the designer's chosen combinations,
such as Light or Semibold Condensed -- and picking one sets every axis at once.  Move a slider
and the pop-up shows *Custom*.  Click the reset arrow beside an axis to return it to the font's
default, or pick a named instance to return every axis.  Axis settings apply to the selection
like any other setting, spread as you type, and can be part of a text style
(xref:text-styles.adoc[Text styles]).

For a variable font with a weight axis, menu:Text[Font Style > Bold] moves the weight axis to
the font's bold instance instead of synthesizing a bold, so no warning icon appears.  If a
collaborator lacks the font, their substitute ignores the axes it does not have; your settings
stay in the document.

== OpenType features

Many fonts hold alternate glyphs and behaviors -- ligatures, small capitals, old-style figures,
swashes -- that are switched on and off with OpenType *features*.  The *Features* group of the
Character section lists the features the chosen font actually offers, so you never see a
checkbox that would do nothing:

[cols="1,3"]
|===
|Feature |What it does

|*Ligatures*
|Standard ligatures such as fi and fl.  Most fonts turn these on by default.

|*Discretionary ligatures*
|Decorative ligatures the designer left optional, such as ct and st.

|*Small caps*
|Lowercase letters set as the font's designed small capitals.

|*All small caps*
|Capitals as well as lowercase set as small capitals.

|*Old-style figures*, *Lining figures*
|Numerals that dip below the baseline like lowercase letters, or numerals that sit on the
baseline at capital height.  Choose one or leave the font's default.

|*Tabular figures*, *Proportional figures*
|Numerals of equal width that line up in columns, or numerals fitted to their own shapes.

|*Fractions*
|Turns 1/2 and similar sequences into true fractions.

|*Swashes*
|Flourished alternates of letters.

|*Stylistic sets*
|The font's alternate designs, *Stylistic set 1* to *20*, with the designer's names where the
font provides them (Single-storey a, Rounded…).

|*Contextual alternates*
|Letter shapes chosen from their neighbors, as in connected scripts.  Usually on by default.
|===

Each checkbox starts at the font's own default for that feature and shows a reset arrow once
you have changed it; the arrow puts the font back in charge.  Feature settings apply to the
selection like any other setting, spread as you type, and can be part of a text style.

NOTE: *Small caps* here uses the font's designed small capitals; if the font has none the
checkbox is absent.  menu:Text[Convert Case > Small Caps] (xref:editing-text.adoc[Editing text])
draws scaled capitals instead and works with any font.

== Alignment

Left, center, right or justified, per paragraph, from menu:Text[Align], the alignment buttons
in the Character section, or the Text toolbar.  Alignment is a paragraph setting and is
described with the rest of them on xref:paragraphs.adoc[Paragraphs].

== Leading

Leading is the baseline-to-baseline distance between lines.  It is set per character range and
the largest value on a line wins for that line.  Three modes:

[cols="1,1,3"]
|===
|Mode |Symbol |Meaning

|Extra
|+
|Type size plus the value in points.  `+0` is *solid* leading (lines as tall as the type).
Changing the size keeps the extra.

|Fixed
|=
|Exactly the value in points, whatever the size.

|Percentage
|%
|The value as a percentage of the size.  `120%` is *auto* leading, the default.
|===

To set leading, choose the mode from the pop-up beside the *Leading* field (Object panel or
Text toolbar) and type the value; or choose menu:Text[Leading > Solid], menu:Text[Leading >
Auto] or menu:Text[Leading > Other…] for a sheet with both controls.  Dragging a block's top
or bottom center handle adjusts it by eye (xref:type-tools.adoc[The type adjustment tools]).

== Kerning and range kerning

Kerning adjusts the space between one pair of characters; range kerning adjusts the space
between every pair in a selection.  Both are in percent of an em (the type size), positive to
open, negative to close, and both add to the font's own kerning pairs, which are always
applied.

To kern a pair, click between the two characters with the Text tool and type a value in the
*Kerning* field, or press kbd:[Cmd+Option+←] / kbd:[Cmd+Option+→].  To range kern, select the
characters and use the *Range kerning* field or the same keys.  Dragging a side handle range
kerns the whole block.

== Baseline shift

Raises (positive) or lowers (negative) selected characters from the baseline, in points, from
the *Baseline shift* field or kbd:[Control+Option+↑] / kbd:[Control+Option+↓].  A raised
baseline plus a smaller size is how you make a superscript "™" or a footnote mark; the
menu:Text[Type Style > Superscript] and *Subscript* commands apply that combination for you.

== Horizontal scale

In the Spacing section, *Horizontal scale* stretches or compresses the glyph shapes, in
percent, without changing their height or spacing.  Values above 100 widen, below 100 narrow.
Word and letter spacing, which sit beside it, are paragraph-level and described on
xref:paragraphs.adoc[Paragraphs].

== Text effects and text styles

The bottom of the Character section has the *Effect* pop-up (highlight, inline, shadow,
strikethrough, underline, zoom -- xref:text-effects.adoc[Text effects, inline graphics and
text wrap]) and the *Style* pop-up, which applies a text style from the Styles panel
(xref:text-styles.adoc[Text styles]).

== How settings spread as you type

Text you type takes the settings of the character before the insertion point.  If you set
something with an insertion point but no selection -- click after a word, choose Bold, type --
the new characters get it, and the characters you type after them keep it until you change it
again.  Typing immediately after a bold word continues in bold; typing immediately before it
does not.  Attached links and inline graphics are the exception: typing at either end of a link
stays outside it.

== Finding and replacing type attributes

To change every occurrence of a font, face or size across a document, use the Find & Replace
panel rather than editing block by block.

To select text blocks by their type attributes:

. Choose menu:Edit[Find and Replace > Graphics…] and click the *Select* tab.
. Choose *Font* from the *Attribute* pop-up.
. Choose where to look in *Search in*: *Selection*, *Page* or *Document*.  For a selection, tick
  *Remove from selection* to deselect matches instead; for a page or document, tick *Add to
  selection* to keep what is already selected.
. Choose a family (or *Any font*), a face (or *Any style*), and a size range (leave both empty
  for any size, or only *Min* for one exact size).
. Click btn:[Find].  The matching blocks are selected and counted at the bottom of the panel.

To find and replace type attributes:

. In the Find & Replace panel's *Replace* tab, choose *Font* from *Attribute*.
. Choose the scope in *Change in*.
. Under *From*, choose the family, face and size range to look for.
. Under *To*, choose the replacement family (or *No change*), face (or *No change*), and size
  (or leave empty).
. Click btn:[Change].  The number of blocks changed is shown at the bottom of the panel.

Finding by text *effect* is on xref:text-effects.adoc[Text effects, inline graphics and text
wrap]; the panel itself is described on xref:find-replace.adoc[Find and replace].

== Working with others

* A setting you apply to a range applies to exactly those characters, even if a collaborator
  is typing elsewhere in the block at the same moment.  If they are typing inside your range,
  their new characters take your setting too, as they would if they had typed after you
  finished.
* If two people set the same attribute on overlapping text at once, the later setting shows on
  the overlap and each person's setting stays on the rest of their range.  After offline work,
  such a paragraph is listed in the review sheet.
* Font substitution is per Mac: a collaborator without your font sees a substitute but the
  document still names your font, and their edits do not change it.
* A font Find & Replace across the whole document is one change; collaborators see every block
  update together.
* Axes and features are settings like any other.  If you and a collaborator drag the weight of
  the same word at once, the later drag wins on that word; if one of you switches on ligatures
  while the other switches on a stylistic set, both apply.  The same feature set opposite ways
  on the same characters goes to the later change, and the review sheet lists the paragraph
  after offline work.

== Specification

=== Data model

Fields on xref:creating-text.adoc[Creating text]: `font_family`, `font_style`, `size`,
`leading`, `kerning`, `range_kerning`, `baseline_shift`, `horizontal_scale`, `axes`
(`FontVariation`) and `feature` (`FeatureSetting`, one mark per feature tag).  Fonts are named
by PostScript family and face names; a document-level font list for embedding is the IO
epic's concern (xref:print-fonts.adoc[Fonts and printing]).  A named instance is written as
`font_style` *and* the instance's axis values in `axes`, so a Mac whose copy of the font lacks
that instance name still renders the same design.

=== Merge semantics

All ten are marks; the general rules on xref:creating-text.adoc[Creating text] apply.

Axes:: `FontVariation` is ATOMIC per mark: the whole list of `(tag, value)` pairs is one value.
A named instance is one choice in the design space, and a slider drag rewrites the full list
carrying the other axes as the dragger read them.  Two people dragging *different* axes of the
same characters concurrently therefore collide: the later mark wins on the overlap and the
other person's axis reverts to what the winner read, listed under *same text* in the review.
Chosen over one mark per axis because a named instance would then be several marks whose
concurrent partial replacement can land on a combination no one chose, and because an axis
tuple is what layout, caching and export key on.  Live, the loser sees the revert within a
moment and drags again.

Features:: One mark per feature tag, each a tri-state register (`DEFAULT`, `ON`, `OFF`); the
attribute identity for overlap resolution is `(feature, tag)`.  Marks with different tags stack;
overlapping marks of the same tag resolve by OpId per character like any attribute, so a
concurrent *Ligatures on* and *Ligatures off* on the same word goes to the greater OpId, and a
concurrent *Ligatures on* and *Stylistic set 3 on* both apply.  `DEFAULT` is a value: the reset
arrow writes it, and it competes with concurrent `ON`/`OFF` writes by OpId instead of vanishing.
+
Two alternatives were rejected.  A SET of signed tags (`+liga`, `-liga`) on one mark cannot say
"off" without contradiction handling -- add-wins keeps a concurrent `+liga` and `-liga` both,
so the read would need a second rule that reaches into the set's add OpIds -- and "back to the
font default" is a remove, which loses to any concurrent add.  A single STRUCT-like
`FeatureSettings` mark with one field per feature cannot be STRUCT at all in text: a mark is a
whole-value register, so a concurrent Ligatures toggle and Stylistic-set toggle on the same
range would collide.  Per-tag marks are the same idea as per-tag registers, landed where marks
live; on a text style, where fields *are* registers, the same tri-states are a STRUCT
(`FeatureSettings`, xref:text-styles.adoc[Text styles]).

Insertion-point settings:: With no selection, a setting is *pending* on the client: the next
`TextInsert` in that session is followed, in the same change, by `TextMark` ops for the pending
attributes over the new ids.  Nothing is written if the user clicks away without typing.
Concurrent remote typing at the same anchor is unaffected (marks cover only the local ids).

Overlap:: Two replicas set `size` on overlapping ranges: per character, the covering mark with
the greater OpId wins.  The review sheet's *same text* row shows the paragraph diff with both
sizes named.

Leading per line:: Layout takes the maximum leading among a line's characters; a concurrent
leading change on part of a line therefore always shows.

Find & Replace font:: One change ("Replace font Helvetica → Inter (N blocks)") of `TextMark`
ops over the matched runs, per block.  Concurrent typing inside a matched run: the typed
characters are inside the run's original marks and pick up the replacement like the rest.

Read-time normalizations::
* `font_family` naming a font not installed: substituted per TXT-002; the mark is untouched.
* `horizontal_scale` at or below 0: rendered as 100.
* `size` outside 1–10,000: rendered as the default size.
* An `Axis.tag` the resolved font lacks is ignored; a value outside the axis range is clamped
  to it; duplicate tags in one `FontVariation` take the last.
* A `feature` tag the resolved font lacks is ignored; a `DEFAULT` state reads as no mark.

=== Offline behavior

Nothing beyond outbox coalescing.  Font substitution needs no server; the team font library
does (TXT-002).

=== Server

Nothing beyond storing and relaying changes.

=== Client

Character section:: SwiftUI-hosted inspector section registered with APP-007 for `text` nodes
and text ranges; mixed values show as "--" and write only the edited field.  Font list from
`NSFontManager`/CoreText with recents and type-to-filter; preview writes a transient attribute
to the layout only.

Layout:: `WTText` maps `size`, `leading`, `kerning`, `range_kerning`, `baseline_shift` and
`horizontal_scale` to Core Text attributes (`kCTKernAttributeName` for pair and range kerning
combined, a horizontal scale via a per-run glyph transform since Core Text has no scale
attribute, baseline offset via `kCTBaselineOffsetAttributeName`).  Greeking is a render-time
choice by pixel size.

Axes and features:: The Axes group reads the resolved font's axes with `CTFontCopyVariationAxes`
(tag, localized name, minimum, default, maximum) and its named instances from the family's
font descriptors carrying `kCTFontVariationAttribute`; the Features group reads
`CTFontCopyFeatures` and shows only the tags in this page's table that the font provides,
with stylistic-set names from the font's `name` table entries.  `WTText` builds each run's
font with `kCTFontVariationAttribute` (a dictionary of axis tag → value layered over the
named instance chosen by `font_style`) and `kCTFontFeatureSettingsAttribute` (an array of
`{kCTFontOpenTypeFeatureTag, kCTFontOpenTypeFeatureValue}` entries; `OFF` writes value 0 so
a font's on-by-default feature is switched off).  An unset `opsz` leaves Core Text's automatic
optical sizing on.  Bold on a variable font with `wght` writes `axes` at the bold instance's
weight rather than `font_style` alone.  A substitute font receives only the axes and features
it has (TXT-002 reports what was dropped in the Missing Fonts sheet).

Export:: PDF has no variable fonts, so IO-025's writer *instances*: for each distinct
`(font, axis tuple)` used on exported pages it produces a static TrueType subset from the
glyf/gvar font by applying the `gvar` deltas (through `avar`) at that tuple, dropping `fvar`,
`gvar`, `avar`, `HVAR`, `MVAR` and `STAT`, and embeds it as its own font resource named
`Family-Instance-<tuple hash>`; the instancer lives in `WTInterchange` and has no third-party
dependency.  CFF2-flavored variable fonts, and any font the instancer rejects, are written as
outlines for those runs and listed in the export sheet beside restricted fonts ("converted to
outlines: variable font"); a CFF2 instancer is a later task.  Features need nothing at export:
the PDF carries positioned glyph ids and `ToUnicode` maps them back.  Printing goes through
Core Graphics (PRINT-014), which handles variation itself; EPS and SVG take outlines per
IO-017 and IO-019.

Undo grouping:: One step per field commit; the size field's stepper coalesces within 1 s; an
axis slider drag is one step and coalesces to one mark in the outbox.

NOTE: As built by TYPE-021 and TYPE-047 (`WTText`: `FontResolver.swift`, `ParagraphTypesetter.swift`;
`WTRender`: `GlyphRun.swift`, `RoundOutline.swift`).  *Attributes*: pair kerning, range kerning and the
paragraph's optimum letter spacing go to `kCTKernAttributeName` together, on top of the font's own
kerning; the horizontal scale is the run font's matrix, which the glyph run carries
(`GlyphFont.horizontalScale`); baseline shift is a y offset WTText applies to the run's glyphs
rather than `kCTBaselineOffsetAttributeName` (whose shift Core Text's run positions do not
report), and a line's ascent and descent grow with its raised and lowered runs.  A size outside
1--10,000 reads as 12 and a horizontal scale at or below 0 as 100.  `CaseStyle.SMALL_CAPS` shapes
every lowercase letter whose capital is one scalar of the same UTF-16 length as that capital at 70%
of the size, in any font (a letter such as ß stays as it is); the `smcp` feature is a feature mark
like any other.  *Faces*: the face is looked up by style name among the family's faces, then by
its bold and italic traits; failing both it is synthesized -- a slant of tan 12° in the font
matrix (`GlyphFont.obliqueness`) and a bold weight drawn as a `RoundOutline` region 4% of the size
wide in the fill colour -- and listed in `TextLayout.fontReport.synthesizedFaces` for the Object
panel's warning.  A family that is neither installed nor activated lays out in the face TXT-002's
`FontManager` substitutes (xref:font-substitution.adoc[Font substitution]) and is listed in
`fontReport.missingFamilies`.  *Greeking* is renderer state: `greekTypeBelow` (device pixels,
0 off) on both renderers and `MetalTileCanvas.setGreekTypeBelow`, applied to runs whose type size
under the tile's transform is smaller, never in PDF; `TextRunItem.greekable` is how the builder
keeps selected and edited text whole (WTApp supplies the preference, 8 by default); the fast modes'
50 pt rule stands.  *Glyph fill and stroke*: `stroke` is a `StrokePaint` on the glyph outlines,
stroked like any path; `overprint` is `TextRunItem.overprint`, composited with multiply under
overprint preview by both renderers.  *Inline graphics*: WTText takes the graphic on the U+FFFC's
attributes (`InlineGraphic`: its bounds and display items, nil items for a missing node), sets a
Core Text run delegate its width and height, draws its items at the glyph origin through the
block's transforms and reports `inlineGraphics(inContainer:)`; a missing node draws an empty box
the type size square, a bare U+FFFC takes no room, a path does not draw inline graphics, and
drawing a node referred to twice only at the first is WTModel's.  *Axes*: layered over the
variation of the face the style names, clamped to the resolved font's ranges; tags it lacks are
dropped and listed in `fontReport.droppedAxes` (the input is one value per tag: WTModel keeps the
last of duplicates).  With `opsz` unset the font gets `kCTFontOpticalSizeAttribute` "auto"; no
font the public API reaches on macOS 26 has an `opsz` axis (the system faces do but are private),
so that line is untested.  *Features*: a font offers the tags in its GSUB and GPOS feature lists,
the tags Core Text reports for it, and the tags its AAT selectors stand for (ligatures, small
caps, number case and spacing, fractions, swashes, contextual and stylistic alternates); others
are dropped and listed in `fontReport.droppedFeatures`.  Run fonts are cached by (family, style,
size, horizontal scale, axis tuple, feature set, upright); `TextLayoutEngine.fontLookups` and
`fontHits` count the lookups of the paragraphs typeset.  "Pixel for pixel with Core Text" is
checked as identical glyph ids and positions to a `CTLine` of the same font and settings (the same
outlines then fill the same pixels), with goldens for three STIX Two Text weights and six Mukta
Mahee features.  The 200,000-character relayouts after a one-paragraph edit take 25--40 ms with
mixed attributes and 18--20 ms with axes on every paragraph in release (the budgets are enforced
there), with every run font of the edited paragraph from the cache.

NOTE: As built by TYPE-048 (`WTInterchange/Fonts/VariableFontInstancer.swift`,
`PDF/PDFFonts.swift`).  The instancer reads the Core Text font's tables: the tuple
(`GlyphFont.variations`, missing axes at their defaults) is normalized by `fvar`, mapped through
`avar`'s segment maps, and every `gvar` tuple variation (shared or embedded peaks, intermediate
regions, shared or private packed point numbers, packed deltas, IUP for untouched points) is scaled
and summed; coordinates round once at the end.  Composite glyphs move their x/y offsets (written as
words) and keep point-matched arguments; a composite's box is its components' boxes moved by their
offsets.  *Deviation*: advances are Core Text's at the tuple (which applies `HVAR`) rather than
`HVAR` read by the instancer, so `hmtx` (every glyph a long metric, the side bearing the new
`xMin`), the PDF's `/W` widths and the layout agree.  `head` (long `loca`), `hhea`
(`numberOfHMetrics`, `advanceWidthMax`), `hmtx`, `glyf` and `loca` are rebuilt and the subset keeps
`FontProgram.keptTables`, so `fvar`, `gvar`, `avar`, `HVAR`, `MVAR`, `STAT` and `cvar` are gone.  The
PDF writer instances every glyph of a (font, tuple) the first time it is used -- so a font that
cannot be instanced is known before any of its text is written -- and embeds the used glyphs (or all
of them under *Complete*) as a `CIDFontType2` named `<subset tag>+Family-Instance-<8 hex digits of
the tuple>`; variations on a font without `fvar` embed the static font.  A variable font without
`glyf` (CFF2), or one whose tables do not parse, draws as outlines with "font … converted to
outlines: variable font" in the summary.  No CFF2 font ships with macOS 26, so that path is tested
with the instancer refused.  STIX Two Text (2,221 glyphs, `avar` and `HVAR`) instanced at 400, 550
and 700 matches Core Text's outlines of the same tuples within 10 units (0.01 em), with advances
within 1 unit; the three-weight PDF passes `qpdf --check` (qpdf 12 from Homebrew, installed for this
task) and Ghostscript and searches in PDFKit; the whole font instances in 7.4 ms in release (budget
200 ms, `PerfBudget`).  EPS and SVG outline variable instances, as specified.
