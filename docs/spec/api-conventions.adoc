= API conventions
include::_attributes.adoc[]
:page-slug: api-conventions

All client-server communication is gRPC.  The `.proto` files in `proto/` are the single source
of truth for the wire protocol *and* for the document schema, and buf is the single gate they
pass through.  This follows dissipate-server's arrangement: the server's Java/Mutiny stubs come
from Quarkus `generate-code`, the client's Swift comes from buf, and both read the same files.

== buf workspace

.`buf.yaml`
[source,yaml]
----
# Single source of truth: proto/.  Quarkus generates the server's Java/Mutiny stubs from it;
# buf lints it, checks breaking changes against main, and generates the Swift client and the
# HTML reference.  The internal (server-to-server, admin) API never reaches the client.
version: v2
modules:
  - path: proto
    name: buf.build/villagecompute/wiretuner
    excludes:
      - proto/wiretuner/internal
deps:
  - buf.build/bufbuild/protovalidate
lint:
  use:
    - STANDARD
breaking:
  use:
    - FILE
----

.`buf.gen.yaml`
[source,yaml]
----
version: v2
managed:
  enabled: true
plugins:
  # swift-protobuf messages; keep in lock-step with the client's SwiftProtobuf package version
  - remote: buf.build/apple/swift
    out: client/Packages/WTProto/Sources/WTProto/Generated
    opt:
      - Visibility=Public
      - FileNaming=PathToUnderscores
  # grpc-swift 2 async/await stubs (see PROTO-004: verify the BSR plugin emits v2; if not,
  # run protoc-gen-grpc-swift-2 from grpc-swift-protobuf as a local plugin)
  - remote: buf.build/grpc/swift
    out: client/Packages/WTProto/Sources/WTProto/Generated
    opt:
      - Visibility=Public
      - Client=true
      - Server=false
  # merge tables + client-side validators generated from wt.crdt and buf.validate options
  - local: tools/protoc-gen-wtcrdt/bin/protoc-gen-wtcrdt
    out: .
    opt:
      - swift_out=client/Packages/WTCRDT/Sources/WTCRDTSchema/Generated
      - java_out=server/wt-crdt/target/generated-sources/wtcrdt
  # static API reference from proto comments; CI publishes it (proto-docs workflow)
  - remote: buf.build/community/pseudomuto-doc:v1.5.1
    out: proto/gen/docs
    opt:
      - html,index.html
----

CI runs, on every pull request touching `proto/`: `buf format --diff --exit-code`, `buf lint`,
`buf breaking --against '.git#branch=main'`, `buf generate`, then fails if the generated Swift
differs from what is committed.  Generated Swift *is* committed so the Xcode project builds
without buf installed; generated Java is not, because Quarkus regenerates it in the Maven build.

== Packages

[cols="1,3"]
|===
|Package |Contents

|`wt.crdt` |Merge-policy field options (xref:crdt-model.adoc#options[CRDT model]).  No services.
|`wiretuner.doc.v1` |The document schema: `OpId`, `Node`, `NodeProps` and every per-kind props message, ops, `Change`, `DocumentSnapshot`.  No services.
|`wiretuner.sync.v1` |`SyncService`: subscriptions, pushes, fetch, presence (xref:sync-protocol.adoc[Sync protocol]).
|`wiretuner.docs.v1` |`DocumentService`, `BranchService`, `VersionService`: library, search, sharing, branches, versions.
|`wiretuner.blob.v1` |`BlobService`: content-addressed binary upload and download.
|`wiretuner.account.v1` |`AccountService` and `TeamService`: profile, devices, preferences sync, personal and team spaces, workspaces.
|`wiretuner.data.v1` |`DataSourceService`: credentials, allowlists, server-side fetch for data merge and scripts (xref:data-merge.adoc[Data merge]).
|`wiretuner.internal.v1` |Server-to-server and admin RPCs.  Excluded from the public module.
|===

Document schema files are split by feature area (`doc/v1/path.proto`, `doc/v1/text.proto`,
`doc/v1/appearance.proto`, ...) so parallel tasks rarely edit the same file.  `NodeProps` (the
`oneof` of every node kind) lives in `doc/v1/node.proto`; adding a kind is a one-line change
there plus the new file.  Field numbers inside `NodeProps.kind` are allocated in blocks per
epic, recorded in a comment at the top of `node.proto`, to keep concurrent pull requests from
colliding.

== Validation

protovalidate (`buf.validate`) constraints are written on every request message and on every
document field with a meaningful range: a corner radius is `>= 0`, a page is at most 222 inches,
a name is at most 256 characters, a change carries at most 10,000 ops.

* The *server* enforces them with `protovalidate-java` on every inbound message, including every
  op inside every change.  A violation is `INVALID_ARGUMENT` with the violations in
  `google.rpc.BadRequest` details.
* The *client* has no protovalidate runtime (there is no Swift CEL interpreter).  Instead
  `protoc-gen-wtcrdt` emits Swift validators for the *standard* rules (`required`, numeric
  `gt/gte/lt/lte`, string `min_len/max_len/pattern`, repeated `min_items/max_items`, enum
  `defined_only`).  Custom CEL expressions are server-only; the generator lists every field with
  one it skipped, so reviewers see the gap.  `WTModel` runs the validators before a change enters
  the outbox, so a user can never queue an offline change the server will reject.

== Services and RPC shape

* Unary RPCs take `FooRequest` and return `FooResponse` (buf `STANDARD`), even when a response is
  empty today.
* Long-lived exchanges are one server-streaming *subscription* per concern, with a `oneof`
  frame message (`ServerFrame`), plus unary *commands* from the client (`PushChange`,
  `UpdatePresence`, `Ack`).  Bidirectional streaming is never used, so every RPC works
  through a Connect or gRPC-Web gateway and through HTTP/1.1 load balancers
  (xref:sync-protocol.adoc[Sync protocol]).  `buf lint` enforces it with a custom rule
  (PROTO-006) that fails on any RPC streaming in both directions.
* Bulk transfers are client- or server-streaming with frames of at most 1 MiB; messages are
  gzip-compressed on the wire (grpc-encoding), and payloads that are already compressed (images,
  zstd snapshot chunks) are sent as `bytes` with compression disabled for that call.  A
  client-streaming RPC that a non-native client would need has a unary equivalent bounded by
  a batch size (`PushChangeBatch` of up to 32 changes beside `PushChanges`) because browsers
  cannot stream a request body either; the unary form is the gateway path, the streaming form
  the native one.  `BlobService.Upload` has none: a browser viewer only downloads.
* Transport.  The Mac client speaks gRPC over HTTP/2 straight to the API.  For browsers and
  HTTP/1.1 the server does *not* speak Connect or gRPC-Web itself: as far as we can verify for
  Quarkus 3.39, `quarkus-grpc` serves HTTP/2 only (both with its own Netty server and when
  sharing the Vert.x HTTP server), it has no gRPC-Web, Connect or JSON-transcoding switch, and
  the upstream requests for gRPC-Web were closed as won't-fix; the Vert.x gRPC libraries
  underneath do ship gRPC-Web and transcoding modules, but Quarkus does not wire them in.
  The documented path is therefore a gateway in front of the API -- Envoy with the `grpc_web`
  filter, or buf's Vanguard (`connectrpc/vanguard-go`), which transcodes Connect, gRPC-Web and
  REST to plain gRPC -- deployed only when a non-native client exists.  If a later Quarkus
  release exposes Vert.x's gRPC-Web support, the gateway is dropped and nothing in the schema
  changes.  Re-check this when the Quarkus BOM is bumped.
* Every mutation is idempotent by a client-chosen key: document ids are client-generated UUIDv7,
  changes are keyed by `(replica, seq)`, uploads by content hash.  A retried call never
  duplicates anything.

== Errors

Standard gRPC status codes, with a machine-readable reason in `google.rpc.ErrorInfo`
(`domain = "wiretuner.app"`).  Clients branch on `reason`, never on message text.

[cols="1,1,3"]
|===
|Code |Reason |Meaning

|`UNAUTHENTICATED` |`TOKEN_EXPIRED` |Refresh the token and retry.
|`PERMISSION_DENIED` |`ROLE_INSUFFICIENT` |The caller's role on the document does not allow this (a viewer pushing changes).
|`FAILED_PRECONDITION` |`REPLICA_EXPIRED` |The replica was retired after long inactivity (xref:offline.adoc#expiry[Offline]).
|`FAILED_PRECONDITION` |`REPLICA_CONFLICT` |The same `(replica, seq)` arrived with different content; the client must rotate its replica id.
|`FAILED_PRECONDITION` |`CLIENT_TOO_OLD` |The document's feature level is above this client's; open read-only and prompt to update.
|`ABORTED` |`SEQ_GAP` |A change arrived before its predecessor; resend from the acked seq.
|`RESOURCE_EXHAUSTED` |`RATE_LIMITED` |Back off for the `RetryInfo` delay.
|`RESOURCE_EXHAUSTED` |`STORAGE_QUOTA` |The space's blob storage quota is full; change ingest is never quota-limited (xref:saving.adoc[Saving]).
|`NOT_FOUND` |`DOCUMENT_NOT_FOUND` |Deleted, or never visible to the caller (the two are indistinguishable on purpose).
|`PERMISSION_DENIED` |`HOST_NOT_ALLOWED` |A data-source fetch targets a host outside the scope's allowlist (xref:data-merge.adoc[Data merge]).
|`FAILED_PRECONDITION` |`CREDENTIAL_MISSING` |The source names a credential the scope does not hold.
|`RESOURCE_EXHAUSTED` |`RESPONSE_TOO_LARGE` |An upstream response exceeded the size cap.
|`UNAVAILABLE` |`UPSTREAM_ERROR` |The upstream API failed; details carry its status.
|===

== Versioning

* Packages are versioned (`v1`).  Breaking changes are forbidden by `buf breaking`; a real break
  is a new package version served alongside the old one until clients have moved.
* The document schema only ever *adds* fields and kinds.  A client that receives a field it does
  not know preserves it byte-for-byte (swift-protobuf and protobuf-java both keep unknown fields)
  and merges it by the policy the *server's* merge table declares for it, which is shipped to the
  client in `Welcome.schema` (xref:crdt-model.adoc#evolution[Schema evolution]).
* Each document records a *feature level*: the highest schema feature any change in it has used.
  A client below that level can open the document read-only.

== Reference docs

The proto reference is rendered from comments by `protoc-gen-doc` (above) and published by CI,
exactly as in dissipate-server's `proto-docs` workflow.  Every message, field, RPC and enum value
carries a comment; `buf lint`'s `COMMENTS` rules are enabled to enforce it.
