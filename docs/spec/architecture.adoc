= Architecture
include::_attributes.adoc[]
:page-slug: architecture

{product} is a vector illustration application with {fh}'s feature set, UX and keyboard feel,
rebuilt as a native macOS client that saves every edit to the cloud and lets several people work
in one document at once -- including people who have been offline for a day or two.

This page is the map.  The pages it links to are normative.

== Principles

. *The client owns the experience.*  Drawing, rendering, text layout, geometry, printing and
  export all happen on the Mac.  The server stores, orders, relays and compacts; it never
  renders artwork and never needs to understand a Pen tool.
. *Every edit is local first.*  A command changes the local document immediately and becomes a
  change in the outbox.  Being online only affects when others see it.  There is no "Save"
  that talks to the network (xref:saving.adoc[Saving]).
. *Merges are mechanical; judgment is the user's.*  Concurrent changes always merge
  (xref:crdt-model.adoc[CRDT model]).  When a merge is large or touches the same objects from
  both sides, {product} shows what happened and lets the user decide
  (xref:reconcile.adoc[Reconciling offline edits]).
. *The schema is the merge contract.*  Every document field is declared once, in protobuf,
  with its merge policy as a field option.  The Swift and Java engines are generated against
  the same declarations and proven equal by a shared conformance suite
  (xref:testing.adoc[Testing]).
. *Normalize on read, never repair on merge.*  A merged state can be odd -- a text flow that
  loops, a symbol instance whose symbol was deleted.  Clients interpret such states
  deterministically when they read them; nobody writes "fix-up" changes in response to a merge,
  because every client would write the same fix at once.
. *One transport.*  Client and server speak gRPC only, over schemas linted, checked for breaking
  changes and code-generated by buf (xref:api-conventions.adoc[API conventions]).

== System

[listing]
....
 ┌──────────────────────── macOS client (Swift) ────────────────────────┐
 │  WTApp (AppKit UI: windows, tools, panels, menus)                     │
 │    │ commands                          ▲ observes                     │
 │  WTModel (typed document, commands → changes, local undo)             │
 │    │ ops                               ▲ merged state                 │
 │  WTCRDT (merge engine) ◄──── WTRender / WTGeometry / WTText           │
 │    │                                                                  │
 │  WTSync ── local store (SQLite) · outbox · reconcile · blob queue     │
 └────┼──────────────────────────────────────────────────────────────────┘
      │ gRPC over HTTP/2 (TLS): Subscribe (server stream), PushChange, PushChanges,
      │ FetchSnapshot, FetchChanges, Documents, Blobs, Branches — bearer token from Keycloak
 ┌────▼─────────────────────── Quarkus server (Java 25) ────────────────┐
 │  gRPC services (Mutiny)  ·  protovalidate  ·  OIDC (Keycloak)          │
 │  ChangeLog ingest ─► Postgres (documents, change log, ACLs, versions) │
 │  Fan-out ─► Valkey pub/sub (live changes, presence across nodes)       │
 │  Snapshotter / compactor (wt-crdt Java engine) ─► R2/MinIO (snapshots, │
 │     cold change segments, blobs)                                      │
 └───────────────────────────────────────────────────────────────────────┘
....
