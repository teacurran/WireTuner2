= Backlog
include::_attributes.adoc[]
:page-slug: backlog

Every task in this book is sized for one agent working alone (xref:authoring.adoc[Authoring]).
Feature tasks live on their feature pages; this page holds the *foundation* tasks that feature
work depends on, and orders everything into waves that can run in parallel.

=== CRDT

Each CRDT task changes both engines (`client/Packages/WTCRDT`, `server/wt-crdt`) and adds
conformance vectors under `crdt-conformance/`.

[[CRDT-001]]
==== CRDT-001 Engine skeleton, OpId order and registers
[horizontal]
Track:: crdt
Depends on:: PROTO-003, PROTO-005
Size:: M
Delivers:: Lamport counter management, `OpId` total order, register storage `(value, OpId)` keyed by field path, `SetFields` apply with ATOMIC and STRUCT policies from the generated merge table, retention of losing writes in the log.
Done when::
* Vectors: concurrent writes to one register, to sibling STRUCT fields, ATOMIC message replacement, out-of-order arrival.
* Both engines produce identical `state_hash` for every vector.

[[CRDT-002]]
==== CRDT-002 Node tree and move operation
[horizontal]
Track:: crdt
Depends on:: CRDT-001
Size:: L
Delivers:: `CreateNode`, `MoveNode`, `SetDeleted` with Kleppmann et al.'s undo-do-redo move algorithm, cycle rejection, well-known nodes, and the unstable move log.
Done when::
* Vectors: concurrent moves of a node into two parents; moving A under B while B moves under A; delete vs. edit; reparent across layers; 10,000 random moves fuzzed against a sequential oracle.
* Applying a late move to a 50,000-node tree takes under 1 ms.

[[CRDT-003]]
==== CRDT-003 Fractional positions
[horizontal]
Track:: crdt
Depends on:: CRDT-001
Size:: S
Delivers:: Byte-string fractional index generation between neighbors with random suffix, comparison, and the child ordering rule (position, then node id).
Done when:: Vectors for insert at start/end/between, concurrent inserts at the same gap, 1,000 sequential appends stay under 40 bytes.

[[CRDT-004]]
==== CRDT-004 Sequences
[horizontal]
Track:: crdt
Depends on:: CRDT-003
Size:: M
Delivers:: `ElementInsert`, `ElementMove`, `ElementDelete` for `MERGE_SEQUENCE` fields, element registers, nested field paths through elements.
Done when:: Vectors: concurrent reorder vs. edit, delete vs. edit, insert-many id allocation, nested sequence (contour → points).

[[CRDT-005]]
==== CRDT-005 Text sequence (Fugue)
[horizontal]
Track:: crdt
Depends on:: CRDT-001
Size:: L
Delivers:: `TextInsert`/`TextDelete` over a Fugue tree per `MERGE_TEXT` field; plain-string read-out; character id ↔ offset mapping for the layout engine.
Done when:: Vectors from the Fugue paper's interleaving cases; 200,000-character document inserts under 50 µs; identical hashes.

[[CRDT-006]]
==== CRDT-006 Formatting marks (Peritext)
[horizontal]
Track:: crdt
Depends on:: CRDT-005
Size:: L
Delivers:: `TextMark` with before/after anchors, mark expansion rules, mark resolution to attributed runs (marks of the same `TextMarkValue` case supersede by OpId; the `feature` case is keyed by its `tag` as well, so different tags stack), paragraph property registers on newline elements.
Done when:: Vectors: bold vs. concurrent typing inside/at edges; overlapping marks; concurrent paragraph split vs. paragraph style change.

[[CRDT-007]]
==== CRDT-007 Sets
[horizontal]
Track:: crdt
Depends on:: CRDT-001
Size:: S
Delivers:: `SetAdd`/`SetRemove` add-wins observed-remove semantics for `MERGE_SET`.
Done when:: Vectors for concurrent add/remove and remove-then-readd, for scalar and `ElementId` members.

[[CRDT-008]]
==== CRDT-008 Changes, log and inverses
[horizontal]
Track:: crdt
Depends on:: CRDT-002, CRDT-004
Size:: M
Delivers:: `Change` application as a unit, the retained change log with losing writes, inverse recording (prior values) for the model's undo, `Noop`, and the per-replica seq bookkeeping.
Done when:: Vectors replaying whole changes out of order; inverse of every op kind verified by apply-then-invert equals identity where uncontested.

[[CRDT-009]]
==== CRDT-009 Snapshots and state hash
[horizontal]
Track:: crdt
Depends on:: CRDT-008, CRDT-006
Size:: M
Delivers:: `DocumentSnapshot` encode/decode, canonical encoding, SHA-256 `state_hash`, zstd chunking.
Done when:: Round-trip is lossless; hash identical across engines for every conformance vector; design-point document loads in under 1.5 s on M1.

[[CRDT-010]]
==== CRDT-010 Causal stability and garbage collection
[horizontal]
Track:: crdt
Depends on:: CRDT-009
Size:: M
Delivers:: Stable-point computation from replica acks, tombstone and move-log pruning, deleted-node compaction after 30 days, and the guarantee that a late op referencing a collected tombstone is a deterministic no-op.
Done when:: Vectors: prune then late delete; prune then late insert with a collected origin; hash unaffected by prune timing.

[[CRDT-011]]
==== CRDT-011 Conformance runner
[horizontal]
Track:: crdt
Depends on:: CRDT-001
Size:: M
Delivers:: Vector format (textproto: initial changes, per-replica delivery orders, expected hash and expected read-outs), runners for both engines, CI job that fails on any divergence.
Done when:: Runs in under 60 s in CI; a divergence report names the vector and the first differing node.

[[CRDT-012]]
==== CRDT-012 Cross-engine fuzzer
[horizontal]
Track:: crdt
Depends on:: CRDT-011, CRDT-010
Size:: M
Delivers:: Random op generation over N replicas with random partitions and delivery orders, run against both engines, minimizing failures into new vectors.
Done when:: One million random ops run nightly with no divergence.
